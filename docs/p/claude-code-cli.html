    Claude Code CLI

    Anthropic's terminal coding agent. In agent-orchestrator it is one of two executors, driven non-interactively rather than used at a prompt.

    #How it is driven

    claude -p --output-format stream-json, spawned with the open workspace as the working directory and granted it explicitly with --add-dir. Structured streaming means the answer is taken from a result object rather than parsed out of prose, and the tool calls, reasoning and text arrive as events the panel can render as they happen.

    Three flags carry the autonomy level (autonomy-decided-before-the-run): --permission-mode plan, acceptEdits with --allowedTools, or bypassPermissions.

    --allowedTools must never be the last flag before the prompt. It is variadic, so in last position it swallows the task and the run silently does nothing. That is a unit test, not a comment.

    #What distinguishes it from the other executor

    It is the only executor that can open images and extract PDFs and office documents, so read-capability-routing sends any subtask declaring those reads here regardless of what the planner preferred. codex-cli gets text.

    Sessions resume per (agent, model, subtask id), and the session id is recorded the moment the CLI announces it rather than once the turn succeeds — a turn that fails still consumed the session.

    #Skills

    Spawned agents arrive with a vendored bundle for that session via --plugin-dir; nothing is installed on the machine and nothing is written into the user's project (agent-skills-checked-into-the-repo).

    #The standing risk

    Every one of these flags is an interface owned by someone else. The test suite asserts the argv sent, not the behaviour obtained, so a renamed permission flag passes every test and fails on first contact. The project records the CLI version each flag was verified against at the point of use, and says so in its test plan rather than leaving it to be discovered.
