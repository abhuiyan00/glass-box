    One Repository at the Workspace Folder

    git init went at vs-llm-orchestrator/, one level above the product folder agent-orchestrator/, and one repository holds the product, the documentation set and the tooling.

    #Why not at the product folder

    Because the documentation set is not part of the product. The SRS, architecture document, security model, test plan, risk register, release procedure and nine ADRs describe the product but do not ship inside the .vsix; the Makefile, the PowerShell runner and the CI workflow build it from outside. Rooting the repository at agent-orchestrator/ would either strand all of that outside version control or force it into the packaged artifact.

    The cost is one confusing sentence that has to be said on the front page: the repository folder is vs-llm-orchestrator, the product inside it is agent-orchestrator. Saying it once beats a rename that breaks every path in a working install.

    #What that makes the root

    The root is a workspace, and it is where the reader arrives — so it carries the front-door README, and the extension has its own text-only one for the Marketplace listing. It also means .gitignore decisions are made at the workspace level, and two of them are worth recording:

    • harness/shots/ is ignored — regenerated output of the screenshot matrix, one command away.
    • docs/img/ is not — the twelve curated figures the documentation embeds. A reader cloning the repository must see them, and a reader browsing on the web must be served them.

    Same file type, opposite decisions, because one is a build artifact and the other is content (generated-artifact-with-pristine-source).

    Also excluded deliberately: four built .vsix files, and .vscode/settings.json — which is exactly where an openrouter key ends up when someone skips the secure command (secrets-from-environment-only).

    #The side effect that mattered here

    This wiki's verify-sources gate had vs-llm-orchestrator marked "not a git repo — cannot be verified either way". Initialising it closed that gate — 164 files, 27,434 insertions, one commit (import-finished-work-into-git).

    #Rejected

    A monorepo of several products. There is one product. Submodules for the skill bundle. Vendored with provenance instead — agent-skills-checked-into-the-repo, provenance-notice-file.
