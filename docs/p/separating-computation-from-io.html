    Separating Computation from I/O

    A function that computes and prints can only be tested by capturing stdout. A function that returns a value can be tested by comparing it. That is the entire argument, and python-programming-laboratories applies it as a rule rather than a preference.

    #The three applications in weblog

    stats never prints. Every aggregation returns a data structure; the CLI layer decides how to render it. The stated reason is testability, and the test suite is the proof — the stats tests assert on returned values with no capsys anywhere.

    Config is read inside main(), never at import time. Import-time config reading means importing the module has a side effect: it touches the filesystem, can raise, and pins the config path before any caller gets a say. Deferring it to main() keeps import pure, so tests can import the module and inject their own config. Config fronts both JSON and INI behind one interface, and a ConfigError is raised at load rather than at first use — failing where the mistake is, not three call frames later.

    Paging checks isatty(). The program pages output when a human is watching and streams plainly when piped. The computation is identical either way; only the presentation layer inspects the environment. This is the same separation pushed all the way to the terminal boundary.

    #Why it compounds

    The nine labs that read the same access log are thin scripts precisely because the computation has no I/O baked in — see extract-the-shared-core. Had stats printed, every lab would have needed its own copy with different formatting, and the shared core would never have been extractable.

    The same discipline is what makes common-log-format-parsing testable: iter_entries yields objects, ParseReport accumulates counts, and nothing in the parsing path writes to a stream.

    #The general shape

    • Pure core, imperative shell. Decisions and calculations in functions that take data and return data; reading, writing, printing and clock-checking at the edges.
    • Return, don't render. image_ratio in lab 11 returns None rather than printing a zero — the caller decides what "no data" looks like.
    • Fail at the boundary. Validate on load, so the pure core can assume well-formed input.

    #Related

    The same instinct at a different scale appears in data-warehousing-and-business-intelligence, where transformation logic is separated from load mechanics, and in farely, whose domain engine is pure and shared across hosts.
