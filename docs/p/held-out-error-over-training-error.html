    Held-Out Error over Training Error

    Training error cannot select a model, and the reason is structural rather than statistical: for nested model families it is monotonically non-increasing in complexity by construction.

    A degree-d+1 polynomial can reproduce any degree-d one by setting the leading coefficient to zero. So the best degree-d+1 fit is at least as good as the best degree-d fit, on any data, always. Selecting on training error therefore picks the largest candidate in the list — and it does so for a reason that has nothing to do with the data.

    #The measurement

         degree        train   validation
          0      0.47624      0.40153
          1      0.27474      0.24176
          3      0.01360      0.01025
          5      0.00568      0.01165
          7      0.00512      0.01015  <- chosen
          9      0.00264      0.01315

    Training error falls all the way to degree 9. Validation error does not — it bottoms out and comes back up, and that non-monotonicity is the entire product of holding data out. A split that produced a monotone validation curve would have bought nothing.

    Both facts are assertions in the test suite rather than observations in a comment: the monotonicity of the training column is asserted, and so is the non-monotonicity of the validation column.

    #The same trap without a degree

    Model complexity does not have to be a visible parameter for this to bite.

    κ-NN at k = 1 has zero training error by construction, because every training point is its own nearest neighbour at distance zero. A k chosen on training error is always 1 — again, for reasons unrelated to the data. See lazy-versus-eager-learners.

    The general form: any metric that a model can drive to its optimum by memorising cannot distinguish memorising from learning. Test-set accuracy on a set that was consulted while tuning has the same defect and is harder to notice.

    #The guarantee has a precondition

    κ-NN's zero-training-error property holds only while no two identical feature vectors carry different labels. With a contradictory duplicate, k = 1 scores 0.8 rather than 1.0 — one of the two identical points must be wrong whatever the classifier does.

    Real text data is full of duplicate feature vectors, so this is not a corner case. It was found by writing a test that assumed the guarantee and measuring 0.8, which is the useful direction for a precondition to be discovered in.

    #Replacing a discrete search with a continuous one

    Once ridge regression is available, the degree stops needing to be guessed correctly: fix a generously large degree and select λ instead. One continuous parameter replaces one discrete one and is easier to search — see condition-number-as-digits-lost for what λ is doing to the solve while it does that.

    #Where this appears

    Implemented in systems-analysis-and-decision-support with both selection sweeps keeping every candidate they rejected rather than returning only the winner. The wider habit — blind-baseline-comparison — is the same argument applied to whether a model beats doing nothing at all.
