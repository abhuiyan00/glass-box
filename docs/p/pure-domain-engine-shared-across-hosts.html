    Pure Domain Engine Shared Across Hosts

    Keep the rules of the domain in one UI-free, platform-free module, and let each host — a browser simulator, a phone, a test harness — supply only input and display. The engine does not know which one it is running in.

    In farely this is apps/tester/src/app/lib/: engine, coordinator, controls, events, liveEvents, vision, diagnostics, diagStore, carLookup, device, session, theme, bridge. The same built bundle is served by Vite in the browser and loaded by the capacitor WebView inside the APK — capacitor.config.json points webDir straight at ../tester/dist. The native side is described as only capturing and displaying.

    #What the split buys

    • The unbuilt half stays testable. Every offer-scoring rule in deadhead-adjusted-net-profit could be exercised in a browser long before an APK existed — which, given that Farely never ran on a live shift, is the only reason any of it was exercised at all. The simulator was the product for its whole life.
    • One implementation, not two. No native scoring path exists to drift from the JS one. Contrast the sibling product stickfps, which deliberately duplicated its simulation code across hosts instead.
    • The native boundary stays small. ~1,099 lines of Kotlin against ~12,100 lines of TypeScript. The Kotlin does capture (accessibility-service-overlay) and drawing (accessibility-overlay-over-system-alert-window); it makes no money decisions.

    #The seam

    A Capacitor plugin bridge in both directions: FarelyBridgePlugin.emitRawOffer pushes a RawOffer into the WebView, showOverlay sends the verdict back out. The data crossing is small and dumb — strings and numbers off the node tree — which is what keeps the engine platform-free. offerFromRaw() on the JS side does all the normalising (fuzzy Polish place resolution, estimating missing km/min, setting the approx flag), so the native side never has to know the domain.

    #Where the purity is imperfect

    vision.ts reaches the network directly and switches transport by host — CapacitorHttp natively, a Vite dev proxy in the browser, direct fetch otherwise. So the "pure" library does contain host detection, isolated to the one module that must do I/O. device.ts likewise sniffs RAM to pick a LITE tier. Both are honest exceptions rather than leaks scattered through the engine.

    #Cost paid

    A duplicated mirror elsewhere: apps/android/reference/ is a hand-maintained copy of the Kotlin files, which CONTRIBUTING asks the developer to keep in sync manually. The discipline that removed duplication from the domain layer did not reach the native layer.
