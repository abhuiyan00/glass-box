    WebSocket Over TCP Instead of Geckos.io UDP

    Decision (2026-07-24, round 11): replace geckos.io — UDP over WebRTC data channels — with plain WebSocket over TCP (ws), across the whole of stickfps.

    Driver: hosting cost, not technology.

    "the original transport was geckos.io (UDP-over-WebRTC), which forces a UDP-capable host — and every managed host that does UDP (Fly.io, Oracle, the big clouds) requires a card. Swapped the whole transport to plain WebSocket-over-TCP (ws), which any persistent Node host can serve, including free no-card tiers (Render, Koyeb)."

    browser_game_stickfps/PROGRESS.md, 2026-07-25

    The trigger was a request to host the game online without a credit card. UDP was the only thing requiring a card-gated host, so the transport was the cheapest constraint to remove.

    #The old transport worked

    This is the part that would be easy to get wrong in hindsight. Confirmed at interview:

    "Cost only — it worked fine."

    interview, 2026-07-28

    There was no reliability problem, no browser-support problem and no debuggability problem with UDP-over-WebRTC. Nothing in the transport failed. This was a clean cost-driven trade, and reading a technical failure into it would invent a rationale that does not exist.

    #What was traded away

    TCP gives ordered, reliable delivery — so a lost packet blocks every packet behind it until it is retransmitted. For a 60 Hz position stream that is the wrong guarantee: the next snapshot makes the lost one irrelevant, and waiting for it costs latency. Named and accepted as "unnoticeable at hobby scale", which is a defensible call for a friends-and-bots game and would not be for a competitive one. entity-interpolation's 100 ms buffer absorbs more of this than it otherwise would.

    #Why the swap was affordable

    A NetChannel / NetServer abstraction was written to mirror only the slice of the geckos.io API the code actually used. geckosServer.ts and geckosClient.ts were deleted and no gameplay code changed — the authority model in server-authoritative-netcode never saw the transport. See ws-websocket-server for what replaced it.

    #Consequences

    • Unblocked render-over-fly-io — Render had been rejected earlier specifically for having no public inbound UDP, and that objection died with this change.
    • Left drift behind: EXPOSE 10000/udp in the docker image, TASKS.md step 8.1 still saying "UDP enabled", all four .tooling agent files still naming Geckos.io, and the SRS diagrams unchanged. See documentation-drift.
