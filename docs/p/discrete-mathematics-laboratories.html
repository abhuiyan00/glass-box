    Discrete Mathematics Laboratories

    Six discrete-maths lab deliverables for a Master's course at Wrocław University of Science and Technology, each turned into a runnable artifact rather than a write-up. 108 files, single author, MIT, public remote. The organising idea is stated in the repo itself and is the reason this repo gets its own pattern page — see make-the-formal-object-observable.

    "The thread running through all six: take a formal object (a cut, a modulus, a set, a recursion, a graph, an information system) and make its behaviour observable."

    #Git history — this repo contradicts the usual pattern

    49 commits, 2026-03-20 → 2026-07-10, five working dates with real gaps, and commits that only exist because something broke: 48ba16d Fix UnicodeEncodeError in the lab3 demos on Windows consoles, 06b5882 Make SentinelNet run offline: vendor React, precompile the JSX (2,692 insertions), 8a2acfe Add .gitignore and stop tracking compiled bytecode, e42bc80 Rename Max_Cut_lab1 to lab1_Max_Cut. That is a working log, not an import — a documented counter-example to import-finished-work-into-git.

    Caveat, so the wiki does not overstate it: within-session granularity is still upload-shaped. Whole finished labs land in one day, one commit per file with the file path as the message, and one commit is literally Add files via upload from the GitHub web UI. Finished work still gets imported — just repeatedly, over four months, with fixes in between.

    The 2026-07-10 tail is a textbook publishing pass — seven README+screenshot commits, then 0a6d54b Rewrite the top-level README as a guided tour, 24e7b33 Add MIT license, 7273d68 Add license badges. See presentation-polish-tail-commits and readme-as-guided-tour. Per the interview these bursts were "just cleaning up local folders" — consolidation, not a release.

    Provenance note. brain.py survey reported this repo as first = last = 2026-07-10, hiding the whole four-month arc. Every date above came from git log directly; the survey's git dates are not trustworthy.

    #Findings

    • tspChristofides in sn-algo.js is not Christofides. It matches odd-degree vertices greedily rather than by minimum-weight perfect matching, so the 1.5-approximation guarantee does not hold. Call it a Christofides-shaped heuristic. Recorded on shortest-path-algorithm-family. confidence: high (read from source).
    • The zero-dependency claim is internally contradicted. lab4/part2 and lab6/viewer contain zero external URLs; Q-HYDRO Wrocław says "No dependencies are vendored" and loads Leaflet, map tiles and IBM Plex from CDNs. Two lab-5 apps side by side under opposite rules, and the root README's "all run offline" overstates it. See zero-dependency-no-build-step.
    • Documentation drift, three instances. lab6_Neo4j/guide.txt still lists "object count = 38" after the README says 38→39 was corrected "throughout"; the same file hard-codes a stale personal absolute path; the root README's offline claim above. See documentation-drift.
    • The only automated check in the repo is lab3_Sets/mandatory_tasks/test_suite.py, a hand-rolled TestRunner with boolean assertions — not pytest. Everything else is asserted in prose and screenshots.
    • Boundaries are written beside the claims rather than hidden — "a conservative placeholder — a full Stoer-Wagner cut is out of scope", "swap in a binary heap for scale". This is the strongest instance of provenance-and-limits-stated-inline in the whole source set.
    • lab6_Neo4j/guide.txt is written as an assistant addressing the user and closes "When all are in this folder, say \"screenshots ready\" -> I build the LaTeX report." — a handoff instruction shipped as a lab deliverable. No agent tooling is in the tree: no .tooling/, no CLAUDE.md, no CI. Do not infer any.
    • No .gitattributes and no Git LFS: 19 PNGs and an 840 KB PDF are committed as plain blobs.
