    Set Similarity Metrics

    Three ways to turn "how alike are these two sets?" into a number between 0 and 1. The optional task of lab 3 in discrete-mathematics-laboratories codes all three and applies them to a job recommender, which is what makes the differences visible rather than academic.

    Metric Formula Behaviour
    Jaccard`\A∩B\/ \A∪B\`penalises every non-shared element; strict
    Sørensen–Dice`2\A∩B\/ (\A\+\B\)`double-weights the overlap; more forgiving of size mismatch
    Cosine (on sets)`\A∩B\/ √(\A\·\B\)`geometric mean in the denominator; between the other two

    Dice and Jaccard are monotone transforms of each other, so they rank pairs identically — they differ only in the magnitude of the score, which matters as soon as a threshold is applied. Cosine can reorder pairs when the two sets differ sharply in size, because a large set is penalised by √ rather than linearly.

    #The application

    A skill-set recommender: user skills as one set, job requirements as another.

    • Skill gap = requirements − skills, a set difference read directly as "what to learn next".
    • Match category = a banded label over the similarity score.
    • Composite score = job match × mean similarity to similar users × count of similar users — a collaborative-filtering shape built from nothing but set operations.

    That composite is the interesting part: three quantities multiplied with no weighting, so a single zero factor annihilates the recommendation.

    #A wrinkle worth recording

    This optional task uses Python's builtin set, while mandatory_tasks/core.py in the same lab implements Set, MultiSet and EmptySet from scratch over native lists (see characteristic-functions). Whether the mandatory task forbade builtins or this is drift is not recorded in the repo. TODO: unresolved; confidence: low on the reason.
