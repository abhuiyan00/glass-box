    setuptools and pyproject.toml

    The packaging layer that turns twelve lab scripts into one installable project in python-programming-laboratories. This is the mechanism behind extract-the-shared-core — without it, "shared core" would just mean a file everyone copies.

    #src-layout

    The package lives at src/weblog/, not weblog/ at the repo root. The difference matters: with a root-level package, import weblog in a test picks up the working directory copy whether or not the install succeeded, so a broken package configuration passes tests locally and fails for everyone else. Under src-layout the only importable weblog is the installed one.

    pyproject.toml sets pythonpath for pytest so the suite still resolves imports without an editable install already in place.

    #The extras split

    dependencies = []

    "# Only the later laboratories need these; the core package has no dependencies."

    Python-Programming-Laboratories/pyproject.toml, 2026-07-25

    The core — parsing, reading, stats, config, CLI — is stdlib only, using argparse rather than click for exactly this reason. Everything else goes into optional extras:

    • labs — click, openpyxl, factory-boy-and-faker, requests, beautifulsoup, matplotlib, pillow, python-docx.
    • dev — pytest, pytest-cov.

    Installing the core installs nothing else, which is zero-dependency-no-build-step expressed as metadata rather than as a claim.

    • ruff with line-length = 90. TODO: configured but never run in CI (there is no CI) and never mentioned in the README. confidence: low on any claim that it was used.

    #The split has a hole

    The dev extra omits factory_boy and Faker, which tests/test_lab09_insults.py imports — so the README's documented quick start fails at collection in a clean virtualenv. Recorded in full on factory-boy-and-faker. Declaring dependencies precisely is the whole value of this file, and this is the one place it is wrong.
