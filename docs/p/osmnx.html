    OSMnx

    Python library that downloads street networks from OpenStreetMap and hands them back as networkx graphs, with the routing-relevant cleanup already done. Used in optimization-methods as the only source of geography for multi-depot-vehicle-routing — pinned as osmnx>=2.0, the one pinned dependency in instance_generator/requirements.txt.

    #How it is used

    graph_from_point(dist=5000, network_type="drive")
  → truncate.largest_component(strongly=True)
  → collapse parallel edges to the shortest directed length
  → CSV
    • network_type="drive" keeps one-way restrictions, which is what makes the resulting cost function directed — dist(a,b) ≠ dist(b,a).
    • strongly=True is the load-bearing flag. The weakly connected component would contain node pairs with no legal directed route; truncating to the largest strongly-connected component guarantees every shortest-path query terminates. Without it, lazy-dijkstra-distance-cache would need an unreachable-pair code path.
    • Parallel edges (OSM regularly has several ways between the same node pair) are collapsed to the shortest directed length, so the C++ side reads a simple graph.

    The graph then leaves Python entirely as {city}_nodes.csv and {city}_edges.csv — the C++ solver re-implements Dijkstra rather than calling back into Python. See two-program-csv-contract.

    #The reproducibility finding

    OSM is a live database, so an OSMnx download is not a fixed input. Everything else in the pipeline is seeded and deterministic; the map is not, and the repo measured exactly how much that costs:

    "Re-running the deterministic greedy on a freshly downloaded Wrocław graph gave 178,207 / 322,318 / 458,921 m vs the paper's 177,555 / 299,944 / 481,089 m — same demands and capacity, but a different sampled road graph (OSM has drifted; today's largest SCC = 3,893 nodes)."

    Optimization Methods/final_project/docs/DATA_VERIFICATION.md, 2026-07-09

    Note the direction of the drift is not uniform — one instance got shorter, two got longer. This is the reason the frozen solver reports are committed while the instance and graph CSVs are gitignored: the artefact is the reference, the regeneration is not. It also means the operator-bake-off cannot be re-run to the same numbers.

    The practical lesson: any pipeline whose first stage hits a live public dataset should commit the downloaded snapshot, not just the code that downloads it. This repo committed the downstream results instead, which preserves the paper but not the experiment.

    #Dependency hygiene

    requirements.txt pins only osmnx>=2.0, leaves networkx, pandas and numpy unpinned, and omits matplotlib entirely although plot_analysis.py imports it — see matplotlib and documentation-drift. A clean install from that file cannot produce the figures.
