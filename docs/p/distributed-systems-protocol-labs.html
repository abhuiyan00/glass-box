    Distributed Systems Protocol Labs

    One service contract, executed over two real transports — length-prefixed TCP JSON and HTTP/1.1 JSON — with a third, gRPC, expressed as a schema and deliberately left unbuilt. Standard library only, Python 3.11+.

    A scattered set of socket exercises becomes one argument: the transport is not the system. What survives changing it is.

    #Why two transports and not one

    A single implementation of an interface is the shape of that implementation, not an abstraction. Writing the second is what proves the boundary exists — the same reasoning that put two storage adapters behind one contract suite in project-management-web-platform, and the general form recorded in dual-implementation-as-cross-check.

    Here it pays twice. The adapters own framing and transport status; the dispatcher owns the trust boundary; the service sees only a validated request and a deadline. Nothing about SequenceService knows whether it was reached by a socket or a POST, and the integration tests assert that both paths produce the same envelope — which is a claim that can only be made because there are two.

    #The contract

    {"version": "1.0", "request_id": "tour-001", "operation": "sequence.generate",
 "deadline_unix_ms": 2000000000000, "payload": {"count": 8}}

    Errors are data, not leaked exceptions — a stable code, a safe message, an explicit retryable flag, and structured details:

    {"ok": false, "error": {"code": "OUT_OF_RANGE",
 "message": "payload.count must be between 1 and 94.", "retryable": false,
 "details": {"field": "payload.count", "minimum": 1, "maximum": 94}}}

    retryable is the field that makes the difference operationally. A caller cannot infer from a status code whether repeating the call is sensible or merely rude, so the server says. See contract-first-api-design.

    #What each transport had to answer

    TCP: where does a message end? 4-byte unsigned big-endian length || UTF-8 JSON, one connection carrying many frames, sizes capped at 64 KiB, an invalid frame answered with a framed INVALID_FRAME where that is still possible and then closed. A stream has no message boundaries until someone defines them, and "read until the buffer looks like JSON" is the bug that survives every test written against a fast loopback.

    HTTP: how do the same failures map? Validation → 400, unknown operation → 404, expired deadline → 504, unexpected → 500, with the JSON shape unchanged. The mapping is one function, not a decision per handler.

    gRPC: what would change? contracts/sequence_service.proto is runtime-neutral and the decisions are written down rather than implemented: request ID moves to x-request-id metadata, the epoch deadline field disappears in favour of the call deadline, contract codes map to canonical gRPC statuses, and cancellation is honoured. Not generating a stub that nothing exercises is the honest version of reference-implementation-as-specification.

    #Deadlines, correlation, shutdown

    Absolute deadlines, checked at admission and during work, on top of client-side transport timeouts. A timeout that is only checked on entry protects against a slow queue and not against slow work.

    Correlation IDs survive every path, success and failure alike. An error response without the request ID is the one you cannot find in a log.

    SIGINT/SIGTERM close listeners and join threads, and the process prints {"event": "stopped"} only after both. Abandoning sockets on exit is invisible in development and is the reason a port is still bound on the next start.

    #Verification

    python -m unittest discover, plus scripts/headless_demo.py, which starts both servers on ephemeral loopback ports, sends equivalent requests, exercises a structured validation failure, confirms the results match, shuts down and prints JSON — no browser, no files written. CI runs both on Python 3.11–3.14.

    Tests cover malformed JSON, equivalent TCP/HTTP outcomes, structured validation and deadline failures, 24 concurrent mixed-protocol calls, and clean listener-thread shutdown.

    A 2026-08-12 local audit passed compilation, all 13 unit and integration tests, and the headless demo. The demo returned identical TCP and HTTP results plus the documented OUT_OF_RANGE envelope. The existing accessible blueprint diagram was inspected and preserved because it renders the same bounded-contract story without claiming an unbuilt gRPC runtime.

    #Open gaps

    • TODO: no gRPC adapter. The schema and the mapping decisions exist; the runtime does not. Stated rather than implied by an empty directory.
    • TODO: loopback educational service. No TLS, authentication, authorisation, quotas or distributed rate limiting on either transport, and the README says so under its own heading rather than in a footnote.
    • TODO: threaded adapters. Fine at this scale, and the wrong shape for high fan-out; the trade is not measured here.
