    No External Assets

    Decision: every visual and audio asset in stickfps must be generated in code. No model files, no texture files, no audio files, no font files. Stated as a hard filter on the design itself, not as a technique:

    "If a design needs an asset, it must be procedurally generatable in code, or it's out."

    browser_game_stickfps/DESIGN_PROMPT.md, 2026-07-25

    #What that means concretely

    • Geometry — the entire arena from box, plane and cylinder primitives in a 576-line Environment.tsx; stickmen generated procedurally. See three-js.
    • Audio — all SFX synthesised with the Web Audio API in a 300-line sounds.ts. Zero audio files.
    • Textures — inline SVG data URIs.
    • Type — system UI fonts.

    #Why it holds up

    It removes an entire class of work that a solo browser project cannot afford: sourcing, licensing, optimising, hosting and cache-busting binary assets. There is no asset pipeline, no CDN, no attribution ledger, and no licence question about anything shipped.

    It also makes the visual identity reviewable. Art becomes code that diffs, and a design change is an edit rather than a re-export from a tool the repo does not contain. When the film-noir grayscale identity was retired for full colour (superseded-in-place-documentation), the change was a code change — with no assets to re-author, reversing a whole art direction stayed cheap.

    #What it costs

    The art ceiling is set by what primitives can express, and everything renders from setup code rather than from optimised buffers. The bundle is still ~1.4 MB, so this bought no size win — the weight is react-three-fiber and its dependencies, not content. Some visual ideas are simply unavailable.

    #Where it sits in the wider habit

    zero-dependency-no-build-step is contradicted at the toolchain level here — stickfps has twelve runtime dependencies and two build pipelines (vite). But the same instinct reappears one layer down as an absolute rule: refuse the asset pipeline wherever code can replace it. The coursework repositories refuse the build step; this one accepts the build step and refuses the content.

    That is the more precise statement of the pattern across the source set: the thing being avoided is a fetched, opaque, unversioned input, not tooling as such.
