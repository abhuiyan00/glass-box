    Zero Dependency, No Build Step

    Wherever a dependency can be replaced by code, it is. Wherever a build step can be avoided, it is. Confirmed across eight repositories — but the honest version of this pattern is that it holds at module level far more consistently than at repo level.

    #The pure cases

    • Information-Systems-Modelling/lab6/app/package.json declares "dependencies": {} and serves over node:http; lab7/package.json has no dependencies key at all.
    • Python-Programming-Laboratories' core weblog package declares dependencies = [], pushing every library to an optional labs extra.
    • Discrete-Mathematics-Laboratories/lab4_Complexity/part2 and lab6_Neo4j/viewer/ contain zero external URLs.
    • Optimization Methods' entire C++17 solver is standard-library only — no Boost, no LEMON, no OR-Tools, no LP/MIP solver anywhere.

    "No build step. No server. No internet. Open one HTML file and start revising."

    Physics/README.md, 2026-07-10

    "# Only the later laboratories need these; the core package has no dependencies."

    Python-Programming-Laboratories/pyproject.toml, 2026-07-25

    #Vendoring over CDNs — and the internal contradiction

    Physics copies KaTeX in wholesale (css + js + 20 .woff2) specifically to avoid a CDN — see vendor-katex-instead-of-cdn. Discrete-Mathematics-Laboratories vendored React's production UMD and precompiled its JSX after a CDN dependency broke file:// loading entirely — see vendor-react-over-babel-cdn.

    But the same repo, in the sibling directory, does the opposite and says so:

    "No dependencies are vendored; there is nothing to npm install."

    Discrete-Mathematics-Laboratories/lab5_GraphTheory/Q-HYDRO Wrocław/README.md, 2026-06-09

    Q-HYDRO loads Leaflet 1.9.4, map tiles and IBM Plex from CDNs. Two lab-5 apps sit side by side under opposite rules, and the root README's claim that labs 4 (part 2), 5 and 6 "all run offline" overstates it. Optimization Methods and Information-Systems-Modelling show the same split — zero-dependency Node tooling next to CDN-loaded Leaflet and Google Fonts.

    #The deeper form: refuse the asset pipeline

    browser_game_stickfps has 12 runtime dependencies and two build pipelines, so it contradicts this pattern at the toolchain level. One layer down it applies the same instinct absolutely:

    "If a design needs an asset, it must be procedurally generatable in code, or it's out."

    browser_game_stickfps/DESIGN_PROMPT.md, 2026-07-25

    All geometry from three.js primitives, all sound synthesized in Web Audio, textures as inline-SVG data URIs. See no-external-assets. Farley shows the same at module level inside a ~40-dependency shell: a "zero-dep IndexedDB" diagnostics store, an offline built-in car dataset, a calendar computed with no library, and a LITE tier that replaces MapLibre with hand-rolled DOM/SVG projection.

    So the accurate statement of the pattern is narrower than "no dependencies": replace a dependency with code wherever the replacement is small enough to own.
