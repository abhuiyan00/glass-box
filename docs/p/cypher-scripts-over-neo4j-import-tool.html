    Cypher Scripts Over the Neo4j Import Tool

    Decision. Import the dataset with LOAD CSV + MERGE Cypher scripts run from the Query editor, not with Neo4j Desktop's graphical Import tool.

    Date. 2026-07-10, lab 6 of discrete-mathematics-laboratories.

    #Why

    The rejected option is named explicitly, in the setup guide, at the exact step where a reader would otherwise click it:

    "STEP 3. Left sidebar -> Query. This opens the Cypher editor where you type and Run commands. (NOT the \"Import\" tool - ignore that one, it makes you draw the model by hand. We use Cypher scripts.)"

    Discrete-Mathematics-Laboratories/lab6_Neo4j/guide.txt, 2026-07-10

    "It makes you draw the model by hand" is the objection: the GUI import produces a mapping that lives in the tool's state, not in the repository. A script is text, so it is reviewable, diffable, re-runnable and quotable in a report.

    #What the script form bought

    Concretely, when the object count turned out to be wrong:

    "Data note. The dataset holds 39 countries; earlier drafts of the guide said 38 (and 950 HAS_VALUE). The numbers were corrected to 39 objects / 975 edges throughout — the import logic itself was already correct (it MERGEs one object per row)."

    Discrete-Mathematics-Laboratories/lab6_Neo4j/README.md, 2026-07-10

    Because the import was a MERGE script rather than a GUI mapping, it was re-runnable and provably correct by reading — the fix was a documentation edit, not a rebuild. See idempotent-loading and cypher.

    #Alternatives rejected

    Option Why not
    Neo4j Desktop Import toolmodel drawn by hand in the GUI; nothing reviewable lands in the repo
    neo4j-admin importbulk offline loader, faster but destructive and not re-runnable against a live DB
    A Python driver scriptadds a dependency and a second language to a lab whose deliverable is the Cypher

Writing the procedure down does not keep it true — documentation-drift. The same file closes with "When all are in this folder, say \"screenshots ready\" -> I build the LaTeX report."
