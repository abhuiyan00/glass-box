    Document the Failure Mode Next to the Fix

    Almost every note in these two repositories has the same shape: state the wrong-but-plausible alternative, name the concrete input that breaks it, then give the fix. Not "we use a regex" but "split() shifts every field after the first quoted one, silently".

    "Not hypothetical -- the sample log in data/ contains an injection attempt whose referer embeds \" sequences, and a naive [^\"]* would terminate the field at the first inner quote and reject the whole line."

    Python-Programming-Laboratories/src/weblog/entry.py, 2026-07-25

    "An assertion has to reach the code under test. A test whose argument is an undefined name raises NameError while evaluating the call, before the function is entered — so pytest.raises(TypeError) never sees it, and the test would pass against an implementation doing no type checking at all."

    Python-Programming-Laboratories/labs/07_testing/README.md, 2026-07-25

    #Why this form and not a comment saying what the code does

    The failure mode is the expensive knowledge. The fix is usually one line and re-derivable from the code; why the obvious thing is wrong is not, and it is exactly what a reader is about to redo. A note that says "parse with a regex" prevents nothing. A note that names the input that defeats split() prevents the rewrite.

    #The catalogue

    • Quoted-field parsing and the injection-attempt referer — common-log-format-parsing.
    • The test that passed before entering the function; the "no"-is-truthy fixture trap — tests-that-pass-for-the-wrong-reason.
    • Image.ANTIALIAS and ImageDraw.textsize removed in Pillow 10, findAll(text=True) removed in BeautifulSoup 4.13 — pillow and beautifulsoup.
    • The Babel CDN leaving a blank page on file:// — vendor-react-over-babel-cdn.
    • errors="replace" costing one skipped line rather than the run; image_ratio returning None "rather than print a zero"; size=0 "so that summing it never needs a guard".

    #Where it comes from

    It is the load-bearing compensation for import-finished-work-into-git. In python-programming-laboratories all twelve commits landed in one day with no fix commits at all — so the Pillow port, the bs4 port, the restructured faculty site and the wrong-reason test exist only as README prose. Where the git history is thin, the prose has to carry the diagnosis.

    discrete-mathematics-laboratories does both: 48ba16d Fix UnicodeEncodeError in the lab3 demos on Windows consoles is a real corrective commit, and the lab-5 README writes out the CDN failure in full. This is the sibling of provenance-and-limits-stated-inline — that pattern states what a claim does not cover, this one states what a design already survived.
