    Agent Orchestrator

    A VS Code extension that turns one request into a plan and runs it across the coding CLIs the author already pays for. An openrouter model reads the workspace, decides whether the request needs one answer or several agents, splits it into a DAG of subtasks, routes each to claude-code-cli or codex-cli at a chosen model and reasoning effort, runs independent work in parallel (dag-scheduling-in-waves), and merges the results.

    The repository folder is vs-llm-orchestrator; the product inside it is agent-orchestrator. One repository holds both, for reasons recorded in one-repository-at-the-workspace-folder.

    Three processes share one machine. Nothing is hosted and no component listens on a socket. The extension has zero runtime dependencies and the webview has no build step (zero-dependency-no-build-step).

    #The split

    LangGraph is Python and the extension API is TypeScript, so the graph runs as a subprocess. That leaves the graph runnable and testable without VS Code, while the extension spawns it, forwards events, and renders them. One JSON object per line in each direction is the complete protocol, which is what makes replay-a-recorded-run possible.

    #Durable goals and portable replay

    Each request belongs to a durable goal. Send continues the active goal; New goal explicitly starts a replacement. Acceptance criteria and verified evidence survive a backend restart or panel reload, so a reader can distinguish a continuing task from a new one.

    Large input is staged in chunks before planning. Input, prompts, provider events, tool events, and results enter a redacted durable trace before the equivalent live event is forwarded. The panel loads retained trace records on demand and preserves which details the reader expanded. The recorded dag-waves fixture keeps a real run's event order while using portable paths: /workspace/dag-waves/scratchpad/ws5, /usr/local/bin/claude, and /usr/local/bin/codex.

    #Autonomy

    Both CLIs run non-interactively, so the autonomy level is chosen before the run and passed as flags (autonomy-decided-before-the-run). readonly maps to plan/read-only modes; auto maps to accept-edits/workspace-write with a build, test, and inspect allow-list; and full maps to bypass-permissions/danger-full-access. Since 0.10.0, full is the shipped default. It is stated plainly as a choice, not presented as a sandbox.

    The router is the only component that sees every subtask output and has no tools. A prompt can persuade it to produce a wrong answer, but cannot directly produce an action.

    #Verification

    The 2026-08-12 local audit passed 345 backend tests, 44 recorded-run panel checks, TypeScript compilation, and 25 repository guards. Extension-host coverage has 33 checks for both source and installed builds. The sandbox could not read the owner's default pytest temporary directory, so that audit supplied an external writable temporary root; that is an execution-host limit, not a product failure. The real CLIs, OpenRouter API, and live permission behaviour were not exercised by this non-display audit.

    #Status

    Version 0.10.0 is working and not published. Marketplace publication remains blocked by a rotated-key requirement, placeholder publisher metadata, no repository field or Marketplace PNG icon, and no Marketplace screenshots until a repository URL exists. docs/RELEASING.md section 3 is the current checklist.

    #Git and documentation

    The product was imported into Git at vs-llm-orchestrator/ on 2026-08-08 after existing as a folder. At that point, brain.py verify-sources changed from reporting it as not a Git repository to reporting it clean; source cleanliness is now checked separately for each audit.

    The repository has an ISO/IEC/IEEE 29148 requirements specification (162 functional and 8 non-functional requirements), architecture and security documents, a test plan, risk register, release procedure, and 19 ADRs. The 60-plus-image screenshot matrix is generated from recorded runs, so a figure is a repeatable visual check rather than an illustrative mockup (readme-as-guided-tour).

    The 30 vendored skills retain their upstream URL, license, and exact commit in a NOTICE file: agent-skills-checked-into-the-repo and provenance-notice-file.
