    Leaflet

    Small open-source JavaScript map library — tile layers, markers, polylines, layer toggles, and very little else. It appears twice in this corpus, in two different repositories, at the same version (1.9.4) from the same CDN, which is itself a finding about how this developer reaches for a map.

    #Optimization Methods — the route explorer

    instance_generator/map_app/city.template.html loads Leaflet from unpkg:

    <link rel="stylesheet" href="https://unpkg.com/leaflet@1.9.4/dist/leaflet.css" />
<script  src="https://unpkg.com/leaflet@1.9.4/dist/leaflet.js"></script>

    Python generates one HTML page per city from that template with the route geometry baked in as coordinate arrays. Each solver gets its own toggleable layer — greedy, blind_ga, lbbs and the tuned variants — so a reader can flip between plans on the same map instead of comparing two static PNGs. There are per-depot layers and a Drive/Evolve animation for watching a solution form.

    This is the presentation half of multi-depot-vehicle-routing, and it is why the repo needed a .gitattributes marking output/** as linguist-generated: the baked-in coordinate arrays are megabytes of generated .js that would otherwise make GitHub call optimization-methods a JavaScript project.

    #Discrete-Mathematics-Laboratories — Q-HYDRO Wrocław

    The Q-HYDRO app in lab5_GraphTheory maps a 25-node Lower-Silesian gravimeter mesh, also on Leaflet 1.9.4 from a CDN, with map tiles and IBM Plex fonts likewise remote. It sits beside a second lab-5 app (SentinelNet) that vendors react and has zero external URLs — two apps, one directory, exactly opposite dependency policies. See graph-connectivity-and-resilience.

    #The consistent exception to a consistent rule

    Both repos otherwise take vendoring seriously. Optimization Methods ships a standard-library-only C++ solver and a study guide with three plain <script> tags and no build step (zero-dependency-no-build-step); Discrete-Mathematics-Laboratories went to the trouble of precompiling JSX so SentinelNet runs offline.

    Maps are where that rule gets suspended, in both repos independently. The reason is not written down anywhere, but it is not mysterious: a map without tiles is not a degraded map, it is a blank rectangle, so the offline story is already lost at the tile server and vendoring the 42 KB library buys nothing. Both repos document the CDN dependency as a graceful-degradation case rather than hiding it, which is the honest version of the compromise — provenance-and-limits-stated-inline.

    The consequence is real, though: neither map app opens usefully from file:// on a plane, unlike every other static deliverable in the corpus (offline-first-static-deliverable).
