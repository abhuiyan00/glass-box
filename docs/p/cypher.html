    Cypher

    neo4j's declarative query language. Patterns are written as ASCII-art graphs — (a)-[:REL]->(b) — which makes a traversal query look like the thing it traverses.

    #What lab 6 uses it for

    Two .cypher scripts in discrete-mathematics-laboratories carrying the whole deliverable:

    Constraints first. Node-key uniqueness constraints created before any data lands, so MERGE is index-backed rather than a full scan.

    LOAD CSV + MERGE import. LOAD CSV WITH HEADERS streams the source file from the Desktop import folder; MERGE matches-or-creates so re-running the script is a no-op rather than a duplication. One :Object per row, 39 objects and 975 HAS_VALUE relationships. This is the graph half of idempotent-loading.

    The distinction that matters and is easy to get wrong: CREATE always creates, MERGE matches the whole pattern or creates the whole pattern. MERGE on a pattern with an unmatched middle node creates the entire path, so the safe idiom is to MERGE nodes separately, then MERGE the relationship between them — which is what the script does.

    Q0–Q6 report queries reading the pawlak-information-system back out: counts, per-attribute value distributions, and the grade/class grouping traversals.

    #Read beside its analogue

    lab6_Neo4j/viewer/pawlak.js reimplements each of these queries in plain JavaScript and renders the result next to the Cypher that produces it. Reading a graph query beside the imperative loop it replaces is the most direct way to see what the declarative form is buying — see dual-implementation-as-cross-check.

    #Note

    guide.txt explicitly steers away from Neo4j's GUI import tool toward scripts — cypher-scripts-over-neo4j-import-tool — which is what makes the import reproducible at all.
