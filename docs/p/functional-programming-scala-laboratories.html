    Functional Programming Scala Laboratories

    A fragmented set of Scala exercises rebuilt as one coherent laboratory. Scala 3.3.8 LTS on JVM 21, production code on the standard library alone, 33 deterministic MUnit tests.

    Seven modules, each answering one question, mapped to their implementation and their test evidence in docs/CONCEPT_MAP.md.

    #Why a rewrite rather than a cleanup

    The archive contains repeated downloads, committed build output, partial solutions, Scala 2-era application patterns, unchecked casts, and actor examples whose correctness depends on sleep and console timing. Copying it forward would have preserved the ambiguity rather than resolved it — see clean-room-rebuild-from-specification for the general rule, though here it is a quality decision rather than a provenance one: the material is the author's own.

    What carried across is the list of learning goals. Everything else was written anew.

    #The seven stops

    Module What it demonstrates
    Recursiontotal APIs, tail recursion, BigInt, Euclid's algorithm
    FunctionalLista recursive ADT with folds, maps, filters, type-safe sorting
    ImmutableCollectionsorder-preserving transformations over standard collections
    Expran expression ADT with an Either evaluation boundary
    Treestructural recursion, folds, mapping, mirroring, traversal
    TeamMemberaccumulating validation without exceptions or partial objects
    DeterministicConcurrencyparallel execution with input-ordered results

    TeamMember is the one worth reading. Validation that accumulates returns every failure at once instead of the first, and never constructs a half-valid object to carry the errors — which is the failure mode of the exception-based version, where the object exists before anyone has checked whether it should.

    #Guarantees, and why each is a guarantee

    Expected failures are Either or a validated result — never null, an unchecked cast, or a sentinel number. The archive contained all three, and each one is a failure the type system was offering to catch for free.

    Collection APIs preserve input order unless the name says sort or reverse. An ordering that happens to hold is an ordering callers will depend on and maintainers will break.

    Concurrent results line up with input positions even though tasks finish in any order. This is the direct answer to the archived actor examples: their correctness depended on timing, so the tests could only be flaky or vacuous. Making completion order irrelevant to the result is what makes a deterministic test possible at all.

    No wall-clock timing, randomness, network, or shared global execution context in tests. A test that sleeps is a test that is slow when it passes and wrong when it fails.

    #Verification

    scala-cli test .
scala-cli run . --main-class fplab.runLaboratories

    scripts/verify-toolchain.ps1 checks the pins are the pins actually installed, and scripts/verify-layout.ps1 checks the structure — both run in CI on a clean Java 21 runner alongside compile, test and demo. Pinning a version in a build file and never asserting it is how a project comes to require a toolchain nobody documented.

    #2026-08-12 reference audit

    The layout verifier passed with 16 Scala files, no archived artifacts, and no exact duplicate sources on Java 21. The local runner did not expose scala-cli, so no compile, test, or demo result is claimed from this environment. The existing transit-map visual is kept as a guide to the documented seven modules and 33 declared deterministic MUnit tests; the unverified count remains explicitly attributed to the repository, not this audit.

    #Open gaps

    • TODO: no property-based testing. FunctionalList and Tree have algebraic laws (fold/map fusion, mirror-of-mirror identity) that example-based tests only sample.
    • TODO: DeterministicConcurrency uses the standard execution context and proves ordering, not throughput or cancellation. No effect system, deliberately — adding one would demonstrate a library rather than the ideas.
    • TODO: exercises, not an application. There is nothing to deploy, and the test suite is the deliverable.
