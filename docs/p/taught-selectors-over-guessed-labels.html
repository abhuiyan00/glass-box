    Taught Selectors Over Guessed Labels

    Stop trying to infer which UI element is which from its text, and let the user point at it once. Store the stable identifier — a view ID — and match on that afterwards. Text guessing is a bet on someone else's copywriting and locale; a taught selector is a fact the user supplied.

    #The failure that produced it

    farely first shipped PAUSE_LABELS / RESUME_LABELS: keyword lists meant to find a "pause" control in Bolt, Uber and FreeNow. The premise itself was wrong, and the CHANGELOG says so plainly rather than quietly deleting it:

    "Correcting a wrong premise: no ride app ships a \"Pause\" button, and the real controls (online/offline toggle, \"Stop new requests\", trip / ID-check markers) differ per app + locale and are often icons with no matchable text."

    Farley/docs/ocr-overlay/CHANGELOG.md, 2026-07-12

    Three distinct defeats for label guessing in one sentence: the control may not exist, its name varies per app and language, and it may be an icon with no text at all. No amount of keyword tuning recovers from the third.

    #The replacement — Learn-controls

    The driver opens the target app, Farely watches, and the driver tags the real node. What gets stored is a selector, matched view-ID-first with text as a weaker fallback — flagReportViewIds on the accessibility service is what makes those IDs visible in the first place, see android-accessibility-service. Coverage is displayed as a fraction (0/4 → 2/4 in the recorded manual checks), so the user can see what the app still cannot do.

    #Boundaries

    Tagging is restricted to chore controls — the multi-app housekeeping actions. A ride offer's Accept button can never become a taught selector; that exclusion is enforced separately and argued on never-automate-the-accept-tap. A general-purpose "teach me any button" mechanism would have dissolved the product's central safety rule, so the teaching surface is deliberately narrower than the technique allows.

    #Where else it applies

    Any automation over an interface you do not own and cannot version-pin: browser extensions over third party sites, RPA over enterprise apps, test suites over someone else's front end. The same trade appears in farely's reading path, where a structured node read beats an inferred one — node-tree-read-before-ocr — and it is the same instinct as provenance-and-limits-stated-inline: prefer the value that was given to the value that was derived, and record which one you have.

    #Cost

    It is unusable on first launch. Every taught selector is an onboarding step, and the app must degrade gracefully to zero coverage — which it does, by simply not offering chore automation until taught.
