    Deterministic Seeded Substitution

    The mechanism that makes structure-preserving-anonymisation work. Instead of drawing a random replacement each time a value is encountered, derive the replacement from the value itself through a keyed hash, so the mapping is a pure function.

    The construction in labour-fraud-analysis:

    1. Concatenate a single global seed string, a namespace (which kind of thing is being replaced), and a stable key (either a surrogate id or the original value).
    2. Hash that with blake2b.
    3. Interpret the digest as an integer and use it to seed a random.Random instance.
    4. Draw the fake value from that instance's own stream.

    Every draw for a given (namespace, key) therefore comes from a private, reproducible generator.

    #The three properties it buys

    • Cross-table consistency. The same source entity maps to the same fake entity in every table and in free prose, without keeping a lookup table in memory during the run. Joins survive; the entity graph survives. Without this the whole dataset falls apart into unlinkable fragments.
    • Reproducibility. Re-running the pipeline on the same input produces byte-identical output, which is what lets generated artefacts be committed and diff-checked — see generated-docs-checked-by-ci-diff and reproducible-analysis.
    • A regeneration switch. Changing the one seed string produces a completely different but internally consistent world:

    "Global seed — flip this and re-run to regenerate a completely different (but internally consistent) fictional world. Committed value gives the published data."

    #Namespacing is not decoration

    Two different entity types can share a key value — an id 4102 might exist as both a person and a company. Without the namespace in the hash input, they would derive the same generator and could collide into related-looking fake values, leaking a correlation that does not exist in the source. The namespace makes each entity type's mapping independent.

    #What is and is not secret

    Determinism means the mapping is exactly as strong as its inputs. The seed string is committed; the mapping's other input is the private source data. The re-identification key — the materialised mapping file — is git-ignored, and so are the local scrub rules. This wiki does not reproduce the seed value, the mapping, or any mapped value; describing the mechanism is safe, publishing a pair is not. The same reasoning as secrets-from-environment-only: the algorithm is public, the key is not.

    Note the corollary honestly: anyone holding the private source and the seed can reconstruct the mapping. The scheme protects against a reader who has neither, which is the actual threat model.
