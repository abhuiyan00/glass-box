    The Shortest-Path Algorithm Family

    Four algorithms, one problem, four different sets of assumptions. SentinelNet in discrete-mathematics-laboratories implements all four against the same graph, which is the only way the trade-offs stop being a table to memorise — an instance of multiple-solutions-side-by-side.

    Algorithm Scope Complexity Requires Gives you
    Dijkstrasingle sourceO((V+E) log V) with a heapnon-negative weightsthe default
    Bellman–Fordsingle sourceO(V·E)nothingnegative weights and negative-cycle detection
    A\*single pairDijkstra-boundedan admissible heuristicfar fewer expansions when geometry is known
    Floyd–Warshallall pairsO(V³)nothingthe full distance matrix, and transitive closure for free

    The choices that matter in practice:

    • Bellman–Ford is not a slower Dijkstra. Its extra pass exists to detect negative cycles — a distance that keeps improving after V−1 relaxations means no shortest path exists. Dijkstra cannot express that question.
    • A\* is Dijkstra plus a lower bound. SentinelNet uses the Haversine great-circle distance as the heuristic. It is admissible because straight-line distance over the sphere can never exceed travel along edges, and admissibility is precisely what preserves optimality.
    • Floyd–Warshall wins when you need every pair. Running Dijkstra V times is asymptotically better on sparse graphs but loses on dense ones and costs far more code.

    SentinelNet backs Dijkstra with a hand-written binary MinHeap rather than a library priority queue, which is the difference between O((V+E) log V) and the naive O(V²).

    Q-HYDRO, at 25 nodes, deliberately does not bother, and says why:

    "Note: Prim and Dijkstra use simple O(V·E) / O(V²) implementations for readability. At |V| = 25 this is instant; swap in a binary heap for scale."

    #The TSP tail — and a correction

    Beyond shortest paths, SentinelNet attempts tours: nearest-neighbour construction, 2-opt improvement, and a function named tspChristofides.

    That function is not Christofides. Christofides guarantees a tour within 1.5× optimal by taking a minimum spanning tree, finding a minimum-weight perfect matching on the odd-degree vertices, combining them into an Eulerian multigraph and short-cutting the Euler tour. sn-algo.js matches the odd-degree vertices greedily. Greedy matching can be arbitrarily worse than optimal, so the 1.5-approximation bound is lost — what remains is a Christofides-shaped heuristic with no proven ratio. confidence: high, read directly from source. It should not be cited as Christofides.
