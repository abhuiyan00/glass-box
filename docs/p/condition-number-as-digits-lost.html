    Condition Number as Digits Lost

    "Ill-conditioned" is a word that does no work. The condition number turned into decimal digits of accuracy destroyed by the solve is a number that does:

    digits lost ≈ log₁₀(condition)

    A double carries about sixteen. A system with condition 10¹⁰ returns an answer with roughly six correct digits; at 10¹⁶ it returns none, and it returns them without complaint.

    #The measurement that makes ridge regression obvious

    Ridge adds λI to the Gram matrix before solving. That shifts every eigenvalue up by exactly λ, which is why a singular system becomes solvable and a merely bad one becomes good. Measured on a degree-8 polynomial design over eleven points:

    λ condition estimate digits lost
    03.32 × 10¹⁰10.5
    10⁻⁸1.07 × 10⁸8.0
    10⁻⁶2.71 × 10⁶6.4
    10⁻⁴4.57 × 10⁴4.7
    10⁻²7.78 × 10²2.9
    11.01 × 10¹1.0

    Ten of sixteen digits gone before any regularisation. The λ that a model-selection sweep picks on validation error is usually somewhere in the middle of that table, which means the stability gain is real and not an artefact of a value nobody would choose.

    #Polynomial fits are the standard bad case

    A polynomial design matrix is a Vandermonde matrix, and Vandermonde matrices are the textbook example of ill-conditioning. Anyone fitting a high-degree polynomial to closely spaced points is in this regime by default, not by misfortune.

    That is worth knowing because the symptom is not an error. The solve succeeds, the coefficients come back finite, and they are wrong in the digits nobody prints.

    #Solve, do not invert

    (ΦᵀΦ)⁻¹Φᵀy is how the formula is written and solve(ΦᵀΦ, Φᵀy) is how it should be computed. The two are algebraically identical; the explicit inverse does more arithmetic and keeps less of it. On a Vandermonde system the difference is measurable rather than theoretical, which is why both routes exist in the implementation and a test compares them.

    #State the estimate's limits with the estimate

    The implementation's condition_estimate is the ratio of largest to smallest pivot in the elimination, not the true 2-norm condition number, which needs singular values. It tracks the same thing closely enough to demonstrate the effect and it is named condition_estimate for exactly that reason — provenance-and-limits-stated-inline.

    An approximation labelled as the real thing is a claim that will be relied on past its accuracy.

    #The cost side

    Regularisation buys stability with bias. On data an unregularised fit handles well, ridge makes the training error strictly worse, and that is asserted rather than mentioned. λ is not a free improvement; it is a dial between two failures, which is the same shape as held-out-error-over-training-error — a metric that only improves is a metric that is not measuring the trade.

    #Where this appears

    Implemented and measured in systems-analysis-and-decision-support. The singular case raises rather than returning an arbitrary member of the solution set, which is the tests-that-pass-for-the-wrong-reason argument applied to numerics: an arbitrary answer is indistinguishable from a real one once it leaves the function.
