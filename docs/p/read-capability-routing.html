    Read-Capability Routing

    The planner picks an executor because it thinks one is better suited. That preference is overridden whenever the subtask must read something the chosen executor cannot open. Capability beats preference, and it is checked before the run rather than discovered by it — sending a PDF to something that cannot open one costs a full CLI round-trip and comes back as an apology.

    #The two tables

    Files are classified into read classes by extension, and each executor declares the classes it can handle:

    READ_CLASSES = ("text", "extract", "vision")

AGENT_READS = {
    "claude": {"text", "extract", "vision"},
    "codex":  {"text"},
    ROUTER_AGENT: set(),
}

    A fourth class, opaque, is what nothing can read — a binary, a compiled artifact — and naming it is useful precisely because it routes to no one and should be reported, not attempted.

    codex-cli's entry is conservative on purpose: text is what it is established to handle here, and anything else is a guess whose wrong answer costs a whole attempt. The router's empty set is not a limitation to fix — it is openrouter being a bare chat completion with no file access, which is the same fact the security model leans on.

    #The bug this shape hides

    _sanitize computes need ⊄ AGENT_READS[agent] and reroutes to the first fallback candidate that can cover need. Since reads defaults to ["text"] and the router's capability is set(), the condition is true for every router-assigned subtask — including the pure-reasoning ones the planner deliberately kept on the router because they read nothing at all. Every one of them was silently moved to a CLI.

    That made the last entry of the fallback order dead code, and the visible symptom appeared only in the worst case: with both CLI subscriptions spent, a run reported that every capable agent had failed while the router sat there, tool-free and perfectly able to answer. Fixed in 0.7.1 — a subtask that declares no file reads stays where it was put. See agent-orchestrator.

    The general lesson is narrower than "test your predicates": a default value (["text"]) and an empty capability set produce a rule that is always true, and a rule that is always true reads exactly like a rule that works.
