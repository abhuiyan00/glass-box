    Python Programming Laboratories

    Twelve laboratories from the Script Languages course at Wrocław University of Science and Technology, deliberately refactored into one installable project instead of twelve loose scripts. Nine labs read the same Apache access log, so parsing, reading, aggregation and config live once in a weblog package and each lab is a thin script over it — the organising move recorded on extract-the-shared-core.

    75 files, Python ≥3.10, setuptools with a src/ layout, MIT, remote over SSH.

    #Shape

    • src/weblog/ — entry, reader, stats, config, cli. Declares dependencies = [].
    • tests/ — 6 pytest files, 75 def test_ plus 5 parametrize decorators.
    • labs/01_first_steps/ … labs/13_sqlite_and_gui/ — each with its own README carrying the engineering narrative. See numbered-stages-in-directory-names.
    • data/ (2,039-line access log, a 2.7 MB tweet CSV, a JSON corpus), assignments/lab-NN.pdf × 12 as issued, assets/ (4 PNGs + a provenance README).
    • No docs/, no .gitattributes, no CLAUDE.md, no CI, no Git LFS.

    Concepts the labs actually teach: common-log-format-parsing · pythons-data-model · separating-computation-from-io · idempotent-loading · tests-that-pass-for-the-wrong-reason.

    Libraries in play: click · argparse · factory-boy-and-faker · beautifulsoup · pillow · matplotlib · sqlite · tkinter · setuptools-and-pyproject.

    #Git history — the pure publishing-dump case

    The first 12 commits land all on 2026-07-25, strictly layer-ordered: Add the weblog package → Add the test suite → Add the data files → labs in four batches → assignment sheets → screenshots → Add the README, licence and gitignore. No fix commits, no refactors, no reverts, no message referring to anything already committed — and the tests are committed before most of the code they exercise.

    The 13th, on 2026-08-01, is the first commit in this repository's history that refers to something already committed. It is a fix, and it is the only one — which is the pattern holding, not breaking: the publishing dump has no fix commits because the fixing happened before the import, and the one defect that survived the import needed a commit shaped like real work to remove.

    The real engineering history survives only as README prose: the Pillow-10 port, the BeautifulSoup 4.13 port, the restructured faculty site, the test that passed for the wrong reason. This repo is the clean confirmation of import-finished-work-into-git, and the mirror image of discrete-mathematics-laboratories, which contradicts it. The licence lands in a separate final commit exactly as in that repo — presentation-polish-tail-commits.

    Because the failure modes are written beside their fixes rather than in commits, the READMEs carry what git does not: document-the-failure-mode-next-to-the-fix and provenance-and-limits-stated-inline.

    #Findings

    • Confirmed defect, since fixed. tests/test_lab09_insults.py does import factory and uses factory.Faker(...), and pyproject.toml's dev extra listed only pytest and pytest-cov, so the README's own quick start failed at collection in a clean virtualenv. factory-boy, faker and click were declared on 2026-08-01 in 385d0fd, each with the reason inline. The repair found a second layer the original finding missed: the same test imports labs/09_dataset_reports/insults.py, which reaches click at module scope, so declaring the two obvious packages still did not collect. Measured after the fix — 89 tests collected; a clean pip install -e .[dev] runs 88 and skips 1, the skip being pytest.importorskip("openpyxl"), which lives in the labs extra by design. confidence: high, both states read directly. Recorded on factory-boy-and-faker and documentation-drift.
    • Namespace hazard. labs/04_classes/requests.py shadows the requests package that labs 10 and 11 import, if that directory ever lands on sys.path. confidence: high.
    • The README says "Twelve laboratories" while the directories number to 13/14 — labs 11–12 and 13–14 are merged into single directories. Minor drift.
    • The core package declares zero dependencies and pushes every library into an optional labs extra — see zero-dependency-no-build-step.
    • Generated outputs are gitignored (build/, *.db, *.docx, *.xlsx, charts/) as "all reproducible from source" — the deliberate opposite of generated-audit-artifact.
