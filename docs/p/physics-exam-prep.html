    Physics Exam Prep

    Not a generated static site and not an asset dump: a hand-written, zero-dependency, offline-first single-page web app — an installable PWA — built from one Physics course's own 106-slide deck (F. Peña-Benítez, 04ITE0-25S301O01903W) and enriched with OpenStax University Physics Vol 3. One of four instances of course-as-runnable-study-tool.

    Status: coursework, finished and frozen at last commit 2026-07-10. "All finished and frozen" (interview, 2026-07-28).

    #What it contains

    29 topics across 4 modules · 13 canvas simulators · 82 Leitner flashcards (spaced-repetition-leitner-boxes) · a 75-question quiz bank · 3 generated study sets (jaccard-similarity-set-selection) · the 30-question scanned exam transcribed with worked step-by-step solutions · a progress dashboard · a 6/7-hour study plan · a printable cheat sheet.

    #There is no build system, and that is the point

    No package.json anywhere in the repo. No SSG config, no bundler, no CI workflow, no output directory. exam_prep/index.html is a hand-authored 5.6 KB shell with five <script> tags; routing is hash-based vanilla JS in js/app.js; sw.js is hand-written. See zero-dependency-no-build-step and offline-first-static-deliverable.

    The only vendored dependency is katex — CSS, JS and 20 .woff2 files copied locally so no CDN is ever contacted. That is a deliberate choice with a rejected alternative: vendor-katex-instead-of-cdn. The bulk of the repo's bytes are therefore content (36 lecture and textbook diagrams, 5 animations) plus math fonts — not build residue.

    File Size Is
    js/data.js101 KBthe knowledge base — topics, formulas, flashcards, quiz bank, plan
    js/app.js47 KBthe SPA — routing, flashcards, quiz, dashboard, timer, search
    js/teach.js47 KBthe "Feynman layer" — intuition, analogies, 40 self-checks, 13 predict-first prompts
    js/sims.js39 KBthe canvas simulators
    js/quizsets.js23 KBgenerated by tools/build_sets.mjs
    tools/build_sets.mjs31 KBJaccard set builder + auditor, Node-only
    tools/qa.mjs14.9 KBhand-rolled static-check harness, Node-only

    Both .mjs tools load the browser's data.js by executing it into a fake window (new Function("window", code)(win)) instead of converting it to an ES module — the global-script shape is preserved on purpose so the browser needs no module system. tools/ is never shipped.

    localStorage progress is keyed physprep.v1 — the same invalidation idea as the STORAGE_VERSION counter used by the sibling apps in course-as-runnable-study-tool, expressed as a versioned key rather than an integer.

    #The tooling is real, and it audits itself

    tools/build_sets.mjs emits both js/quizsets.js and a committed tools/AUDIT.md sanity report — generated-audit-artifact. tools/qa.mjs runs static integrity checks including check 8, "Service worker precache vs index.html", which fails if any asset index.html loads is missing from the service worker's CORE list. That check exists because it caught a real offline bug; the fix is recorded as cache-individually-not-addall.

    What none of it checks is subject-matter correctness: the README claims the Bohr simulator reproduces the Balmer lines at 656 / 486 / 434 / 410 nm, but qa.mjs validates ids, asset paths, KaTeX parsing and precache coverage — never numerical output. See provenance-and-limits-stated-inline.

    #Findings

    • The app was built outside version control. File mtimes run 2026-06-27 (vendor/katex) to 2026-06-30 (js/*), ten days before the first commit on 2026-07-10 — seven commits in two clusters, the second being the licence/badge pair shared with computer-project-management and privacy-policy-template. import-finished-work-into-git with mtime proof.
    • These are also the earliest in-repo timestamps of the whole exam-prep family. The interview names it-applications-in-business-and-commerce as the origin of the lineage and that answer is authoritative; the mtime tension is argued out once on course-as-runnable-study-tool and is not re-litigated here.
    • documentation-drift, four independent instances — the densest concentration in the source set, all of them the docs falling behind the code: | Claim | README.md | snapshot.md | The code / generated output | |---|---|---|---| | service-worker cache version | physprep-v2 | physprep-v3 | physprep-v4 in sw.js | | simulators in sims.js | 9 (structure block) / 13 (feature table) | 13 | — | | qa.mjs static checks | 32 | 34 | — | | quiz bank size | — | 75 | build_sets.mjs header says 62; AUDIT.md reports 75 |
    • A claimed test harness that is not in the tree. exam_prep/README.md states "A headless DOM smoke test additionally renders all 40 routes without a runtime error". tools/ contains only build_sets.mjs and qa.mjs. confidence: high on the absence.

    #Open gaps

    • TODO: the cache-version history is undocumented drift. physprep-v2 → v3 → v4 implies at least two unrecorded offline-cache changes after the README was written. Asked at interview and answered "Don't remember the cache history" — so what broke, and what each bump fixed, is unrecoverable. confidence: low on any narrative about the cache; nothing is invented here.
    • The tool was used for the exam — confidence: medium, implied by the interview answer's own framing rather than stated outright.
    • TODO: "two answer-key errors in the provided exam set were caught and corrected" rests solely on the author's own AUDIT.md; never confirmed with the lecturer. The two READMEs even disagree on which questions they were. confidence: low.
    • TODO: the "Feynman layer" is the app's signature idea and is never defined as a method, only exemplified across 29 topics. No rule distinguishes a good "Feynman's take" from a summary.
    • TODO: whether it was ever served over HTTP (the service worker is dormant under file://) or only ever double-clicked is unrecorded. There is no Pages config and no CI.
    • TODO: no reason is recorded anywhere for vanilla JS + hash routing over a framework, beyond the repeated "no build step". Whether a framework was tried first is unknown. confidence: low.
