    Structure-Preserving Anonymisation

    Redaction destroys the thing being studied. If the finding is that many nominally independent people share one contact address, blacking out the address deletes the finding. Structure-preserving anonymisation is the alternative: replace every value, keep every relationship.

    "Reconciling those is the whole trick: replace every value, preserve every relationship."

    labour-fraud-analysis-a-forensic-data-investigation/docs/methodology.md, 2026-07-11

    #What "preserve every relationship" means concretely

    In labour-fraud-analysis the properties the analysis depends on are enumerated and each is carried across deliberately:

    Property in the source Why it must survive How
    The same person appears in six tablesjoins, and the graphdeterministic-seeded-substitution — same input maps to the same output everywhere
    A batch of documents has consecutive serial numbersthe bulk-filing signalthe batch is offset by a constant, so contiguity is preserved
    Many people share one contact pointshared-identifier-clusteringthe sharing is a join key, so it maps identically
    Identifiers have a recognisable shapeparsers, regexes and the eyeformat-preserving-invalid-identifiers
    Some dates are wrong, from OCRthe dataset must exercise the same cleaning problemserrors are copied, not fixed

    "Data-quality artifacts — wrong dates from OCR are preserved so the dataset exercises the same cleaning problems as the original."

    labour-fraud-analysis-a-forensic-data-investigation/docs/methodology.md, 2026-07-11

    Two of these preserved properties are regression-tested — the shared-contact concentration and the bulk-filing batch each have a test asserting the pattern still exists after anonymisation. Testing that a finding survived the privacy pipeline is the part most implementations skip. See reproducible-analysis.

    #Free text is the hard part

    Structured columns are easy: you know which column holds what. Prose does not announce its identifiers. The pipeline makes three passes — a length-sorted, boundary-aware replacement (with the word boundary deliberately widened so that an identifier glued to a filename by an underscore is still caught), a glossary pass that also cleans up orphaned grammatical particles left behind by substitution, and a residual regex sweep. Each pass exists because the previous one demonstrably missed something. The disclosure-gate is what proves the passes worked.

    The module that does this holds no source strings in its own text:

    "This script may reference real strings at run time because it reads them from the private source; it contains none in its own text."

    labour-fraud-analysis-a-forensic-data-investigation/src/anonymize.py, 2026-07-11

    #Stated limitation — residual source signalling

    docs/methodology.md §4 claims the world is relocated and that no origin-signalling scrap survives. That claim is not fully borne out by the committed code. Column names retain the source jurisdiction's identifier registers (pesel, nip, regon, krs) and carry through the DDL, the CSV headers, the dashboard and the generated data dictionary; the validator's allow-list contains the source country's name and adjective; one PII pattern is a country-specific phone prefix; the viewer still formats numbers with that jurisdiction's locale; and one generator comment names a jurisdiction-specific company form.

    None of these is a person-like value, and none re-identifies anyone. But together they narrow both the host jurisdiction and the worker-origin corridor, which is exactly the class of inference the methodology says it removed. Recorded here as a limitation of the implementation, not of the technique. It is one of the reasons every page for this repo is publish: false.
