    pandas

    Python's in-memory dataframe library. In labour-fraud-analysis it carries the entire analytical argument — and, notably, nothing else.

    #The boundary: pandas at the surface, stdlib csv in the pipeline

    Verified from the import graph across all eight src/ modules plus the notebook and the test suite:

    Uses pandas Uses the standard-library csv module
    src/app.py — the streamlit dashboardanonymize.py, build_db.py, build_docs.py, build_viewer.py, port_report.py, validate_anonymization.py
    notebooks/01_investigation_analysis.ipynbsrc/tests/test_dataset.py

    The anonymisation pipeline, the SQLite build, the generated docs, the disclosure-gate and the whole test suite are written against csv.DictReader and collections.Counter. That is a real and defensible split rather than an inconsistency: the pipeline's job is faithful row-by-row transformation of untrusted text where a dataframe's type inference is a liability, and the analysis surface's job is fast grouped aggregation where it is the point. The test suite staying on stdlib also means the integrity checks do not depend on the library whose behaviour they would otherwise be testing through.

    #The two idioms that carry everything

    Read everything as text, coerce per analysis.

    pd.read_csv(path, dtype=str).fillna("")           # every table, every column
pd.to_numeric(df["value"], errors="coerce")       # only where a number is needed

    Nothing is inferred at load time. A permit number that looks like an integer stays a string; a contract value becomes numeric only inside the one analysis that needs it, with unparseable rows becoming NaN rather than raising. For a forensic dataset that deliberately retains data-quality artefacts — OCR-mangled dates are kept, not cleaned — this is the correct default: type inference would quietly "fix" exactly the damage the dataset exists to exhibit.

    Group, count, sort. Every one of the four named signals is one of:

    • groupby([date, employer]).size() — bulk sponsorship batches
    • value_counts() on a contact column — shared-identifier-clustering
    • a 30-bin histogram of a coerced numeric column — declared-wage uniformity
    • groupby([year, employer]).size() — entity succession

    No statistical model, no significance test, no outlier score. The method is aggregation plus convergent-evidence; pandas is exactly sized for it.

    #In the dashboard

    The whole data/csv directory is loaded into a dict[str, DataFrame] behind @st.cache_data, so twenty tables are parsed once per session. Frames feed plotly figures directly and the graph analysis via networkx; the notebook plots the same frames through matplotlib instead. Both recompute from the CSVs on every run — nothing is hard-coded, see reproducible-analysis.
