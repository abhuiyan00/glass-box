    Single-Source-of-Truth Generators

    Hold the facts once, in a plain data structure, and emit every deliverable from it — including deliverables in different formats and for different audiences. The test of the pattern is not "is there a generator"; it is can any two outputs disagree. If they can, it is not this pattern.

    Confirmed twice in Information-Systems-Modelling, in two consecutive labs written the same day.

    #Lab 7 — one spec, three artefacts

    lab7/src/specs.js (605 lines) declares each of eight business processes once: pools, lanes, nodes with event markers, sequence flows, message flows. A zero-dependency Node generator (layout.js 307 · svg.js 298 · bpmn.js 134 · report-text.js 49) turns each spec into a rendered SVG, a Camunda-compatible .bpmn file with diagram interchange, and a section of the PDF report. The README states the reason in the same breath as the mechanism:

    "A zero-dependency Node generator holds the eight processes once as a data model and emits the diagrams, the BPMN files and the report from it, so the rendered SVG and the .bpmn diagram interchange can never drift."

    Information-Systems-Modelling/lab7/README.md, 2026-07-09

    "Can never drift" is the load-bearing claim, and here it is structurally true: the SVG and the .bpmn are two renderings of one object, not two documents about one process. See bpmn-process-modelling.

    #Lab 6 — one dataset, two RDF syntaxes

    lab6/app/data/*.json holds the instance data; one renderer emits RDFa 1.1 in the body and JSON-LD in the head of every page, plus the static site and the SSR responses. The README is explicit that this replaced a hand-written version, and names the failure it was replacing:

    "The old approach hand-wrote the same data into six HTML files twice (RDFa in the body + JSON-LD in the head), so every fact lived in 2–4 places and could drift. This app makes the data the single source of truth and generates the markup."

    Information-Systems-Modelling/lab6/app/README.md, 2026-07-09

    The switch is a recorded decision with a deletion behind it — see generate-markup-instead-of-hand-writing-it — and it is the only place in the fifteen-repo source set where a superseded version was deleted rather than kept.

    src/rdf/vocabmap.js extends the idea to the documentation about the output: the VOCAB MAP comment at the top of each page is generated by walking that page's own graph, so a term added to the data cannot leave the comment stale. See linked-data-publishing and provenance-and-limits-stated-inline.

    #Why it keeps appearing next to zero-dependency Node

    Both instances are dependencies: {} with node: builtins only, and so is the exam trainer in the same repo — see zero-dependency-no-build-step. That is not a coincidence: a generator you own end to end has no upstream to track, so the cost of not taking a diagramming library or a templating engine is one afternoon of layout.js, and the benefit is that the pipeline still runs in five years.

    #The limit of the pattern in this repo

    Lab 6's headline principle is that no fact should be written twice. Meanwhile ontology.ttl exists as byte-identical copies in lab5/.../resources/ and lab6/vocabulary/ — the one fact the generators do not own is duplicated across the lab boundary, and the prose does not mention it. The generators guarantee consistency within a lab, not across the repo. Compare keep-the-superseded-version-in-tree, which explains why nothing gets deduplicated here.

    The narrower sibling pattern — where the generated file and its input both live in the tree, with a DO-NOT-EDIT banner on the output — is generated-artifact-with-pristine-source.
