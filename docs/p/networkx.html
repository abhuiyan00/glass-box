    NetworkX

    Pure-Python graph library. Appears in two repositories in this corpus, and in both it is used for graph construction and layout rather than graph algorithms — the analysis it enables is done elsewhere or by eye.

    #In Optimization Methods — a transport, not a solver

    NetworkX is present as the object model osmnx returns: a downloaded drive network arrives as a NetworkX MultiDiGraph, gets truncated to its largest strongly-connected component, has parallel edges collapsed, and is then exported to CSV and abandoned. The shortest-path work is re-implemented in C++17 as lazy-dijkstra-distance-cache; networkx.shortest_path is never in the inner loop.

    That is a defensible split — a GA evaluates millions of distance queries per run and a Python shortest-path call per query would dominate everything — but it means NetworkX's actual contribution to multi-depot-vehicle-routing is graph cleanup, and the routing library is the user's own 40 lines of C++. It is listed as an unpinned dependency; only osmnx>=2.0 carries a version floor.

    #In labour-fraud-analysis — an entity graph read visually

    The forensic investigation builds a networkx.Graph from four edge specifications — work_permit, contract, payroll and residence_card, each linking a person to a company — then lays it out with spring_layout(seed=7, k=0.55) and sizes nodes by degree.

    The finding extracted from it is bridging: persons with two or more company neighbours, counted as evidence of entity succession (a worker's paperwork migrating from a predecessor company to a successor). That is a degree threshold, computed directly.

    No centrality measure is computed — no betweenness, no eigenvector, no community detection. Bridging is exactly the measure that betweenness centrality was designed for, so the graph is doing less work than the library would allow. Whether that is deliberate restraint (a threshold anyone can audit beats a centrality score nobody can) or unexplored headroom is not recorded.

    The seeded spring_layout is worth noting on its own: seed=7 makes the picture reproducible, which matters when the picture is the evidence being shown to a reader — the layout is an output artefact, not a viewing convenience. Compare generated-audit-artifact.

    #The pattern across both uses

    In both repos NetworkX ends where the interesting computation begins — in one it hands off to C++, in the other it hands off to human judgement. It is a graph builder in this corpus, never a graph analyser. That is a real observation about how these projects are structured, not a criticism: both uses are one import and a handful of lines, and neither pretends to be more.
