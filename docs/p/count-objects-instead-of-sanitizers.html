    Count Objects Instead of Sanitizers

    Decision. The C++ tests in programming-fundamentals-and-oop-laboratories use an instrumented tracked payload to assert ownership lifetimes in the portable baseline suite. AddressSanitizer and Undefined Behavior Sanitizer remain an opt-in CMake configuration, not a prerequisite for the tests.

    #Make the lifecycle observable

    The tracked header supplies a payload whose construction and destruction update shared counters. A test can reset a tracking_scope, exercise an ownership operation, and assert the expected number of live, constructed, and destroyed objects. The project's small test harness then reports those ordinary assertions through CTest like its other behavioural checks.

    ~~~cpp tracking_scope scope; // exercise an owning_ptr or tree operation CHECK_EQ(tracked::alive, 0u); ~~~

    This keeps the test's observation in standard C++ code. A supported compiler and CMake are enough to run it; the README therefore presents the lifetime assertions as part of the regular C++20 suite.

    #A deliberately bounded signal

    The counters answer a specific question: did this test path create and release the tracked objects according to the ownership contract? They do not diagnose every memory-safety property. They cannot replace runtime instrumentation for untracked allocations, buffer bounds, use-after-free, or undefined behaviour that prevents the process from continuing.

    The helper also records a repeated destructor observation through its marker, but instrumentation does not make undefined behaviour safe. Tests should treat the counters as a direct contract check, not as a general memory debugger.

    #Why sanitizers stay available

    Sanitizers provide a different kind of evidence and are valuable when the selected toolchain supports them. The CMake option FUNDAMENTALS_SANITIZE enables that additional run without making the repository's normal test command depend on a sanitizer runtime.

    The two approaches are complementary: object counts make expected ownership transitions assertable in every regular test run, while sanitizers can inspect a wider set of runtime conditions in an environment configured for them.
