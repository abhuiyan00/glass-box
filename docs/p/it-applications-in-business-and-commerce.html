    IT Applications in Business and Commerce

    #Read this first — the course title is misleading

    This repository is not business analytics. There is no e-commerce model, CRM, ERP, supply-chain simulation, payment system, market-basket analysis, RFM segmentation, forecasting model or KPI dashboard anywhere in the code. A reader arriving from the course title will expect the opposite of what is here.

    What is actually in the tree is two unrelated deliverables:

    Unit What it is Stack
    project/ — AI Racera proximal-policy-optimisation agent driving in TORCS over the torcs-scr-protocol, for the IBM AI Racing LeaguePython + pytorch
    lecture/exam_prep/ — IT Apps Knowledge Testa zero-build single-page quiz app, 497 questions across 28 setsvanilla HTML/CSS/JS

    Business-systems material — SOA, BPEL, BPMN, WSDL, SOAP, REST/microservices, virtualization, PKI, proof-of-work — appears only as quiz content in chapters.js. Not one line of code in this repo implements a business system. Tagging the AI-Racer material business-systems would misfile the whole repo, so none of these pages carry that tag.

    Status: coursework, finished and frozen at last commit 2026-07-25. "All finished and frozen" (interview, 2026-07-28). Nothing here is maintained.

    #The git history is a publication record, not a development record

    11 commits, ~100 tracked files, ~9.8k lines of Python and JS, ~25 MB of committed binaries. Eight of the eleven commits land inside six seconds on 2026-07-10T20:46, importing a complete, documented, screenshot-illustrated tree. A second micro-burst on 2026-07-25 changes 36 lines total and touches no code. This is the cleanest instance of import-finished-work-into-git in the corpus, with the polish tail of presentation-polish-tail-commits — with one inversion worth recording: licence work is commit #1 here, not the last act.

    The real development history lives in a different repository. Szymon1905/AI_racer_pytorch, six named authors, branch tips dated 2026-04-19 → 2026-06-17. None of that history is in this git. Commit messages here are uniformly publication-facing ("Add the top-level guide…", "Remove decorative emoji…"); none describes a bug, an experiment or a decision — the exact opposite of the messages quoted inside the branch reports.

    project/docs/branch-reports/ — 11 markdown files, 846 lines — is a mechanical branch-by-branch audit of that other repository, with tip SHAs, constants tables, reward pseudocode and a lineage graph. See generated-audit-artifact and branch-per-experiment. Its generator was never committed, so unlike the sibling instances of that pattern the audit cannot be re-run.

    #Team attribution and the identifiers this wiki omits

    project/README.md carries a per-member contribution table. Public per-member attribution was a competition requirement:

    "Intentional — team credit was required."

    interview, 2026-07-28

    The table pairs full names with institutional student identifiers. This wiki deliberately omits both the names and the identifiers and reproduces no part of that table. The requirement is recorded here as context; the personal data is not.

    The blanket publish: false on this repo's pages was lifted on 2026-07-30. The omission was never enforced by that flag and does not depend on it — the names and identifiers are not in these files at all, so there is nothing for a publish flag to hold back. Re-checked on 2026-07-30 against person-like values across every page resting on this repo; audit-secrets re-checks the published subset on every build. What goes public is the engineering: the torcs-scr-protocol client, the generated question bank, the branch strategy.

    #Headline performance claims have no artefact

    The README's 1:31.53 lap at ≈245 km/h, and "8 of 10 runs (≈80 %), mean ≈1:33", rest on prose alone. There is no eval log, no TORCS results file, no video and no plot data in the repo. The nine committed CSVs come from the other branch and carry no lap-time column; the lap-time figure is a PNG, not data.

    #guide.txt — a documentation-drift showcase

    Four distinct failures in one file, all instances of documentation-drift:

    1. The banner stamps the focus track as corkscrew while §0, §3.1, §3.5 and G8 still target alpine-1 and save to lines/alpine-1.npz.
    2. §8 lists gym_torcs/recon_lap.py, and gotchas G4/G5 plus validation V4 depend on it — the file does not exist.
    3. §1 describes the pre-rewrite baseline (steer-only, gear hardcoded to 1, 23-dim state) as "What exists today", contradicting the shipped three-dimensional-action racing-line environment.
    4. §7 proposes a speed-cap curriculum that nothing in train_torcs_rl.py implements.

    Seven further drift instances exist elsewhere — a stale copy-pasted commands.txt, a report claiming 12 log files where 9 exist, eval_torcs.py for eval_torcs_rl.py, Obsidian wikilinks that render as literal brackets on GitHub, and a top-level README that softens a failure the branch's own README states flatly.

    The last commit in the repo exists solely to remove a pointer to agent tooling. As committed on 2026-07-10, guide.txt opened with:

    "architecture in this repo. Read CLAUDE.md first for the project map; this file"

    IT Applications in Business and Commerce/project/code/a.bhuiyan/guide.txt, 2026-07-10

    439a690 (2026-07-25T02:04) rewrites that line to point at the README instead. No CLAUDE.md, .claude/ or AGENTS.md exists in the tree or in history. Agent tooling was present in the working copy and deliberately excluded from publication — the repo's final act was scrubbing its last trace. This contradicts agent-skills-checked-into-the-repo.

    #The exam-prep app, and where the lineage starts

    lecture/exam_prep/ is the origin of the four-repo exam-prep lineage:

    "One was first and I copied it forward."

    interview, 2026-07-28

    The user names this repo as the first. One caveat is recorded rather than dropped: the earliest in-repo mtime evidence points at Physics/exam_prep/ instead (2026-06-27→06-30), and this app has no comparable in-repo timestamp because its development history lives in the other repository. See course-as-runnable-study-tool, zero-dependency-no-build-step and offline-first-static-deliverable.

    The app itself is the strongest engineering in the repo: all scores derived from the answered set rather than kept in desyncable counters, STORAGE_VERSION = 7 invalidation, and qa_test.js — a hand-rolled node:vm + DOM-shim harness that loads the production app.js, drives real event handlers and exits non-zero on failure. It is the only automated test in the repo; _smoke.py prints and never asserts.

    Content provenance, stated because no README states it. The 20 study sets are a synthetic bank — disclosed only in a code comment in _build_bank.js, never in any README, while the root README says the app "turns the whole syllabus into an interactive quiz". The 8 "Testownik" sets are real past-exam questions whose primary source (uploads/Quiz_Question_Bank.md) is absent from the repo.

    • TODO: the copyright status of the Testownik question source is unestablished and the primary files are missing, so their answer-key verification is unauditable. No quiz item is reproduced in this wiki, and none should be. confidence: low on any provenance claim for that bank.

    The training CSVs are clean by contrast: 9 files, 330 rows, machine-written by this repo's own code against a simulator on 2026-06-04/05. No personal or commercial data. provenance-and-limits-stated-inline is unusually well done here — .gitignore explains why the ~1 GB TORCS simulator is excluded, NOTICE attributes the upstream work, the README has an explicit "Not included:" callout, and a.bhuiyan/README.md lists five failures by track coordinate.
