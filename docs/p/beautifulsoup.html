    BeautifulSoup

    HTML/XML parsing library, used in labs 10 and 11 of python-programming-laboratories for scraping and for a document pipeline that extracts 41 chapters of text.

    #Defensive scraping, because the target moved

    The lab README records the situation plainly: "The faculty site has been restructured since the exercise was set." The scraper was written to survive that rather than to match one snapshot — the parsing is tolerant of structure it does not recognise instead of indexing blindly into a fixed tree.

    Paired with requests, the network side is equally defensive: a timeout= on every request, and raise_for_status() before anything is written to disk, so a 404 error page is never saved as if it were the content. Both are the kind of guard that only gets written after it has bitten someone — see document-the-failure-mode-next-to-the-fix.

    The REST client in the same lab accepts both a bare list and a {"data": …} envelope, because tolerating two response shapes is cheaper than pinning an API you do not control.

    #The 4.13 API removal

    "Two library APIs moved. Image.ANTIALIAS and ImageDraw.textsize were removed in Pillow 10; findAll(text=True) was removed in BeautifulSoup 4.13."

    Python-Programming-Laboratories/labs/11_report_pipeline/README.md, 2026-07-25

    findAll(text=True) was the long-deprecated camelCase alias with the old keyword; the modern form is find_all(string=True). The port is one line and the diagnosis is the expensive part, which is why it is written down beside the code rather than left in a commit message — none of these commits exist, see import-finished-work-into-git. The pillow half of the same note is recorded there.

    #Namespace hazard nearby

    labs/04_classes/requests.py shadows the requests package that this lab and lab 11 import, if that directory ever ends up on sys.path. confidence: high — see python-programming-laboratories.
