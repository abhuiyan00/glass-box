    Census That Names Its Own Gaps

    When enumerating a large collection — subjects in an archive, tables in a warehouse, endpoints in an API — the failure that matters is not a wrong entry. It is a missing one, and a missing entry is invisible by definition.

    The pattern: pair the enumeration with a hand-maintained disposition map, and make the tool print by name every item with no disposition.

    missing = [key for key, _ in rows if key not in COVERAGE]
if missing:
    print(f"\n{len(missing)} entries without a disposition:")
    for key in missing:
        print(f"  {key}")

    A clean run is now evidence. Not because the author remembered everything, but because anything forgotten is printed.

    #Why a README sentence is not the same thing

    "All subjects have been reviewed" is unfalsifiable and drifts silently the moment a new folder appears. The census re-runs, finds the new folder, finds no entry for it, and says so — which turns documentation-drift from something you notice eventually into something the next run reports.

    Same instinct as verify-the-load-dont-declare-it and generated-audit-artifact: don't assert the property, compute it, and let the computation fail loudly.

    #What it caught here

    The first run reported 17 entries without a disposition. Seven were empty subject folders whose names implied material that does not exist; two were film-subtitle archives; one was a folder whose name is a soft hyphen. None of them was knowingly skipped and none would have been noticed by rereading the index.

    The deeper catch was structural. An earlier census walked subdirectories to enumerate subjects, which is the obvious approach and is wrong for this archive: one semester has no subject folders at all and 116 files sit loose at its root. Counting loose files at every root moved the total from 16,066 files to 54,034.

    Both numbers were produced honestly. The first excluded what it could not classify and did not say so, and that is the failure mode this pattern exists to make impossible.

    #The two-number rule

    A related habit, from the same repository's archive-integrity check: when a check can be read two ways, report both numbers separately rather than one reassuring one.

    files newer than the freeze : 94
of which are content        : 0

    Ninety-four files did change. None of them was content — all were .git and .gradle metadata touched by inspection tooling. Collapsing that into "the archive is unmodified" would have been false; collapsing it into "94 files changed" would have been alarming and useless. The script fails only on the second number and prints both — provenance-and-limits-stated-inline.

    #When to reach for it

    Any time a claim of completeness is going to be made about a set that someone else will trust, and especially when items are added to that set by a process outside your control. The disposition map is the cost; it is small, and it is the only part that a reviewer needs to read.

    #Where this appears

    pwr-subject-notes, covering an eight-semester coursework archive. The same shape, applied to source repositories rather than to subjects, is what verify-sources does for this wiki: it skips directories it cannot verify and reports them, because a stray directory passing the gate silently would make "all source trees clean" mean less than it says.
