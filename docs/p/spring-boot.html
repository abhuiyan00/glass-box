    Spring Boot

    3.5.6 on Java 21, via spring-boot-starter-parent. Three separate backends in Information-Systems-Modelling — labs 2, 3 and 4 — each a forward copy of the last, all sharing the package pl.edu.pwr.tkubik.ism and the same artifactId. It is the only Java web framework in the source set.

    #Which Spring features carry weight

    • Generated controllers. openapi-generator-maven-plugin 7.20.0 emits the API interfaces from the OpenAPI document with interfaceOnly + delegatePattern; the hand-written controllers implement them. See contract-first-api-design and maven.
    • AOP as the extension point. Because the controllers implement generated interfaces, lab 4 puts logging, timing, audit and usage counting into aspects rather than into the controllers — see aspect-oriented-programming.
    • RFC 9457 ProblemDetail. A @RestControllerAdvice converts unhandled exceptions into structured error bodies specifically so stack traces do not reach clients.
    • Profiles. application.properties (dev) and application-prod.properties (prod) differ in more than credentials: the H2 console is disabled in prod, upload limits are tightened, and a fully commented-out PostgreSQL/HikariCP/Flyway block sits in the prod file as a migration sketch.
    • Actuator, dev seed data and file uploads round out lab 4.

    Security is deliberately not a starter. No spring-boot-starter-security, no SecurityFilterChain; lab 4's authentication is a hand-rolled Spring MVC interceptor over jjwt with BCrypt borrowed from spring-security-crypto. See bcrypt-crypto-only-no-spring-security and stateless-jwt-authentication.

    #Two documented contradictions

    1. The root README says lab 4 returns RFC-7807 ProblemDetail; GlobalExceptionHandler's own javadoc says RFC 9457, which obsoletes 7807. The code is right.
    2. The root README caps uploads at "20 MB/file and 50 files/build" — true in dev, but application-prod.properties tightens to 10 MB / 30 MB, below MediaController's own constants, and the README never mentions prod.

    Both are documentation-drift.

    #What is not proven

    Three of the five Java test files assert only contextLoads(). Nothing tests a service implementation, an aspect, the exception handler, the upload limits or the JWT path beyond one end-to-end MockMvc flow. Spring Boot's testing support is present and essentially unused.

    • TODO: no deployment, no CI, no container image, no Dockerfile anywhere. The prod profile exists but there is no evidence it was ever run. confidence: low on any production claim.
