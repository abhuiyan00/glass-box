    PyTorch

    torch==2.11.0. The only machine-learning dependency in the entire source set, and it appears in exactly one repository: IT Applications in Business and Commerce, where it trains the PPO race driver described in proximal-policy-optimisation and residual-reinforcement-learning.

    Everything else in the corpus that touches numerics uses numpy, and there is no TensorFlow, JAX, scikit-learn, Stable-Baselines3 or Gymnasium anywhere. The PPO implementation is hand-written on top of raw torch.nn — no RL library was used.

    #What is actually built with it

    Both agent trees define an ActorCriticNet(nn.Module):

    • two 256-unit Tanh MLP trunks — separate self.actor and self.critic, not a shared backbone
    • linear policy_head and value_head on top
    • a learned log_std as an nn.Parameter, initialised to -1.2, feeding a torch.distributions.Normal
    • policy_head weights and bias zero-initialised, then the throttle bias nudged to +0.5 so the car moves at step zero instead of learning to press the accelerator from scratch

    That last detail is the kind of thing a library hides. Here it is three lines of nn.init and a with torch.no_grad() block, which is the argument for writing it by hand at all.

    The training loop uses the clipped surrogate objective, GAE advantages, an entropy bonus (entropy_coef=3e-3) and target-KL early stopping (target_kl=0.03) — the whole update is plain tensor code, no torch.compile, no AMP, no distributed anything.

    #Checkpoints and a real migration problem

    Six .pt checkpoints (~0.9 MB each) are committed. rl_agent.py carries a shape-tolerant loader that maps an older backbone.* state dict onto the current split actor/critic trunks — evidence that the architecture changed mid-project and old runs had to keep loading. It is the only piece of version-migration code in the repo.

    #Dependency hygiene

    Both requirements.txt files pin torch plus its entire transitive tree — filelock, fsspec, Jinja2, MarkupSafe, mpmath, networkx, sympy, typing_extensions, numpy — with identical versions and differing only in the header comment. That is the signature of pip freeze, not of a curated manifest. There is no pyproject.toml, no lockfile and no CI.

    ⚠ The a.bhuiyan/requirements.txt header comments matplotlib as "optional — only needed to plot the generated racing line", but matplotlib is not in the list, while racing_line.py imports it for that plot. See documentation-drift.

    • TODO: whether pinning torch==2.11.0 was a reproducibility decision or an accident of the virtualenv is unrecorded and the interview did not cover it. confidence: low on any intent.

    #No GPU story

    Nothing in the repo records a device, a CUDA version or a training wall-clock. Networks are two 256-unit MLPs, so CPU training is entirely plausible, but the repo does not say — and the throughput claims that do exist belong to the parallel branch, which ships no code here. See branch-per-experiment.
