    In short

    Two formulas are equivalent when they take the same value under every valuation

    Equisatisfiable Not Equivalent

    Two formulas are equivalent when they take the same value under every valuation. They are equisatisfiable when one is satisfiable exactly if the other is. The second is strictly weaker, and buying it instead of the first is what makes several standard constructions affordable.

    #Why anyone would settle for less

    Converting a formula to conjunctive normal form by distributing | over & produces an equivalent formula and can be exponentially larger. The witness is exact rather than hypothetical: (a₁ & b₁) | … | (aₙ & bₙ) has precisely 2ⁿ clauses, one per way of choosing a side from each disjunct.

    The Tseitin encoding gives up equivalence to escape that. Name every compound subformula with a fresh variable, add clauses forcing the variable to equal the subformula, and assert the top one. The result cannot be equivalent — it contains variables the original did not — but it is satisfiable exactly when the original is, and any model of it restricted to the original variables is a model of the original. Its size is linear in the input: under sixty clauses where distribution gives 256.

    That is why a SAT solver's input is never the user's formula.

    #The same trade one level up

    Skolemisation does it for quantifiers. Replacing ∃y by a fresh function symbol applied to the universally quantified variables in scope removes the existentials, and the result asserts that a specific witness exists rather than that some witness does. The signature changed, so equivalence is off the table; satisfiability is preserved, and refutation only ever needed that. Every first-order resolution prover begins here.

    #Why the distinction has to be stated

    Both constructions are usually introduced as "converting to CNF" and "removing existentials", phrasings that imply equivalence. A comment claiming equivalence where the construction gives equisatisfiability is a bug in the documentation, and it is the kind that survives review because the code is correct. In logic-for-computer-scientists the two properties are tested differently on purpose: the CNF conversion is checked for equivalence by enumeration, and the Tseitin encoding is checked only for preserved satisfiability plus the restriction property — which is all it claims.

    The general habit is counted-complexity-assertions applied to a semantic property rather than a cost: state the weaker claim, and test exactly the weaker claim.
