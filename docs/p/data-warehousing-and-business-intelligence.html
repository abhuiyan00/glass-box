    Data Warehousing and Business Intelligence

    Coursework plus a course project for the Data Warehousing and Business Intelligence module at Wrocław University of Science and Technology. 73 tracked files (measured 2026-08-05): seven annotated .sql scripts, three SSIS packages (.dtsx), three SSAS multidimensional projects (.dwproj) holding four cubes, six assignment PDFs, and one Python reference script. The repo builds two independent Kimball stars — see star-schema.

    An earlier version of this line read "57 tracked files … two SSIS packages, three SSAS multidimensional projects". Two of those three numbers have since changed and the third was wrong when written: there were two .dwproj projects and three cubes, and the sentence counted cubes while saying projects. Both units are now named, because "three SSAS things" is not a fact.

    T-SQL on SQL Server 2019 (sql-server) · ssis for flat-file landing · ssas multidimensional for the cubes · Visual Studio 17.5 / SSDT · one Python-over-sqlite reference implementation.

    Both marts state their grain in prose and enforce it with the primary key — fact-grain. The surrogate/natural contrast between the two is the whole of surrogate-vs-natural-keys. DIM_PRODUCT collapses the source Product → Subcategory → Category snowflake into one denormalised dimension, the opposite move from third-normal-form.

    #ETL

    Mart A loads dimensions before the fact, and builds DIM_TIME from the source header table rather than from the fact — the header comment writes out the deadlock the alternative causes. That reasoning is etl-load-order. The load ends with a row-count roll-call and two anti-join referential-integrity checks: verify-the-load-dont-declare-it.

    Mart B lands a CSV through an ssis flat-file→OLE DB data flow into a staging.quotes table carrying two CHECK constraints at the door, then loads the star, then backfills relative-strength-index with a four-CTE UPDATE ... FROM built on window-function-frames. project/twtr/rsi_reference.py re-expresses the same indicator in Python over sqlite — reference-implementation-as-specification.

    #Findings

    • The rejected design is still shipped. docs/star-schema.md argues at length that an indicator must be a measure, not a dimension — and project/twtr/ssas/Dim RSI.dim implements RSI as a dimension, with RSIKey, IsOverbought, IsOversold. The SQL side ships the winner; the SSAS side ships the loser. See rsi-as-measure-not-dimension, measure-vs-dimension and keep-the-superseded-version-in-tree.
    • There is no slowly-changing-dimension handling anywhere. No EffectiveFrom/EffectiveTo, no IsCurrent, no Type-2 rows. Every load is truncate-and-rebuild, with DROP TABLE IF EXISTS at the top of the DDL. DIM_TICKER.ListedOn/DelistedOn is the closest thing present and is a single hard-coded row. Stated as an absence, not implied as a feature.
    • Nothing here was executed and committed. Every row count and RI check is a query needing a live SQL Server with AdventureWorks2019 and AdventureWorksDW2019 attached. No output, log, or expected-count file is in the tree; "0 orphans" is a query, not a recorded result. Only rsi_reference.py runs standalone. No test suite, no CI, no Makefile.
    • Documentation drift, four instances. The two TWTR data source views bind FactTwitterData, DimDate, FactRSI and DimRSI — none created by any committed DDL, which builds dw.FACT_QUOTES/DIM_DATE/DIM_TICKER. The SSIS list_four schema disagrees with mart on column set and defaults. olap/ssas/DIM TIME.dim exposes only DateKey/Day/Month/Year while the DDL defines Quarter, MonthName and IsWeekend too. See documentation-drift.
    • The as-submitted coursework is kept beside the corrected version. docs/lab-1-notes.txt and lab-2-notes.txt hold the original SQL, bugs included; sql/01_analytics/ rewrites each query with a comment naming what was wrong — keep-the-superseded-version-in-tree.
    • Numbering marks run order, not chapters: sql/01_analytics/, sql/02_star_schema/, 01_create…/02_load…, 01_staging/02_star_schema/03_technical_indicators. See numbered-stages-in-directory-names.
    • Every modelling choice states its cost in comments — "a day's RSI takes two joins", Wilder's exponential smoothing named as the variant not implemented, the cubes flagged as "Visual Studio project files rather than deployed databases". provenance-and-limits-stated-inline.
    • The first 7 commits, all on 2026-07-25 inside a four-second span, ordered as a curated build-up with the README, LICENSE and assets last. import-finished-work-into-git · presentation-polish-tail-commits · readme-as-guided-tour. Per the interview these bursts were "just cleaning up local folders" — consolidation, not a release. The 8th, on 2026-08-01, is the only one that adds material rather than arranging it.
    • No .gitattributes and no Git LFS: two PNGs, six PDFs and the SSAS .dim/.cube/.partitions files are committed as plain unmanaged blobs.
