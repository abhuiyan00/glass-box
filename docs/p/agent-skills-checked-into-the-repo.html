    Agent Skills Checked Into the Repo

    The tooling that builds the product is committed alongside the product, versioned with it and reviewed like it. In stickfps that is 91 files under .tooling/ — more files than the server source directory.

    Two different things live there, and the distinction matters:

    Vendored (87 files). Nineteen Three.js skill packs, each a SKILL.md plus references/{methods,examples,anti-patterns}.md. Third-party, with provenance in frontmatter — license: MIT, metadata.author: OpenAEC-Foundation. Taxonomy is five prefixes: core- (math, raycaster, renderer, scene-graph), syntax- (geometries, materials, shaders, controls), impl- (react-three-fiber, drei, lighting, shadows, animation, audio, post-processing), errors- (performance, rendering), agents- (scene-builder, model-optimizer). The content is reference tables and NEVER/ALWAYS rules aimed squarely at model failure modes rather than at human learning:

    "Designed for AI coding agents."

    browser_game_stickfps/.tooling/skills/ (SKILL.md frontmatter), 2026-07-25

    Authored (4 files). Three subagent definitions and one orchestration command — see architect-coder-tester-loop, which is where the role separation is documented.

    #Why commit it

    Committing the tooling makes the build process reproducible in the same sense the code is: a later session, or another person, starts from the same instructions rather than from whatever the model happens to know. It also makes the instructions reviewable — a wrong rule in a skill pack is a diff, not an invisible habit.

    The seed directory files/ extends the same idea backwards: pristine copies of TASKS.md, an empty PROGRESS.md skeleton and the four agent files, all stamped 2026-07-14, kept in the repo as a bootstrap kit. TODO: whether files/ is a deliberate reusable kit for future projects or leftover scaffolding was not resolved at interview — no intent is asserted here.

    #The cost: vendored knowledge drifts too

    Skill packs are pinned text about a moving dependency, and nothing checks them against the lockfile. The R3F pack states a version floor the project has already passed:

    "Requires @react-three/fiber 8.x+"

    browser_game_stickfps/.tooling/skills/impl-react-three-fiber/SKILL.md, 2026-07-25

    More seriously, all four authored files still instruct agents to use Geckos.io and Fly.io, months after both were replaced in websocket-tcp-over-geckos-udp and render-over-fly-io. Guidance that is confidently wrong is worse than absent guidance, because the loop reads it as authoritative. Catalogued with the rest in documentation-drift.

    #Confidence

    confidence: medium — the artefacts are directly observed and unambiguous, but this appears in one repository only so far, which is thin evidence for a pattern in the user's practice rather than a one-off.
