    pnpm

    Content-addressed package manager whose defining property is that it does not flatten node_modules. In farely that non-hoisting behaviour is not a preference — it is the reason the Android build finds its dependency. See pnpm-over-npm-for-capacitor-gradle-path for the decision.

    #What the repo declares

    pnpm-workspace.yaml:

    • packages: apps/*
    • minimumReleaseAge: 10080 — refuse any package version published less than 7 days ago
    • supportedArchitectures: linux/x64 + arm64/glibc

    Plus a pnpm overrides entry pinning Vite to 6.3.5, and every dependency exact-pinned across both workspace packages — no ^, no ~, anywhere.

    minimumReleaseAge is a supply-chain control: it blackholes the window in which a compromised release does most of its damage, at the cost of never being on the newest patch. Combined with exact pins and an architecture allowlist, this is the most security-conscious dependency configuration in the source set.

    #The contradiction

    The repo declares a pnpm workspace, CONTRIBUTING and README both instruct pnpm install, and the gradle path argument depends on pnpm's layout. But:

    • the only committed lockfile is package-lock.json — there is no pnpm-lock.yaml in the tree;
    • package.json also declares npm workspaces: ["apps/*"];
    • every root script is npm --prefix … — dev, build, sync, apk, cap:open.

    So the documented package manager and the committed one disagree, and the committed one is the manager whose hoisting the docs warn about. Anyone following the README gets a lockfile the repo does not track; anyone running the scripts gets npm. Recorded as a finding, not resolved — an instance of documentation-drift in the build layer rather than the prose layer.

    #Consequence for the APK

    Under npm's hoisting, @capacitor/android may land at the root rather than under apps/android/node_modules, where the gradle project's relative ../node_modules reference expects it. The failure surfaces at gradlew assembleDebug, far from its cause. Since the APK was never validated on a live shift, this path has been exercised on exactly one machine — the debug build did succeed there.
