    ws (WebSocket Server)

    The Node WebSocket implementation, ^8.21.1. In stickfps it is the entire transport, serving /ws on the same express ^5.2.1 server that answers /healthz. It replaced geckos.io (UDP-over-WebRTC) in the final build round — websocket-tcp-over-geckos-udp.

    #The wire format

    Compact JSON frames shaped { e: event, d: data } — event name plus payload, nothing else. Frames are small by construction because the client only ever sends intent under server-authoritative-netcode, and the server's per-tick broadcast is a batched position snapshot rather than one message per entity.

    #Connection handling worth copying

    • Origin check in verifyClient, against CORS_ORIGIN, before the upgrade completes. Cheaper than authenticating after the socket is open, and it is the reason stickfps keeps express and cors for a service with one HTTP route.
    • 64 KB maximum payload. A hard ceiling on any single frame limits the cheapest denial-of-service shape without any rate-limiting logic. (Per-connection rate limiting is still absent and is listed as a known gap.)
    • The server issues the identity. Each connection gets a fresh crypto.randomUUID() delivered in a connection-ready frame, and the client's connectToServer promise resolves only once that id arrives. Anything the client believed about who it was before connecting is irrelevant — which is why supabase's anonymous id is not the player id.
    • Reconnect with capped jittered exponential backoff, 500 ms → 8 s. Jitter matters: without it every client dropped by one server restart returns in the same instant.

    #The abstraction that made the swap cheap

    Rather than rewrite gameplay code against ws, the build introduced NetChannel / NetServer — an interface shaped to mirror only the slice of the geckos.io API the code actually used. No gameplay code changed when the transport was replaced.

    The transferable point is the sizing rule: the wrapper was written to the observed usage, not to the vendor's full surface, and not speculatively in advance. A transport interface designed up front to cover everything either transport might do would have been larger and would still have leaked.

    #TCP, knowingly

    WebSocket is TCP, so a lost packet blocks everything behind it — head-of-line blocking that UDP would not have. Accepted explicitly and called "unnoticeable at hobby scale". Under this transport, entity-interpolation's 100 ms buffer is doing more work than it would over UDP.
