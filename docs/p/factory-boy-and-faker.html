    factory_boy and Faker

    Faker generates plausible fake values — names, dates, text. factory_boy wraps that in declarative factories that build whole model instances, so a test asks for an object instead of writing out every field.

    Used in lab 09 of python-programming-laboratories to generate fixtures for a CSV reporting exercise over a 10,360-row dataset.

    #The discipline that makes them safe

    Generated fixtures are a trap if the generator decides the value under test. The lab's rule:

    Factories fill the irrelevant fields; each test sets the field under test explicitly.

    The concrete motivating bug is the "no"-is-truthy trap — a string field whose value is "no" evaluates true, so a test whose fixture happened to populate it can pass against a filter that does nothing. Full treatment on tests-that-pass-for-the-wrong-reason.

    Stated positively: a fixture makes the setup cheap; it must never make the assertion implicit.

    tests/test_lab09_insults.py does:

    import factory
... factory.Faker(...)

    and pyproject.toml's dev extra listed only pytest and pytest-cov. factory_boy and Faker appeared in the README's Technology section and in the test imports, and in no dependency declaration.

    Consequence: the README's own quick start — pip install -e ".[labs,dev]" then pytest — failed at collection in a clean virtualenv, because pytest imports every test module before running anything. It worked only on a machine where the packages were installed for some other reason. confidence: high; both files read directly.

    This was the sharpest instance of documentation-drift in the repo: the documentation and the code each internally consistent and mutually incompatible, with no CI to catch it.

    #What the fix found that the finding did not

    Declaring the two named packages was not sufficient, and that is the part worth keeping. The same test imports labs/09_dataset_reports/insults.py, which reaches click at module scope — so collection still died on a clean install with factory-boy and faker present. click was already declared, but in the labs extra, for running the exercise. The test path needed it too:

    Python-Programming-Laboratories, git commit 385d0fd "Declare the test dependencies a clean install was missing", 2026-08-01

    The general shape: an import-time dependency of a module a test imports is a test dependency, no matter which extra it logically belongs to. Reading the failing import gives you the first name; only running the clean install gives you the rest. The commit records reproducing in an empty virtualenv before and after, which is the only evidence that settles it — a declaration you cannot install into a clean environment is a guess.

    Measured after the fix: 89 tests collected, 88 passed and 1 skipped on a clean [dev] install, the skip being pytest.importorskip("openpyxl"), which belongs to labs on purpose.
