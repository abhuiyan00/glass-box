    Extract the Shared Core

    When several deliverables consume the same input, make the shared part a real package with tests and reduce each deliverable to a thin script over it — instead of twelve directories each with its own copy of the parser.

    #The instance

    Nine of twelve labs in python-programming-laboratories read the same Apache access log. Rather than twelve parsers, there is one weblog package — entry, reader, stats, config, cli — installed with pip install -e, exposing a console script, and each lab is a script that imports it.

    "# Only the later laboratories need these; the core package has no dependencies."

    Python-Programming-Laboratories/pyproject.toml, 2026-07-25

    The core declares dependencies = []; every library lives in an optional labs extra. A shared core that drags a dependency tree behind it is not shared, it is imposed. See setuptools-and-pyproject and zero-dependency-no-build-step.

    #What makes the extraction actually work

    • The core has no I/O. stats never prints; config is read in main(). Had the computation rendered its own output, every lab would have needed a fork with different formatting and nothing would have been extractable — separating-computation-from-io.
    • The core is the only tested code. All six pytest files target weblog plus two labs; the thin scripts are not tested because there is nothing in them to test. Concentrating the tests where the logic is concentrated is the direct payoff.
    • The hard problem is solved once. The quoted-field regex in common-log-format-parsing is subtle enough that twelve copies would mean eleven wrong ones.

    #The honest caveat

    The README frames extraction as the design — nine labs share a log, therefore one package. The commit history cannot confirm it: all twelve commits landed on 2026-07-25 in strict layer order, package first, so whether weblog existed from lab 02 or was extracted later once the duplication became obvious is unrecoverable. See import-finished-work-into-git. TODO: unresolved; confidence: low on the chronology, confidence: high on the end state.

    #Contrast

    discrete-mathematics-laboratories does the opposite and is right to: its six labs share no input, so each is self-contained. The pattern applies when the labs share data, not merely a course. farely and optimization-methods apply the same move at product scale — a pure engine shared across hosts, a solver shared across two programs.
