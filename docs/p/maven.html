    Maven

    Four pom.xml files, all in Information-Systems-Modelling — labs 2, 3, 4 and 5. The only Java build tool in the source set; there is no Gradle anywhere. Labs 2–4 ship the Maven wrapper (mvnw 3.3.2, resolving Maven 3.9.10); lab 5 does not, and lab3/README.md tells the reader to run bare mvn clean compile regardless.

    ⚠ The root README's toolbelt table says "Maven 3.9+ | labs 2–5 | or use the bundled wrapper mvnw". Lab 5 has no wrapper, so the promise fails on a quarter of its own scope — documentation-drift.

    #The one interesting plugin chain

    Labs 2–4 do not hand-write their API interfaces. Three plugins cooperate:

    1. openapi-generator-maven-plugin 7.20.0 reads src/main/resources/openapi/openapi.yaml and generates Spring interfaces with interfaceOnly=true + delegatePattern, emitting into target/generated-sources/openapi.
    2. build-helper-maven-plugin adds that directory to the compile source roots so javac sees it. (Present in labs 3 and 4; lab 2 wires the generator without it.)
    3. spring-boot-maven-plugin packages the result.

    This is the machinery behind contract-first-api-design, and it has a second-order consequence worth noting: because the controllers implement generated interfaces, hand-adding cross-cutting code to them is fragile — which is the stated reason lab 4 reaches for aspect-oriented-programming instead.

    The generated tree is also why a naive file count over this repo reports 231 Java files when the tracked source is 134: target/ holds build copies of everything.

    #Dependency management, not just dependencies

    • Labs 2–4 inherit from spring-boot-starter-parent, so Spring, Jackson and JPA versions come from the BOM rather than from pins. See spring-boot.
    • Lab 5 inherits from nothing and imports rdf4j-bom in dependencyManagement for the same effect on the RDF4J side. See rdf4j.
    • Only the genuinely external things are pinned by hand: sqlite-jdbc 3.49.1.0 and hibernate-community-dialects (lab 2), h2 (labs 3–4), jjwt 0.12.6 (lab 4), springdoc 2.8.9 / 2.8.13, jakarta.xml.bind-api 4.0.0.
    • Lab 5 uses exec-maven-plugin 3.1.0 as its run mechanism — no Spring Boot plugin, so mvn exec:java is the entry point.

    #What Maven is not used for here

    No maven-surefire configuration beyond the default, no failsafe, no jacoco, no checkstyle, no shade/assembly, no release plugin, no CI that invokes any of it. The build produces jars and nothing else; the verification story is thin and lives outside JUnit — see information-systems-modelling.

    Three of the seven labs use no build tool at all: labs 6 and 7 and the exam trainer are plain Node with dependencies: {}. Lab 7's README says so in as many words, which is why zero-dependency-no-build-step and Maven coexist in one repository without contradiction — they cover disjoint halves of it.
