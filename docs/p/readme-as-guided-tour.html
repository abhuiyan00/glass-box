    README as Guided Tour

    The README is written for a reader being shown around, not for a user trying to run something. Present in all 15 source repositories. Three of them say it in so many words.

    #The recurring skeleton

    1. Shields.io badges (MIT, "open source · free to use", sometimes stack badges)
    2. A centred hero screenshot or figure with a caption
    3. An explicit "Start here" line
    4. A screenshot table — 2×2, 2×3 or 3-up — each image with a <sub> caption saying what to look at
    5. An "arc at a glance" table walking the parts in order
    6. A fenced repo-layout tree
    7. A ## Technology prose section
    8. A ## Skills demonstrated section
    9. ## License

    #Evidence

    "Start here. This page is the guided tour of all three projects"

    Optimization Methods/README.md, 2026-07-10

    "The armory opens for 8 seconds each round… validated server-side, not trusted from the client"

    browser_game_stickfps/README.md, 2026-07-25

    The captions carry argument, not decoration — the second quote is a screenshot caption that explains server-authoritative-netcode in passing.

    #How far it goes

    • browser_game_stickfps/assets/README.md documents the capture settings for its own screenshots: 1600×900 downscaled to 1440 px, progressive JPEG q90, "chosen over PNG to avoid banding".
    • Python-Programming-Laboratories/assets/README.md states provenance: "Real captures, not mockups."
    • Farley ships three task-scoped guides (DEMO / EMULATOR / ANDROID-INSTALL) plus one-click .bat launchers for each.
    • Information-Systems-Modelling/README.md runs to 385 lines with a per-lab chapter each.
    • IT Applications in Business and Commerce nests four guided-tour READMEs.

    #Where it is absent

    Two repos break the pattern, and they break it the same way — Oracle-Database-Laboratories and Cybersecurity-Engineering-Laboratories both have a walkthrough README but no badges, and both bundle README + LICENSE + .gitignore into a single final commit rather than the separate polish commits described in presentation-polish-tail-commits. Both are also the two most prose-disciplined repos in the set.

    #Reading it critically

    A guided tour is a persuasive form, and in several repos the tour is more confident than the code. IT Applications in Business and Commerce/project/README.md softens a failure its own sub-README states flatly ("did not fully solve the S-curve"). Farley's README claims a test suite that does not exist. The tour is the top of a gradient — see documentation-drift — and the deeper file is usually the more honest one, which is itself an instance of provenance-and-limits-stated-inline.
