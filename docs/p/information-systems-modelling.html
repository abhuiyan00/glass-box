    Information Systems Modelling

    Seven-lab coursework repo (Wrocław University of Science and Technology, course led by T. Kubik) carrying one invented domain through the whole SDLC. The domain — ModellingClub, a hobbyist RC-car / drone / scale-model community platform — is specified in lab 1 and then satisfied, extended and re-modelled in every lab after it. Plus a bonus 570-question exam trainer.

    #It ships real model artefacts — and no UML at all

    A first pass over the file counts suggests the XML here is all IDE metadata and therefore that the repo contains no models. That is wrong on the substance. The tree delivers:

    • 8 .bpmn — BPMN 2.0 collaborations with diagram interchange, plus 8 rendered .svg
    • 5 .ttl, 1 .owl, 1 .rdf, 3 .jsonld — a real TBox/ABox split
    • 4 OpenAPI .yaml contracts

    Of 93 on-disk .xml, 87 are .idea/ but only 27 are tracked; the "231 Java files" figure counted target/ build copies, while tracked source Java is 134.

    The genuine absence is UML. There is no class, sequence, state, use-case or activity diagram in any format — no .uml, .di, .notation, .ecore, .eap, .vpp, .asta, no Mermaid, no hand-drawn tool file — in a course called Information Systems Modelling whose own exam-prep theme table names "UML & SysML diagrams". Modelling here is done in BPMN and RDF/OWL instead.

    • TODO: whether UML diagrams were produced and kept outside the repo, or genuinely never required, is unrecorded. confidence: low on any claim either way — do not assert they exist.

    #Each lab is a forward copy of the last

    lab3 = lab2 + the documentation of auth; lab4 = lab3 + AOP, uploads, validation and the auth lab3 only promised. Same package (pl.edu.pwr.tkubik.ism), same artifactId, same api/ → service/ → repository/ → entity/ split — see layered-architecture and forward-copy-lab-progression. Every superseded ancestor stays in the tree, which makes this a four-way instance of keep-the-superseded-version-in-tree: labs 2 and 3 beside lab 4; a 39-file nested duplicate of the pre-rewrite student-CRUD Angular scaffold sitting inside the real SPA; instances.ttl (557 lines) and cardinalityTest.owl tracked but referenced by nothing; and ontology.ttl existing as byte-identical copies in lab5 and lab6.

    The numbering runs through directories rather than documents — lab1/…lab7/, bpmn/p1-… … p8-…, mirrored by specs.js constants P1…P8. See numbered-stages-in-directory-names; contrast numbered-docs-chapters, which this repo contradicts (there is no docs/ directory).

    #One deletion that happens nowhere else in the corpus

    "refactor(lab6): drop hand-written snapshot pages, generate from the app"

    Information-Systems-Modelling, git commit 98fac45, 2026-07-09

    −1268 / +222, deleting six hand-written HTML pages. This is the only place in the entire 15-repo source set where a superseded version was deleted rather than kept. It is the whole point of generate-markup-instead-of-hand-writing-it, and the exact inverse of keep-the-superseded-version-in-tree — the same author, four ways, in the same repository. Two projects (here, two labs) disagreeing is a finding about the practice, not a bug.

    The same instinct produces single-source-of-truth-generators in labs 6 and 7 and schema-org-first-custom-vocab-fallback in the vocabulary mapping.

    #⚠ Lab 3 documents an authentication system it does not have

    The sharpest finding in this repo, verified directly against source rather than against its prose. Lab 3's OpenAPI contract advertises UC-02: Login – issues HttpOnly JWT session cookie (bcrypt verify) and its README says the same. The code does none of it:

    • pom.xml declares neither jjwt nor spring-security-crypto, and there is no security/ package anywhere in the module
    • UserServiceImpl.register writes request.getPassword() straight into the password column — the password is stored in plaintext
    • AuthController.authLoginPost looks the user up by email and returns the profile without ever comparing the submitted password

    Anyone who knows a registered email address is logged in as that user. Lab 4 is the first module where authentication actually exists — jjwt and BCrypt appear in its pom.xml, and its own choice to use the crypto primitive without the framework around it is recorded on bcrypt-crypto-only-no-spring-security.

    Both claims are kept rather than one overwriting the other, per CLAUDE.md §10: the contract and README state one thing and the code states another, at the same time and in the same commit. This is not a claim that expired — it is documentation-drift in its most consequential form, where the drifting document is a security contract. Recorded on stateless-jwt-authentication and forward-copy-lab-progression; the copy-forward habit is exactly how a stub survived into a module that advertised it as finished.

    confidence: high — four independent code-level confirmations.

    #Tests are thin, and the verification lives elsewhere

    5 Java test files in total. Three are StudentServiceApplicationTests asserting only contextLoads(). Two are BuildsControllerIntegrationTest (lab3, lab4) with exactly one @Test each — an end-to-end register → login → POST /builds MockMvc flow whose real assertion is that the returned id is not Swagger's placeholder UUID.

    Zero tests cover the AOP aspects, JWT service, media upload limits, exception handler, or any service implementation. On the Angular side, .spec.ts files exist only in the dead nested duplicate; the live SPA has one app.spec.ts and no feature tests.

    Real verification lives outside JUnit: lab6/app/scripts/validate.py prints rdflib triple counts, while ism_final_exam_prep/qa_test.js is a node:vm DOM-shim harness for scoring, timer, persistence, and poisoned-save recovery. Because validate.py asserts no count, any data edit can silently invalidate the "333 triples site-wide / 76 for build-falcon.html" claim.

    #.idea/ was committed on purpose

    Two dedicated commits — 6309f7b chore(ide): add IntelliJ project metadata for labs 4 to 6 (17 files, +706) and 0cd382d chore(ide): add IntelliJ project metadata for lab7 — put 21 .idea/*.xml and 4 .iml in the tree. The per-module ignores come from Spring Initializr and JetBrains, so the inner module .idea/ paths are correctly untracked and the outer per-lab ones are not. A root .gitignore now excludes Maven target/, Node node_modules/ and dist/, plus Python __pycache__/ and .venv/ output.

    #Documentation drift — 11 catalogued instances

    Sharpest four (documentation-drift):

    1. lab6/README.md §2's file tree lists snapshot.md — the file does not exist, on disk or in history at HEAD.
    2. The root README says lab4 returns RFC-7807 ProblemDetail; GlobalExceptionHandler.java's own javadoc says RFC 9457, which obsoletes 7807.
    3. The root README caps uploads at "20 MB/file and 50 files/build" — true for dev, but application-prod.properties silently tightens to 10 MB / 30 MB, below MediaController's own constants. The README never mentions prod.
    4. lab4/guide.txt is dated 2026-05-13 — before its own lab's commits — hardcodes a machine-local absolute path unrelated to the repo layout, and is mojibake-corrupted (UTF-8 written, cp1252 re-saved).

    Others: lab6's headline "no fact written twice" principle sits beside the byte-identical cross-lab ontology.ttl; the root README's toolbelt promises an mvnw wrapper that lab5 does not have; dist/ is called the deliverable to inspect but is gitignored and untracked.

    #Publishing shape

    Bursty imports rather than a working log — labs 1–3 land within 10 seconds on 2026-04-14, and Add lab4 and lab5 plus root README is 274 files / 39,273 insertions in one commit (import-finished-work-into-git). The 2026-07-09 burst of 13 commits is the exception: genuinely incremental, and it contains the one real refactor. The tail — README rewrite, six per-lab READMEs with screenshots, MIT licence, licence badges, then a screenshots showcase two weeks later — is textbook presentation-polish-tail-commits and readme-as-guided-tour.

    ism_final_exam_prep/ is one of four instances of course-as-runnable-study-tool.
