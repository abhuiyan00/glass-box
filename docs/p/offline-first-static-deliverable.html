    Offline-First Static Deliverable

    The deliverable must work by double-clicking a file: no server, no install, no network. Seven repositories build this way, and in two of them it is stated as a value rather than a convenience.

    #Evidence

    "Farely runs fully on-device"

    Farley/README.md, 2026-07-24

    " // addAll is atomic; cache individually so one miss doesn't abort install"

    Physics/exam_prep/sw.js, 2026-07-10

    The second quote is the pattern taken seriously: an installable PWA whose service worker caches per-URL because one missing file would otherwise abort the whole offline install. See cache-individually-not-addall.

    #The instances

    • Discrete-Mathematics-Laboratories — lab4_Complexity/part2 and lab6_Neo4j/viewer/ contain zero external URLs; the lab-6 viewer reimplements every Cypher query in JS as "the exact analogue" so the graph can be explored without a database running. See dual-implementation-as-cross-check.
    • Physics — a full installable PWA: manifest.webmanifest, hand-written sw.js, KaTeX vendored locally with 20 font files so no CDN is needed. See vendor-katex-instead-of-cdn.
    • labour-fraud-analysis — a deliberate second entry point: serve.py is 60 lines of stdlib http.server, and interactive/vendor/ commits all six third-party JS libraries so there is no npm.
    • privacy-policy — one self-contained index.html, inline <style>, prefers-color-scheme light and dark, no assets, no JS. See self-contained-single-file-html.
    • Information-Systems-Modelling/lab6/app/ — server-side rendering over node:http with "dependencies": {}.

    #Why: file:// is a real constraint that bites

    This is not aesthetic. Discrete-Mathematics-Laboratories learned it the hard way:

    "It used to be loaded through the Babel CDN with type=\"text/babel\", so opening it directly (file://) left a blank page — the browser blocks Babel from fetching the local .jsx, and there was no internet fallback."

    Discrete-Mathematics-Laboratories/lab5_GraphTheory/README.md, 2026-07-10

    The fix was to vendor React's production UMD build and commit the precompiled JSX — 2,692 inserted lines in one commit. See vendor-react-over-babel-cdn.

    #The tension worth recording

    Farley demonstrates that "offline-first" can be a value the documentation strengthens while the code stays the same. The 2026-07-24 README rewrite demoted its cloud vision path from "the one owner-chosen exception I switched on" to "ships off by default" — making the claim less accurate, not more, since map tiles and a car-spec lookup are unconditional outbound requests. The value is real — classifyScreen genuinely falls back to on-device heuristics with no API key — but the headline overstates it. Covered on on-device-first-inference and opt-in-cloud-fallback.

    #Where it is contradicted

    Discrete-Mathematics-Laboratories' Q-HYDRO app sits beside two offline apps and loads Leaflet, map tiles and fonts from CDNs, saying so plainly. Optimization Methods does the same for its route explorer. Neither hides it; both are documented as graceful-degradation cases. The pattern is a strong default, not a rule — as with zero-dependency-no-build-step.
