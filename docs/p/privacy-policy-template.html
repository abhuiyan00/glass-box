    Privacy Policy Template

    Six files, ~25 KB. One document in two hand-maintained renderings: PRIVACY_POLICY.md (the canonical text, 15 sections, 186 lines) and index.html (a self-contained responsive page, 214 lines, inline <style>, light/dark via prefers-color-scheme, zero external requests). No build step, no generator, no framework, no JavaScript. See self-contained-single-file-html.

    Status: active and shipped. "A template, and Pages is live" (interview, 2026-07-28). It is a reusable policy template published at the project's GitHub Pages URL — one-reusable-policy-not-per-project and host-on-github-pages.

    Evidence gap, recorded honestly: the repo contains no CNAME, no Pages workflow and no deployment artefact of any kind. The README's "(done)" refers to the push, not to Pages being enabled. The live-URL claim rests on the interview alone; confidence: high on the claim because the user confirmed it, with nothing in the tree corroborating it.

    #What it covers — and what it does not

    Chronology rules out both products. privacy-policy was created 2026-02-28 and its full policy text landed 2026-07-10. farely's first commit is 2026-07-12; stickfps's is 2026-07-24. The policy predates them by roughly 4.5 and 5 months, so it covers neither.

    The content confirms it independently. The policy's subject is a website: it discloses only GitHub Pages server logs plus inbound email, states "None set by this Service by default" for cookies, and names no other third-party processor. Farely is an Android app with an accessibility service, on-device inference, an optional cloud-vision path and a third-party events feed — and it carries its own privacy documentation, which never links here. Stickfps has accounts and a database; the policy discloses neither. Two independent lines of evidence agree, so this is confidence: high.

    #The legal content, as concepts

    data-minimisation — named and applied in §4, and the load-bearing principle of the whole document · gdpr-legal-bases — Art. 6 bases mapped per processing purpose in §5 · controller-vs-processor — defined in §3 and applied to the host in §7.

    Also present, not given their own pages: the CCPA/CPRA no-sale/no-share attestation with a 12-month lookback (§8), data-subject rights with response windows of 30 days GDPR / 45 days CCPA (§9), the Polish supervisory authority named by name (UODO), international transfers via Standard Contractual Clauses (§10), retention limits (§11), a children's-privacy floor of 13 — or 16 in parts of the EU (§13), an LGPD/PIPEDA catch-all (§9.3), and an annual-review commitment (§14).

    #Findings

    • The only genuinely long-running history in the group. 8 commits over 2026-02-28 → 2026-07-25, in three phases with a ~4.5-month dead gap: three commits in three minutes in February whose wording and rename-in-place pattern are characteristic of GitHub web-UI edits (a placeholder repo created in the browser); four commits in about one second on 2026-07-10 replacing the placeholder with the real policy, the HTML rendering, the licence and the expanded README; and one lone screenshot commit on 2026-07-25.
    • The 2026-07-10 burst is 24 minutes before the identical licence/badge pair in physics-exam-prep and computer-project-management — one consolidation session across three repos, not a product launch. Per the interview these dates are "just cleaning up local folders"; see import-finished-work-into-git.
    • Two renderings, maintained by hand, with nothing preventing drift. No generator turns the markdown into the HTML. They agree structurally today; nothing enforces that they will. Compare documentation-drift, which is what happens when this arrangement is left alone.
    • The README is a product tour, not a code README — badges, a light/dark preview table, "What's inside", publishing steps, a reuse checklist, licence, disclaimer. readme-as-guided-tour.
    • The disclaimer is inline, not a footnote. "It is not legal advice" appears in both the README and the closing line of the policy itself — provenance-and-limits-stated-inline.

    #Security note

    The owner's email address appears four times in PRIVACY_POLICY.md (§1, §9, §15), once in index.html §15 and once in the README footer. It is deliberately not reproduced anywhere in this wiki. The repo is public, so this is a disclosure the owner chose; that does not make it this wiki's to copy.

    #Open gaps

    • TODO: no repository among the 15 sources contains a footer link to the policy URL, although the README instructs "Link to that URL from the footer of any of your sites or apps". Which live surface, if any, it is currently linked from is unevidenced. confidence: low.
    • TODO: what the February placeholder contained, and what made the policy urgent on 2026-07-10, is unrecorded. Not asked at interview.
    • TODO: §10 invokes Standard Contractual Clauses without stating which mechanism actually applies to GitHub (SCCs vs the EU–US Data Privacy Framework). §11's "typically a short period" for host log retention cites nothing. §9.3 names LGPD and PIPEDA without defining or scoping either. Whether these were checked or carried over from a template is unknown. confidence: low.
    • TODO: §8's CCPA attestation — "In the preceding 12 months we have not sold or shared personal information" — is a date-bound factual claim made by a document whose effective date is the day it was written. Basis unrecorded.
    • Standing risk, not a defect: the template's factual statements (no cookies, no third-party processors) become false if it is ever applied unedited to a project with analytics, a database or a cloud API. The README's reuse checklist anticipates exactly this; see one-reusable-policy-not-per-project.
