    Render Over Fly.io

    Decision (2026-07-24, round 11): host the stickfps game server on Render. Koyeb recorded as an equal alternative; Fly.io demoted to "needs a card".

    This is the same question answered twice, oppositely, in one project — which is what makes it worth a page.

    #Round 1: Render evaluated and rejected

    "Evaluated Render as a Fly.io/Vercel replacement; rejected after confirming (web search) Render has no public inbound UDP — kept Fly.io (backend) + Vercel (frontend, user's existing account)."

    browser_game_stickfps/PROGRESS.md, 2026-07-25

    Correct at the time. The transport was geckos.io over UDP, and a host with no inbound UDP cannot serve it at all. Fly.io was never chosen on its merits — it was forced by the transport.

    #Round 11: the constraint was removed instead of satisfied

    When the requirement became "host this without a credit card", the binding constraint was UDP, not the host. websocket-tcp-over-geckos-udp deleted the UDP requirement, and Render's disqualification went with it. Every managed UDP host wanted a card; every free no-card tier spoke TCP.

    The transferable move: when no option satisfies a constraint acceptably, check whether the constraint is load-bearing before accepting the least-bad option. Here one layer of the stack was cheaper to change than the entire hosting decision it was dictating.

    #What Render was chosen on

    Free tier with no card, persistent process (required for a 60 Hz authoritative loop — see split-frontend-backend-hosting), WebSocket upgrades on the standard port, and a /healthz route for its health check. Accepted cost: free instances idle down after ~15 minutes and cold-start the next player. Details on render-hosting.

    #Configured, not codified

    Render is set up through dashboard settings — Root Directory server, build npm install && npm run build, start npm start — with no render.yaml, no CI and no .github/ in the repository. fly.toml and a working docker image remain in the tree for the abandoned path.

    Known gapthe host of the live multiplayer session is unevidenced. The interview confirms the game was hosted and played with other people over a real network, but no artefact names where, and docs/DEPLOYMENT.md — accurate as of the last commit — states no deploy had been run from that environment. confidence: low on "it ran on Render" specifically; confidence: high on the decision recorded here.
