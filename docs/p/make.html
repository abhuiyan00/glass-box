    Make

    The old dependency-graph task runner, used here purely as a named-command registry rather than for incremental rebuilds. labour-fraud-analysis carries the only Makefile across the repositories ingested with it; data-warehousing-and-business-intelligence has no build entry point at all.

    Thirteen phony targets: all, data, db, docs, report, viewer, validate, lint, test, app, notebook, ci, clean.

    #The idea worth stealing: split targets by what they can access

    The pipeline reads a private document corpus that exists on one machine. Rather than let a reader discover that by running something and watching it fail, the file says so at the top and names exactly which half works:

    "Targets that read the PRIVATE source (data, report, viewer) only work where that source + src/scrub_rules.local.py exist. On a clean clone, data/ and docs/ are already the safe output; use db, docs, validate, test, app, notebook."

    labour-fraud-analysis-a-forensic-data-investigation/Makefile, 2026-07-11

    Then the split is encoded as a target, not just documented:

    "ci: db docs validate lint test ## what CI runs on a clean clone (no private source)"

    labour-fraud-analysis-a-forensic-data-investigation/Makefile, 2026-07-11

    make ci is the clean-clone contract. Anyone can run it, and it is the same list github-actions executes, so a green local run means something. make all is the private superset. The Makefile is the one place where the boundary between "reproducible by anyone" and "reproducible by one person" is written down — see reproducible-analysis.

    #Self-documenting help

    help:
	@grep -E '^[a-z].*:.*##' $(MAKEFILE_LIST) | sed 's/:.*## /\t/' | sort

    Every target carries a ## comment; make help greps them out of the file itself. The documentation cannot drift from the target list because it is the target list — the same instinct as generated-docs-checked-by-ci-diff, applied to the build file. Compare documentation-drift, which is what happens everywhere this trick is not used.

    #Overridable variables, not hard-coded paths

    PY ?= python, plus SOURCE ?=, REPORT ?= and VIEWER ?= defaulting to sibling-directory paths outside the repo. ?= means an environment variable wins, so the private source can live anywhere without editing the file — and no absolute path is committed.

    #Targets that assert rather than build

    Several targets exist to make a check runnable by name, which is what turns a claim into a command:

    • db — "load data/csv -> data/data.sqlite (asserts 0 FK violations)"
    • validate — "the leak-gate — must print RESULT: PASS", the disclosure-gate
    • docs — regenerates the artefacts CI then diffs

    That is verify-the-load-dont-declare-it wired into the entry point. clean removes only the regenerated database, never data/csv — the published dataset is an input to the clean-clone path, not an output of it.
