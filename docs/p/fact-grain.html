    Fact Grain

    The grain of a fact table is the answer to "what does one row mean?". It is the first decision in a star-schema, because every later choice — which dimensions can attach, which measures are additive, which duplicates are impossible — follows from it.

    #Declare it, then enforce it

    data-warehousing-and-business-intelligence states the grain in prose and makes the primary key carry it, in both marts:

    Mart Grain Enforced by
    Retail salesone row per sales order linePK on the source order-line identifier
    Price quotesone row per ticker per trading daycomposite PK (TickerKey, DateKey)

    "The primary key states the grain: one row per ticker per trading day. A fact table without one leaves the grain to be inferred from the loading query, which is how duplicate rows get in."

    Data-Warehousing-and-Business-Intelligence/project/twtr/sql/02_star_schema.sql, 2026-07-25

    The point of that comment is that a grain written only in documentation is a comment; a grain written as a primary key is a constraint the database enforces on every future load. It is the same instinct as verify-the-load-dont-declare-it applied at DDL time rather than at load time, and the same instinct as idempotent-loading — uniqueness lives in the schema, not in the loader.

    #Consequences that show up immediately

    • Measure additivity. At order-line grain, LineTotal sums freely across any dimension. At ticker-day grain, a closing price does not sum across days at all — which is part of why an indicator computed over a window is not a stored dimension attribute, see measure-vs-dimension.
    • Which dimensions can attach. A dimension can only join if it is meaningful at the grain. A salesperson is meaningful per order line; it is also frequently absent, hence nullable-salesperson-key.
    • Window functions need the grain to be regular. The whole ROWS BETWEEN n PRECEDING AND CURRENT ROW construction in window-function-frames assumes one row per ticker per trading day and silently means something else if that stops being true.

    #Grain outside the warehouse

    The same discipline shows up in labour-fraud-analysis, where the twenty-table dataset is FK-closed and each table's row count is reconciled against a committed manifest — a row-count reconciliation is only meaningful if you can say what one row is. See third-normal-form and reproducible-analysis.
