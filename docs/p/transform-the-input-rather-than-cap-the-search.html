    When a search does not terminate, the reflex is to add a step limit

    Transform the Input Rather Than Cap the Search

    When a search does not terminate, the reflex is to add a step limit. Sometimes the limit is right — a genuinely exponential search needs a budget. But when non-termination comes from a property of the input rather than the size of the problem, capping converts a hang into a wrong answer, which is worse.

    #The case that produced the rule

    A context-free grammar recogniser searched forward from the start symbol and pruned any sentential form whose minimum possible length exceeded the target. That is a correct pruning and it terminates on most grammars. On S → S S | ε it hung: S S S S is longer than the target and can still shrink back to it, so no form was ever prunable and the queue grew forever.

    A step cap would have made the recogniser return "not in the language" for strings that are in it. The bug would have moved from a visible hang to a silent wrong answer, and the tests would have gone green.

    The fix was to change the grammar instead. Removing epsilon productions and unit productions — both standard transformations, both preserving the language up to the empty string — leaves a grammar in which every derivation step either lengthens the sentential form or replaces a nonterminal by a terminal. After that the same bounded search is a genuine decision procedure, and the bound is a consequence rather than a hope.

    #How to tell which case you are in

    Ask what the bound would mean if it were hit.

    • "This instance is too big for the budget I gave it" — a cap is right, and it must raise rather than return a negative answer. Resolution saturation and SLD depth in the same repository do exactly that: RuntimeError and DepthExceeded, both distinct from "no".
    • "This input has a shape my search cannot handle" — a cap is wrong. Normalise the input so the shape disappears, or the wrong answers are permanent.

    #The related habit

    State the boundary in the signature, not in a caveat: max_steps, max_depth, MAX_ENUMERABLE_VARIABLES. And keep "out of budget" distinguishable from "no answer" — see logic-for-computer-scientists, where every bounded procedure raises rather than returning a negative, and document-the-failure-mode-next-to-the-fix for recording why the shape mattered once the fix has hidden the symptom.
