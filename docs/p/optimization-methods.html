    Optimization Methods

    Master's Optimization Methods course at Wrocław University of Science and Technology (FICT, lectures by M. Przewoźniczek). Three self-contained deliverables under one guided-tour README — see readme-as-guided-tour, of which this repo is the strongest instance in the corpus.

    3exam_prep/24-chapter interactive study guide, 23 canvas demos, zero dependenciesVanilla ES6 + HTML5 Canvas

    335 files / ~8.2 MB readable text. 102 PNG, 30 CSV, 19 .cpp, 12 .h, 10 .hpp, 17 .js, 17 .md, 2 PDF (one 11 MB). Remote over SSH, branch main with master merged in.

    #The git history splits the corpus's strongest pattern

    This is the headline finding of the ingest. 69 commits over 105 days through 2026-07-10 — the whole coursework history, and the 70th commit is the 2026-08-01 repair above — author date == commit date throughout, seven distinct working dates, four Merge remote-tracking branch 'origin/master' commits proving work across two machines, a structural refactor (b66a594 changed folder structure, 78 renames), and a real mid-stream bug fix:

    Optimization Methods, git commit d72e8bf "fixed no run on tabu search on high talliard instances", 2026-04-07

    That commit adds std::max(1, totalBudget/neighbourhoodSize) — on tai500_20_0 the integer division floored the budget to zero, so Tabu Search never iterated. A bug found by running the thing, fixed in place, committed the day it was found. tabuSize parameter was added follows three minutes later.

    But the repo is not uniform. 44 of 69 commits land on one day (2026-04-20), 17 of them a mechanical one-file-per-commit comment sweep. Then an 81-day silence, after which final_project arrives as one commit of 224 files / 17,075 insertions and exam_prep as one commit of 5 files / 4,608 insertions. Internal timestamps prove the work predates the commits by months — DATA_VERIFICATION.md says "Date of check: 2026-07-09", comparison_detailed.txt is described as generated 2026-06-16.

    Verdict: first_project is a genuine working log; final_project and exam_prep are a publishing dump. Recorded on import-finished-work-into-git as its one split case. The last four commits are pure presentation — linguist marking, tech-stack section, MIT licence, licence badges — i.e. presentation-polish-tail-commits.

    #Verification is auditing, not testing

    There are no unit tests anywhere in either project. Verification is entirely post-hoc artefact auditing, and unusually good at it: tools/verify_reports.py re-parses all 36 solver reports (trip-distance sums to ±1 m, demand == load, load ≤ capacity, every customer served exactly once) and cross-checks a hard-coded copy of the paper's Table 7 to ±2 m — a real external check, not a self-check. verify_chromosomes.py checks 12 chromosomes are valid permutations with in-range, non-monotonic depot genes. docs/DATA_VERIFICATION.md is dated, and the result is surfaced as a README badge (data checks 36/36 ✓) with re-run instructions. See generated-audit-artifact.

    The repo also states what it could not verify, in the shipped prose rather than a footnote — provenance-and-limits-stated-inline. It advertises its own negative results: the GA losing to greedy (blind-baseline-comparison) and a parameter change that backfired (revert-depot-mutation-rate-raise).

    #Findings

    • CMakeLists.txt line 1 was cmake_minimum_required(3.16) — the VERSION keyword missing, so the README's "recommended" CMake path could not configure, and the committed prebuilt pfsp.exe was the real run path. Fixed 2026-08-01 in d116a84, which also gave project(PFSP CXX) its language; the file now reads cmake_minimum_required(VERSION 3.16). The finding stands as a finding — it was true for the whole life of the coursework — and is retired as a live defect. Details and the full reasoning on cmake. confidence: high, both states read directly.
    • A negative reproducibility result, kept. Re-running the deterministic greedy on a freshly downloaded Wrocław graph gave 178,207 / 322,318 / 458,921 m against the paper's 177,555 / 299,944 / 481,089 m — OSM has drifted. Recorded on osmnx and multi-depot-vehicle-routing.
    • documentation-drift, four instances. first_project/README.md still says "No license file is currently included in this repository" three months after MIT was added at root; mdvrp/README.md says "never new executables" while ARCHITECTURE.md §7 lists six; HOW_TO_RUN.md names two scripts that do not exist — self-flagged in the audit rather than fixed; exam_prep/README.md says 24 chapters while chapters.js says "Twenty-five chapters".
    • The .gitattributes is about language stats, not binaries. Two linguist-generated=true rules only, so GitHub stops labelling the repo "100% JavaScript" when most of those bytes are generated map-coordinate data. No Git LFS; the 11 MB PDF and pfsp.exe are committed raw.
    • No .claude/, CLAUDE.md, AGENTS.md, .github/ or .vscode/ anywhere — this repo contradicts agent-skills-checked-into-the-repo.
    • final_project/docs/ uses SHOUTY topic filenames with no numeric prefixes; numbering lives inside content (chapters 01–24, ARCHITECTURE.md §1–§10, combos C01–C32). Contradicts numbered-docs-chapters and numbered-stages-in-directory-names.

    #Open gaps

    • TODO: the headline "C19 wins for both solvers" rests on analysis files whose underlying combo_ranking.csv / pilot_summary.csv are not committed (only .gitkeep). The 1,280-runs-per-solver claim cannot be re-derived. See operator-bake-off. confidence: low.
    • TODO: first_project's results are cross-checked against nothing — no comparison to published Taillard best-known values. See permutation-flow-shop-scheduling. confidence: low.
    • TODO: why final_project/mdvrp dropped CMake for a hand-written Makefile plus raw g++ lines in docs/commands.txt is not recorded anywhere.
    • TODO: the standard-library-only constraint (no Boost, LEMON, OR-Tools, no LP/MIP solver) has no recorded reason — course rule, portability, or preference is undetermined.
    • TODO: DATA_VERIFICATION.md §2.5 records BestFoundResults/ being deleted as a duplicate, but git shows zero deletions in history. That cleanup happened off-git during the May–June silence; what else was pruned is unrecoverable.
    • TODO: the 32-page report/OptiRepo.pdf carries claims beyond Table 7 that nothing audits.
