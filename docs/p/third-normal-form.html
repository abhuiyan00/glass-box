    Third Normal Form

    A relation is in 3NF when every non-key attribute depends on the key, the whole key, and nothing but the key. In practice: no repeating groups, no partial dependency on part of a composite key, and no attribute that is really a fact about another attribute rather than about the row's identity. Lookup values move to reference tables; many-to-many relationships get junction tables.

    #The normalised side — a forensic dataset

    labour-fraud-analysis ships twenty tables with four reference lookups and three junction tables (document_person, document_company, document_worksite) implementing the many-to-many links that carry chain-of-custody. Foreign-key closure is asserted in two places: the database build runs with PRAGMA foreign_keys = ON, so a clean build implies zero violations, and the test suite checks primary-key uniqueness on six tables and FK closure over eight pairs. See reproducible-analysis and sqlite.

    Normalisation is doing real work here, not decoration. Because a person, a company and a document are separate entities joined through junctions, the same document can support claims about several parties, and the shared-identifier-clustering signal is a group-by rather than a text search.

    #The denormalised side — a warehouse, deliberately

    data-warehousing-and-business-intelligence goes the other way on purpose. DIM_PRODUCT collapses a three-level Product → Subcategory → Category snowflake into one wide table, repeating category text on every product row. That is a textbook transitive dependency and it is correct for the workload: analytical reads, no updates, one join per dimension. See star-schema.

    The rule the two repos jointly demonstrate: normalise where the data is written and audited, denormalise where it is only ever read in aggregate. Normal form is a property you choose per workload, not a virtue you maximise.

    #Gap in the 3NF claim

    • TODO: the fraud repo's README and generated schema both assert "3NF", but no file argues the normal form, and person carries the contact attributes the analysis explicitly treats as shared across people — which is the signal, not an error. Whether that is an accepted violation, a different reading of the dependency, or an unexamined label is unrecorded. confidence: low on the "3NF" label specifically; the table structure itself is read directly from the DDL and is not in doubt.
