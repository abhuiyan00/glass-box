    Labour Fraud Analysis

    A portfolio case file. A private labour-migration / financial-crime document corpus is run through a deterministic anonymisation pipeline, and what ships is a 20-table synthetic relational dataset — 1,472 structured rows over 512 document records — with three analysis surfaces and a long-form narrative. The engineering deliverable is the pipeline and its gate, not the finding.

    Status: finished and frozen at last commit 2026-07-11. 8 commits, seven inside one second and the eighth four minutes later — import-finished-work-into-git. The README banner and docs/investigation.md §5 both describe the underlying matter as "real, active" and "ACTIVE — under review"; the repo itself is presented as complete.

    Publish stance — reversed 2026-07-30. The original stance was publish: false on every page for this repo, per the interview ("just keep it as it is"). The author lifted it deliberately on 2026-07-30, having been shown what the blanket held back: twelve tech and method pages that carry nothing from the matter itself.

    What the reversal does not change: the underlying corpus is not here, was never here, and no page reproduces a name, an identifier or a document from it. Every value in the shipped dataset is invented — see synthesise-rather-than-redact and structure-preserving-anonymisation. What is now public is the method: how the substitution is seeded, what the disclosure gate refuses, how the load is verified.

    #Stack

    Python 3.10+ · pandas · networkx · streamlit · matplotlib · plotly · sqlite · vanilla JS with vendored libraries · make · ruff · pytest · github-actions. ~2,200 LOC across eight modules in src/.

    pandas is a presentation dependency here, not a pipeline one. It is imported by src/app.py and the notebook only; the anonymisation pipeline, the disclosure-gate and the whole test suite run on stdlib csv. The part that must be trustworthy has the fewest dependencies — the same instinct as zero-dependency-no-build-step, applied to the Python half.

    #The privacy pipeline

    Private source CSVs (outside the repo) plus a git-ignored local rules module feed anonymize.py, which writes data/ and a git-ignored re-identification mapping. Every value is replaced; every relationship is preserved — structure-preserving-anonymisation. Substitution is derived from one committed global seed via a keyed hash, so the same source value maps identically in every table and in free text: deterministic-seeded-substitution. Identifiers keep their shape and lose their validity — format-preserving-invalid-identifiers. validate_anonymization.py runs the disclosure-gate before anything ships.

    #The analytical method — and what is not in it

    Four named signals, stated identically in docs/investigation.md §8, the dashboard, the notebook and the test suite: bulk sponsorship (permits per employer per day over a threshold, reinforced by permit-serial contiguity), shared-identifier clustering (contact-address concentration — 66 nominally independent workers collapsing onto two contact points, see shared-identifier-clustering), declared-wage uniformity (a modal-spike read off a 30-bin histogram), and entity succession (permits migrating predecessor→successor across a year). A fifth, graph-based signal counts people adjacent to two or more companies as bridges.

    The argument is convergent-evidence — "not a smoking gun, a convergence", "No single one proves intent" — with a three-tier reliability scheme and chain-of-custody back to a document row for every claim.

    What is NOT here, stated so no reader assumes it. No Benford's law. No z-score or IQR outlier detection. No time-series anomaly model. No significance testing of any kind. No centrality measure — degree is used only for node sizing. No ghost-employee test as such: the outsized payroll line and the implausible-age employees are narrative observations, not computed. No duplicate-record detection as an analytic — the SHA-256 folding of 2,456 originals down to 512 records is a deduplication step in ingestion, not a fraud test. The method is threshold flags, group-bys, value-count concentration and a graph, argued as convergence.

    #Findings

    • The README's CI claim overstates what CI enforces. confidence: high. The README says no value identifies a real party, "a claim that is test-verified in CI"; ci.yml's own comment says the leak scan and the stem guard skip on a clean runner because the private source and rules are absent. CI therefore enforces structural integrity plus a regex sweep only. This is the single largest prose-vs-artifact gap in the repo. Recorded on disclosure-gate.
    • Residual source-signalling survives in committed code, and it contradicts docs/methodology.md §4's claim that no origin-signalling scrap survives. The pesel, nip, regon and krs column names carry through DDL, CSV headers, the dashboard and the generated data dictionary; the validator's ALLOW set contains "poland" and "polish"; one PII pattern is a +880 phone regex; the viewer still formats numbers with a pl-PL locale. None is a person-like value, but together they narrow the source jurisdiction and the worker-origin corridor. Stated as a limitation on structure-preserving-anonymisation.
    • Two analytical signals are regression-tested against anonymisation damage — test_shared_inbox_pattern_preserved and test_bulk_permit_batch_pattern_preserved. Testing that a finding survived the privacy pipeline is unusual and real. See reproducible-analysis.
    • Manifest contradictions. pyproject.toml declares [project] with requires-python = ">=3.10" and a py310 lint target but no dependencies key at all, so pip install -e . installs nothing; all twelve runtime deps live only in requirements.txt. CI pins Python 3.12, so the declared 3.10 floor is never tested. pyvis is listed with a comment about entity-graph rendering and is imported nowhere. plotly is grouped under the same comment but is used only by streamlit — the notebook uses matplotlib exclusively. All deps are floor-pinned with no upper bound and no lockfile, under a comment claiming reproducibility. See setuptools-and-pyproject and documentation-drift.
    • Generated docs are committed and then diff-gated in CI — generated-docs-checked-by-ci-diff and generated-audit-artifact.
    • The Makefile is the clean-clone contract, and CI restates it instead of calling it. make ci is written as the one command a stranger runs after cloning; ci.yml re-expresses the same sequence as YAML steps. Nothing checks that the two still agree, so the canonical entry point can drift from the enforced one silently. See make and github-actions — and contrast verify-the-load-dont-declare-it, where the same repo does wire the check to the artifact.
    • Limits are written into the shipped prose, not into an appendix: a threat-model section, a "what the data will not tell you" section, deliberately retained OCR date errors, and the tiered reliability scheme. Strongest instance of provenance-and-limits-stated-inline in the source set.
    • Milder documentation-drift: the README and methodology call it a "four-way" disclosure gate while the validator's own docstring says "two independent checks"; the viewer's i18n module still advertises two locales after build_viewer.py::strip_locale was written to remove one — keep-the-superseded-version-in-tree.

    #Open gaps

    • TODO — publishing. Publishing the derived form would need clearance from whoever holds the source corpus; the underlying matter is described in the repo as live and under review. No such clearance is evidenced. Every page for this repo stays publish: false until that is resolved.
    • TODO: the >= 3 permits/day bulk-sponsorship threshold is hard-coded identically in the dashboard, the notebook and the test suite, with no derivation recorded anywhere. Legal threshold, empirical break in the data, or a round number is unknown. confidence: low on the threshold's justification.
    • TODO: permit-number contiguity is the strongest single element of the bulk-sponsorship argument and is asserted by eye — the notebook prints a sorted list and nothing computes gaps. See convergent-evidence.
    • TODO: why three UIs over the same twenty tables, and which came first, is never stated.
    • TODO: the README lists "entity resolution" as a skill; the code does grouping and value-counting with no matching, blocking or linkage algorithm. What was meant is unrecorded.
    • TODO: "512 documents distilled from 2,456 originals" appears in four files, but the generated one traces back to data/, so all four rest on one source. Whether 2,456 is a recorded ingest count is unknown. confidence: low on that number.
    • TODO: the README and generated schema both claim 3NF; no file argues the normal form, and person carries the contact fields the analysis treats as shared across people. See third-normal-form.
    • TODO: whether make all has been run end-to-end since the last commit — i.e. whether committed data/ still matches what the current pipeline and seed would produce — is unknown.
