    Project Management Web Platform

    A TypeScript API for projects, tasks, accounts, and session-based access control. It is a clean-room implementation of a fifth-semester Web Systems Programming specification: 116 real-socket tests run without a database, and the repository keeps one runtime dependency with no build output to commit.

    #Policy before persistence

    Authorization lives in pure functions over already-loaded entities in src/domain/authz.ts. Use cases load a resource, make an explicit access decision, then write. The Actor type carries only the authenticated user id and role needed for a policy decision, and the helpers make the difference between visibility, modification, deletion, and administration explicit.

    The policy also handles information boundaries deliberately. A caller who cannot see a resource gets the response appropriate to that visibility boundary, while an assignee who already knows a task exists receives a direct denial if they try to delete it. Session authentication re-reads the user record, so a current role or block status remains authoritative.

    #Storage as a port

    The service layer depends on the Store boundary rather than a database implementation. MemoryStore and JsonFileStore share the same repository contract, including normalised email addresses and task cleanup when a parent project is removed. That makes the HTTP API testable against real local servers while keeping persistence adapters interchangeable.

    Configuration is fail-closed: the service requires its session secret from the environment rather than using a default. Password hashing uses node:crypto.scrypt, tokens use createHmac, and Node runs the typed source directly for development.

    #Verification

    npm run check runs TypeScript checking and 116 tests against a real server and socket. On 2026-08-12 it passed unchanged. node tools/mutation-check.mjs copies the tree to a temporary directory, applies 12 controlled policy mutations one at a time, and confirms that each makes at least one selected test fail: 12/12 were caught in the local audit.

    #Boundaries

    The repository concentrates on the server contract. It has no browser front end, no Mongo adapter, and no multi-process JSON-file adapter. Those are deliberate limits rather than features implied by the API surface. The published NOTICE records the clean-room provenance and course-material boundary.
