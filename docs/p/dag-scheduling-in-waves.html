    DAG Scheduling in Waves

    Given a plan whose subtasks declare depends_on, release every subtask whose dependencies are already finished, all at once, as one parallel wave. When they rejoin, do it again. Repeat until nothing is left. It is a topological sort executed in batches rather than one node at a time, and the batch is the point: the width of each wave is the parallelism available for free.

    #Why batches rather than a queue

    A worker pool with a ready-queue gets the same throughput, but the wave is a unit the user can be shown. In agent-orchestrator each release emits one event —

    {"event":"wave", "data":{"ids":[…], "index":0, "size":3}}

    — so the panel can say "three agents started together" instead of three unrelated starts a half-second apart. Scheduling that is legible costs nothing here and buys the whole progress display.

    #The two bugs this shape invites

    Counting the wave by its subtasks. schedule() runs once per rejoining worker, not once per wave, so numbering waves by how many ids had been dispatched labelled a two-wave plan 0 then 2. The fix is a counter incremented on release, not derived from the work.

    Running out of supersteps. schedule → worker → schedule is a loop, so each wave costs two langgraph supersteps. The library's default recursion_limit of 25 aborts a deep plan partway through — which looks like a model failure and is not. The project sets 150.

    #What makes a wave safe

    Two subtasks in the same wave are independent by construction — that is exactly the property that makes running them together correct. It is also what makes context sharing decidable: a subtask may see its transitive ancestors and nothing else, because nothing else is guaranteed to exist yet (transitive-context-with-budgets).

    The scheduler must therefore be defensive about the plan it is given, since the plan comes from a model: dependency ids that name nothing are dropped rather than deadlocking the run, and a cycle is broken rather than looped on. A DAG asserted by an LLM is a DAG only until it isn't.
