    Generated Artifact with a Pristine Source

    The file the application loads is generated, carries a DO-NOT-EDIT banner naming its generator, and its input is committed beside it. Three things must all be true, and it is the third that distinguishes this from ordinary code generation: in a normal build the source is the only thing in the repo and the artifact is gitignored. Here both are tracked, because the artifact must load from file:// with no build step available — see zero-dependency-no-build-step.

    Confirmed in three repositories.

    The banner is the tell, and it says the same thing in two repos five weeks apart:

    "// GENERATED by _build_bank.js — DO NOT hand-edit. Edit chapters.backup.js (study) or the"

    IT Applications in Business and Commerce/lecture/exam_prep/chapters.js, 2026-07-10

    "/* AUTO-GENERATED by tools/build_sets.mjs — do not hand-edit."

    Physics/exam_prep/js/quizsets.js, 2026-07-10

    Both banners go further than forbidding edits: they name the file to edit instead, and the exact command to regenerate. A banner without those two facts sends the reader hunting.

    #What the generators actually do

    Not templating. In each case the generator performs a transformation that would be error-prone or tedious by hand, and each one is deterministic so re-runs are stable:

    • _build_bank.js merges a synthetic study bank with a dirty past-exam dump, de-duplicates (~169 raw items where concepts repeated up to six times, collapsed to one well-formed question each), de-biases option order so the answer is not guessable by position, reassigns global ids, and applies four documented answer-key corrections. Determinism comes from an LCG seeded 1337.
    • build_sets.mjs partitions a question bank by Jaccard similarity to a provided set — set 2 is the 16 most similar, set 3 the 59 least similar, i.e. the coverage gaps — and writes an audit report alongside.
    • The Discrete-Maths viewer converts a CSV into the PAWLAK object of a pawlak-information-system, so an offline viewer can reproduce the Neo4j lab without a database.

    The one asymmetry: only the first two commit their generator. The Neo4j viewer's data.js states its input (global_finance.csv, which is in the tree) but the converting script is absent, so that instance is regenerable in principle and not in practice.

    #Why the source is "pristine" and not just "the input"

    _build_bank.js reloads the backup rather than the generated file on every run — deliberately, and it says so:

    "// ---- load synthetic bank (ALWAYS from the pristine backup, never the generated file) ----"

    IT Applications in Business and Commerce/lecture/exam_prep/_build_bank.js, 2026-07-10

    That single line is what prevents the classic failure: regenerate from the output once and the de-biasing, de-duplication and id reassignment compound on already-processed data. The word "backup" in the filename is misleading — chapters.backup.js is not a backup, it is the source of truth, and the file that looks authoritative is the derived one.

    #Where it sits

    Three of the instances are exam-prep apps, so this is a component of course-as-runnable-study-tool. The broader form — one dataset, many outputs, generator owns all of them — is single-source-of-truth-generators. Keeping both files in the tree is also a mild case of keep-the-superseded-version-in-tree, though here the retained copy is load-bearing rather than vestigial.
