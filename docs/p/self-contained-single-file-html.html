    Self-Contained Single-File HTML

    One .html file that renders completely with zero outbound requests — styles inline in a <style> block, no scripts, no images, no fonts, no CDN. Copy the file anywhere, open it by double-click, email it as an attachment: it looks the same everywhere and it works with the network unplugged.

    #The instance

    privacy-policy/index.html in privacy-policy-template: 214 lines, one inline <style> block, a two-column table of contents, 15 sections, and light/dark handled by CSS custom properties under @media (prefers-color-scheme: dark) rather than a theme toggle. Grepped for external references, it has none — every https:// in the file is a hyperlink in the prose, never a fetched asset. The font stack is system fonts, so nothing is downloaded to render text.

    #When the extreme point is the right one

    Inlining everything trades editability for portability, and that trade only pays when the document is small, static and needs to survive being copied. A privacy policy is exactly that: one page, changed a few times a year, that must render identically for a regulator, in an email attachment, and on a Pages URL.

    The cost is visible in the same repo. Because there is no generator, PRIVACY_POLICY.md and index.html are two hand-maintained copies of one document. They agree today; nothing enforces that they will. That is documentation-drift pre-loaded into the architecture — and the same trade keep-the-superseded-version-in-tree makes deliberately, except here the duplication is a side effect rather than the goal.

    Above roughly one page, or the moment the content needs to be generated, the folder-shaped deliverables in the table above are the better answer.
