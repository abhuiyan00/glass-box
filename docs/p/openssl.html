    OpenSSL

    The general-purpose cryptography toolkit — a library that most of the internet links against, plus a command-line front end that is the standard way to do PKI work by hand. Used in labs 06, 07 and 09 of cybersecurity-engineering-laboratories, alongside GnuPG and Easy-RSA.

    #The subcommands the labs exercise

    Area Subcommand Purpose
    RSA keysgenrsa, rsagenerate a private key; derive the public half
    Modern keygengenpkeyalgorithm-agnostic key and parameter generation, including DH parameters
    Digests & signingdgsthash, sign with a private key, verify with a public one
    Key agreementpkeyutl -derive, pkeyparam, pkeyDiffie–Hellman derivation and key inspection
    Certificatesreq, x509, ca (via Easy-RSA)CSR generation, self-signing, CA operations
    Packagingpkcs12bundle key and certificate into a .p12

    The sign/verify pair is the heart of lab 07: sign a file with the private key, verify with the public one, then modify the file and verify again to watch it fail — see digital-signatures. Easy-RSA wraps the same primitives into a CA whose certificates then feed OpenVPN in lab 09.

    #Where it sits against CrypTool

    cryptool shows you what a primitive does; OpenSSL makes you produce the artefacts. The commands are text, so they are reviewable and repeatable — which is precisely what the GUI crypto labs cannot leave behind. That is also why OpenSSL is where the repository's failures are most visible: a screenshot of a working demo hides nothing, whereas a command that returns an error is recorded as an error.

    #The Diffie–Hellman exercise did not complete

    Lab 06 attempts DH practically between two VMs — generate shared parameters, derive per-client keys, exchange public halves, derive the shared secret, compare. The report records failures at four consecutive steps ("could not extract", "not working", "did not work", "not resolved") and the author notes the instructions were unclear.

    #Operational notes worth keeping

    • Generate the CSR where the private key lives. The private key must never leave the subject's machine — the whole non-repudiation argument in public-key-infrastructure rests on it.
    • A .p12 is a private-key container by definition. This repository's .gitignore excludes *.p12, *.pfx, *.pem, *.key, *.jks, *.keystore and id_rsa* so the rule holds by default rather than by vigilance.
    • The natural terminal output of key generation prints the private key. That single fact drove a documentation decision in this repo — see omit-rsa-private-key-screenshot.
    • Verification failures are informative and distinguishable. Verifying against the wrong key and omitting the signature argument fail differently, which is exactly why the lab's chosen illustration keeps the failed attempts above the successful one.
