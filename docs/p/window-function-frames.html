    Window Function Frames

    GROUP BY collapses rows. A window function does not — it computes an aggregate for each row, over a set of rows defined relative to that row. The frame clause is what defines that set, and it is the part people skip.

    AVG(x) OVER (PARTITION BY k ORDER BY t ROWS BETWEEN 13 PRECEDING AND CURRENT ROW)
    • PARTITION BY — restart the calculation per key. Without it, one series bleeds into the next.
    • ORDER BY — establish what "preceding" means. A frame without an order is meaningless.
    • ROWS BETWEEN … AND … — the frame proper: how many neighbours participate.

    ROWS counts physical rows; RANGE counts logical peers by the ordering value and folds ties together. For a series with one row per key per period they behave identically, which is exactly why substituting one for the other is a bug that survives testing on tidy data.

    #The frame is the whole indicator

    In data-warehousing-and-business-intelligence, a 14-period moving indicator is not an algorithm so much as a frame. LAG supplies the previous value, a CASE splits the change into gain and loss components, and two AVG(...) OVER (...) calls over a 14-row trailing frame produce the ratio that becomes relative-strength-index.

    Warm-up is handled by counting the frame, not by guessing. A COUNT(*) over the same frame returns fewer than 14 for the first thirteen rows of each partition, and the write gates on it, storing NULL rather than a number computed from a short window. That is the transferable trick: the frame can tell you how full it is, so a partial window never silently becomes a wrong answer. See tests-that-pass-for-the-wrong-reason for the general shape of that hazard.

    #Ranking frames, elsewhere in the same repo

    The analytics scripts use the other family of window functions — ROW_NUMBER() OVER (PARTITION BY … ORDER BY …) for profiling and de-duplication — alongside PIVOT, ROLLUP, GROUPING SETS and GROUPING(). Same mental model: partition, order, then read one row's position within its group without collapsing the group.

    #Portability

    The reference implementation re-expresses the same frame in sqlite, "chosen because its window-function syntax matches and it needs no server". Window syntax is one of the more portable corners of SQL — the frame clause is standard, the surrounding date and string functions are not. See reference-implementation-as-specification.
