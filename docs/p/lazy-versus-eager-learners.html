    Lazy versus Eager Learners

    Two classifiers taught in the same course sit at opposite ends of one trade, and the trade is a pair of counts rather than a pair of adjectives.

    work at fit time work per prediction
    κ-NN (lazy)0 distances computedexactly len(train) distances
    naive Bayes (eager)one counting pass over the datafeatures × classes, independent of len(train)

    Both numbers are counted by the implementations and asserted by tests. "κ-NN is slow at prediction time" is unfalsifiable; "it computes exactly len(train) distances per query" fails the moment an index or an approximation is introduced, which is what makes it worth writing down — counted-complexity-assertions.

    #Why the asymmetry is the whole design

    A lazy learner defers everything, so it has no model. That has consequences in both directions and neither is obviously the better side:

    • adding training data is free — no refit, no retraining, no invalidation;
    • there is nothing to inspect, nothing to ship without the data, and nothing that compresses;
    • every query pays for the whole history, forever.

    An eager learner does the opposite. It compresses the data into parameters once, and the parameters are the thing you can ship, version, inspect and reason about. Adding data means refitting.

    The practical rule that falls out: lazy wins when the data changes faster than you query it, eager wins when you query faster than it changes.

    #The naive Bayes failure that matters more than the algorithm

    A word never seen in a class gets probability zero under maximum likelihood, and zero is absorbing in a product. One unseen feature drives that class's posterior to zero regardless of every other piece of evidence in the document — a single word vetoing the verdict.

    Laplace smoothing adds a pseudo-count to every cell and removes the veto. Measured with alpha = 0, a document of three unseen words gives -inf for one class and a finite score for the other; with alpha = 1 both are finite and the evidence decides.

    This is why the smoothing parameter is not a tuning knob. At zero the estimator is not merely worse, it is structurally broken, and it is broken in a way that looks like confidence.

    #The other arithmetic failure

    Naive Bayes multiplies one factor per feature, which underflows long before the answer is reached — see log-domain-arithmetic-for-probability-products for the measured vocabulary size at which it dies.

    #Determinism is not free either

    κ-NN ties have to be broken by something. Left to dictionary or set iteration order, identical code over identical data scores differently on consecutive runs — which has actually happened in this archive's retrieval evaluation, where one scoring path produced 0.73, 0.53 and 0.60 on three runs.

    Breaking ties by training-set order makes the result reproducible, and the test asserts it by repetition rather than by inspection.
