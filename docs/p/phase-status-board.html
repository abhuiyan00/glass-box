    Phase Status Board

    A single live table of numbered phases, each carrying a colour, a status, and — the part that does the work — an explicit "Remaining:" line naming what is not done. It replaces the binary done/not-done checklist with something that can express code exists but has never met reality.

    farely's 02-roadmap.md runs fourteen phases with four states: 🟢 done · 🟡 in progress · ⚪ not started · 🔴 blocked.

    #Why the extra states earn their place

    Two labels carry almost all the information:

    • "done (sim)" — Phases 6b and 11 are marked green with a qualifier. The feature works in the browser simulator; it has not worked anywhere else. Without that suffix they would be indistinguishable from genuinely finished work.
    • "code-complete — remaining: validate on device" — Phases 2, 3, 6, 7 and 12. This is the honest name for the most common state in a solo prototype and the one a checkbox cannot express at all.

    Phase 5 — field testing on a real phone with real offers — sits at ⚪ not started.

    #The board told the truth

    This is the finding worth keeping. Farely's README overstates its test coverage and its privacy posture, and four documents describe an OCR engine that is a stub — see documentation-drift. The roadmap board is the one artifact in the repo that did not drift:

    "Only the web simulator, never the APK on a live shift."

    interview, 2026-07-28

    Which is exactly what a board reading Phase 5 ⚪ not started and five phases at remaining: validate on device had been saying all along. A structured status table with a mandatory "remaining" field resists optimism in a way that prose does not, because leaving the field blank is visibly a lie while writing a confident sentence is not.

    Contrast the same repo's index README:

    "Phase 0 — Documentation. No native code merged yet"

    Farley/docs/ocr-overlay/README.md, 2026-07-02

    Same repo, same directory, thirteen phases apart. The difference is that the board is the file the author returned to; the index is prose written once.

    #Where the pattern is weak

    The board records engineering completion, not value completion. Every green phase in Farely is green against a simulator, and no phase asks "did this earn money" — which is why deadhead-adjusted-net-profit's constants could stay unvalidated with the board still looking healthy. A status board bounds the claim "the code exists"; it cannot bound "the code is right".
