    Docker

    Container packaging for the stickfps game server. The only containerised service in the source set.

    #The image

    Two-stage build on node:22-slim: a build stage that compiles TypeScript, then a runtime stage that installs with npm ci --omit=dev and copies the compiled output. EXPOSE 9090.

    Two-stage matters more than it looks for this service: the runtime image carries no TypeScript compiler and no dev dependencies, which is most of the weight of a Node build. npm ci rather than npm install pins to the lockfile, so the image is reproducible from the same commit.

    #It was actually run

    Unlike the deployment itself, the container was built and executed locally and verified through a real /healthz request. That makes it one of the few pieces of stickfps's infrastructure story backed by an executed command rather than a written runbook — the wider limits are on render-hosting and stickfps.

    #But it is not on the deployed path

    The image belongs to the Fly.io route, which was the original target while the transport still needed UDP. render-over-fly-io moved the documented deployment to a dashboard-configured build (npm install && npm run build, npm start) that does not use this Dockerfile at all. fly.toml survives in the tree with its UDP service removed.

    So the repo carries a working container for a host it no longer targets. That is not obviously wrong — it keeps the service portable to any container host and it is the only fully self-describing deployment artefact present — but it should not be read as how the thing is deployed.

    #A drift marker

    The Dockerfile still declares a UDP port after UDP was removed:

    EXPOSE 10000/udp

    A leftover from geckos.io, retired in websocket-tcp-over-geckos-udp. Harmless — EXPOSE is documentation, not a firewall rule — and precisely because it is harmless nothing forced it to be updated. Catalogued with the rest in documentation-drift.
