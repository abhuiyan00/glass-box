    Tests That Guard the Repository

    Put the promises the repository makes into the same suite as the code, so they fail on the same command. Fifteen of agent-orchestrator's 145 pytest units never import the product: they read files.

    #What they assert

    Guard Fails when
    version consistencyany of the six places carrying the version disagrees — manifest, changelog heading, skill bundle, install line, front door, docs
    dependency claimsthe extension gains a runtime dependency, or the backend a second one
    commandsa command is contributed in the manifest but never registered
    packagingthe .vsix would include something that must not ship
    secretsan API-key-shaped string appears anywhere in the tree
    pathsa developer's absolute path is committed
    linksany relative markdown link in the docs resolves to nothing
    runnersmake and the PowerShell script stop offering the same targets

    #Why these and not a linter

    Each one is a promise already written down somewhere in prose. "The version appears in six places" is a line in the release procedure; without this guard it is a line someone has to remember at 1 a.m. The test does not add a rule — it makes an existing rule enforceable, which is the difference between a convention and a constraint.

    The dead-link guard is the clearest case. Documentation cross-references rot silently and are found by a reader, not by an author — documentation-drift. Two broken ADR links were sitting in the architecture document when this test was written; it found them, and it will find the next two.

    #Cost, honestly

    They are slower to write than they look, because each one has to decide what counts: the secret scanner must match key shapes without matching the documentation that discusses keys, and the link checker must strip anchors and skip http, https and mailto. A guard with a false positive gets deleted by the next person in a hurry, so the tuning is the work.

    They also only cover what is committed. A test cannot tell you the vendor renamed a CLI flag — that is stated as uncovered rather than papered over.
