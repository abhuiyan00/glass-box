    Air Quality and Public Health Analysis

    A dependency-free Python pipeline that asks one narrow question honestly: at the area-day level, how does the linear association between air-quality exposure and newly reported cases per 100,000 change across candidate lags?

    The answer it gives is a descriptive ecological screen. It is not an estimate of individual risk and not a causal claim, and the repository spends more effort defending that boundary than computing the number.

    #What the original notebook did wrong

    The coursework version is the more instructive artefact, because every one of its faults is the kind that produces a plausible chart:

    Original Why it is wrong Rebuilt as
    Took the first 100 rowsA convenience sample presented as a datasetFull validated series, or a hard failure
    Used cumulative case counts as a predictorAny two rising series correlate; the number measures timeDifferenced to daily new cases before analysis
    No city-to-county join establishedThe two files were never about the same placesGeographic unit explicit and identical in both inputs
    Lags as row offsetsA missing day silently shifts the lagLags computed on calendar dates
    Raw counts across areasPopulation confounds every comparisonOutcomes normalised per 100,000
    Several models fitted, none evaluatedSelection without a criterionOne reported statistic, and its limits
    Causal-sounding conclusionUnsupported by any part of the designNo p-values, predictions or causal language

    The first two are the ones worth remembering. Cumulative-count correlation is the error that produces a strong, publishable-looking result from two variables that share nothing except a direction of travel.

    #The analytical contract

    Validation runs before analysis and fails loudly: dates are ISO, rows unique by (date, area), each area a complete daily series, AQI finite and within 0–500, cumulative counts non-decreasing, deaths never exceeding cases, population positive and area-constant. Malformed, duplicate, decreasing or non-daily input is rejected rather than repaired.

    That strictness is the point. Geographic crosswalking, date imputation, population sourcing and revision handling are data-preparation decisions, and hiding them inside an analysis is how an assumption becomes invisible. See verify-the-load-dont-declare-it for the same instinct applied to a warehouse load.

    Both pooled and within-area correlations are reported, because the gap between them is where the ecological fallacy lives.

    #Reproducibility as a property, not a claim

    One run writes four files: the report, the joined daily records, the lag table, and a manifest.json carrying SHA-256 hashes of every input, the parameters, and hashes of the three outputs. No timestamp and no machine path enters any file, so the same inputs produce byte-identical output on every platform — a committed reference report is the fixture that proves it. reproducible-analysis, generated-artifact-with-pristine-source.

    The committed data is synthetic, invented with a deliberately injected lag-two signal. Recovering that signal verifies the pipeline and says nothing about the world; the README says so in the same paragraph that reports it. docs/DATA_PROVENANCE.md records why the two historical coursework CSVs cannot be responsibly joined as they stand, which is also why they are not here.

    #Verification

    python -m unittest discover over validation, analysis, determinism and CLI regression tests, plus a CI matrix on Python 3.11–3.14 that compiles the package and rebuilds the fixture report in a temporary directory. Runtime dependencies: none — zero-dependency-no-build-step.

    A 2026-08-12 local audit passed all 18 tests and validated the synthetic three-area input. The repository's existing uncommitted lag-screen.svg is generated from the committed report, compared byte-for-byte with its generator by the suite, and states that the lag-two signal was injected. It is evidence, not a new scientific claim, so it was preserved without alteration.

    #Open gaps

    • TODO: the fixture is synthetic by design, so no real-world finding is produced. The backlog for replacing it is evidence-gated in TASKS.md and starts with the geographic crosswalk, not with the model.
    • TODO: Pearson correlation only. No confidence intervals, no seasonality adjustment, no autocorrelation handling — all of which a real analysis needs, and each of which is named in docs/LIMITATIONS.md rather than silently absent.
