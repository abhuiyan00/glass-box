    SQL*Plus

    Oracle's command-line client, and the execution model the whole of oracle-database-laboratories is written against. Every script in that repo is a SQL*Plus script first and a SQL file second — the @ run order, the & substitution variables and the / statement terminator are all client features, not database ones.

    #The four client features the repo depends on

    Feature Use
    @path/to/script.sqlrun a file; the README's run order is literally a list of @ lines
    &variableprompt-and-substitute at parse time — the repo's only parameterisation mechanism
    SET SERVEROUTPUT ONmake DBMS_OUTPUT.PUT_LINE actually print; without it the block runs and shows nothing
    SHOW ERRORS PACKAGE BODY xsee why a body compiled invalid
    / on its own lineterminate a PL/SQL block or type body — a bare ; will not

    SET SERVEROUTPUT ON appears at the top of every procedural script. Forgetting it is the classic "my trigger did nothing" false alarm: the code ran, the buffer filled, nothing was flushed.

    #Substitution variables versus bind variables

    &name is a textual substitution performed by the client before the statement reaches the server. It is not a bind variable: there is no type, no reuse of the parsed plan, and no protection against whatever the value expands into. Host binds (:name) exist, but need a separate VARIABLE declaration before the block will run.

    The repo standardises on substitution throughout and says so where the choice is visible:

    "Substitution variables (&...) throughout, consistent with the rest of the file -- mixing in a host bind (:name) would need a separate VARIABLE declaration before the block would run under SQL*Plus."

    Oracle-Database-Laboratories/sql/03_plsql/02_cursors.sql, 2026-07-25

    That records internal consistency as the reason for the choice, which is real but narrow.

    #Output is deliberately not committed

    .gitignore excludes *.lst, *.log, *.trc, sqlnet.log and afiedt.buf — SQL*Plus spool and editor artefacts — alongside wallet and credential material (*.sso, *.p12, *.jks, tnsnames.ora, wallet/). Clean, but it has a consequence the wiki records rather than glosses: no execution evidence exists in the repository. The scripts are internally consistent and would run; that they were run is not established. See oracle-database-laboratories.

    #Why a client gets its own page

    Because the run contract lives here, not in the database. @-ordered scripts with no build step and no driver program are the same delivery shape as zero-dependency-no-build-step elsewhere in this source set: the artefact is text, the runner is whatever the reader already has, and the ordering is carried by numbered-stages-in-directory-names rather than by a manifest.
