    Provenance NOTICE File

    A separate, plain-text NOTICE at the repository root whose only job is to draw the line between what the author made and what the author borrowed. Three repositories carry one, and in each the line is drawn around a different risk.

    #The three instances

    Repo The boundary it draws
    research-methodologies-open-set-recognitionown writing, structure, mermaid diagrams and the redrawn figure are MIT; the nine cited papers and the AUROC numbers are not the authors'
    it-applications-in-business-and-commercethe team's code and docs are MIT; TORCS, the SCR protocol and gym_torcs are third-party — TORCS is a runtime prerequisite, explicitly not redistributed, and the upstream gym_torcs licence is preserved verbatim in-tree
    labour-fraud-analysisthe loudest of the three: a SYNTHETIC DATA — READ FIRST banner declaring every name, identifier and narrative in the repo invented, while the data's shape and the analytical techniques are carried over from a real matter

    Three different reasons — academic attribution, licence compliance, and disclosure ethics — reaching for the same artefact. That convergence is what makes this a pattern rather than three coincidences.

    #Why a separate file, not a README section

    A README is a sales document — it is read for what the project does. NOTICE is the file you look in when you need to know what you may reuse and what you must not claim, and putting it at the root under a conventional name means the answer does not depend on anyone reading the tour. It also survives the README being rewritten, which in this source set happens often (readme-as-guided-tour pages are edited in dedicated presentation commits).

    The Research Methodologies instance is the strictest: the benchmark table is fenced off in its own NOTICE section, and flagged inline under the table in the report, and again in the licence footer. The same fact stated three times in three files is the point — see report-cites-benchmarks-rather-than-reproducing.

    #Relation to the broader habit

    This is the file-shaped specialisation of provenance-and-limits-stated-inline, which covers the same instinct expressed inline: OpenStax figure citations in physics-exam-prep, "not legal advice" in privacy-policy-template, "not experiments run for this coursework" in the OSR report. The inline form is more common; the NOTICE form is what appears when the boundary is legal rather than merely epistemic.

    Prefer the inline form for a caveat about a claim, and the file for a caveat about ownership — the second needs to be findable without reading the prose.
