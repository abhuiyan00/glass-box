    On-Device-First Inference

    Do the classification locally with cheap deterministic logic; treat a model call as an upgrade the owner may switch on, never as the default path. The local answer must be good enough to ship alone — if the product is unusable without the network, this is not on-device-first, it is a cloud product with a cache.

    Stated in farely's VISION §4 as "My data, my phone" and enforced in code: classifyScreen(capture, apiKey) returns heuristicClassify() immediately when no key is present, and a cloud failure falls back to the same heuristic.

    #What runs locally in Farely

    • Node-tree read of fare / km / min — node-tree-read-before-ocr
    • Offer scoring, the entire deadhead-adjusted-net-profit calculation
    • Multi-app coordination and identity-check detection
    • Keyword screen classification (heuristicClassify)
    • Diagnostics — on-device-black-box-diagnostics
    • Session persistence in localStorage

    #What the phrase does not license

    "Fully on-device" is a claim about data leaving, and Farely's README overstates it. Two network calls are unconditional — OpenFreeMap tiles via maplibre-gl and fueleconomy.gov car specs — and the anthropic-messages-api path is compiled into the shipped bundle even when it is dormant. SRS §4.10 and the Android install guide enumerate all six external interfaces correctly; the README does not. The honest formulation is no server of mine, no account, no telemetry, and the only outbound content path is opt-in — see opt-in-cloud-fallback.

    Worth recording: the 2026-07-24 README rewrite for public release made this claim less accurate than the earlier VISION text it replaced. Publishing pressure sharpened the slogan and dropped the caveat. That is documentation-drift running in the direction of marketing.

    #Why it holds up here

    The domain favours it. An offer verdict must land in under a second while the driver is looking at a countdown; a round trip to a model is both slower and metered. The local path is not a degraded mode, it is the fast path — the cloud call exists only for screens the local classifier cannot name at all.

    #Cost

    The local classifier is a keyword list, so it is locale-bound and silently wrong on redesign. Farely absorbs that with taught-selectors-over-guessed-labels and by logging every unknown-case to the diagnostics ring buffer for later tuning, rather than by reaching for the model.
