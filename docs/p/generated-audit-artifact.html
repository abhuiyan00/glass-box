    Generated Audit Artifact

    A script emits a report; the report is committed next to its output; the claim then points at the report rather than at prose. Five repositories do this, in four different shapes. It is the strongest verification habit in the source set and the direct counterweight to documentation-drift.

    #Shape 1 — a dated audit backed by re-runnable checkers

    Optimization Methods ships tools/verify_reports.py and tools/verify_chromosomes.py, and commits docs/DATA_VERIFICATION.md stamped "Date of check: 2026-07-09", surfaced as a README badge (data checks 36/36 ✓) with re-run instructions. The checker re-parses all 36 solver reports for internal consistency and cross-checks a hard-coded copy of the paper's Table 7 to ±2 m — so it is a genuine external check, not a self-check.

    "Re-running the deterministic greedy on a freshly downloaded Wrocław graph gave 178,207 / 322,318 / 458,921 m vs the paper's 177,555 / 299,944 / 481,089 m — same demands and capacity, but a different sampled road graph (OSM has drifted; today's largest SCC = 3,893 nodes)."

    Optimization Methods/final_project/docs/DATA_VERIFICATION.md, 2026-07-09

    A negative reproducibility result, kept.

    #Shape 2 — the audit gates the build

    labour-fraud-analysis is the most developed instance. make docs regenerates docs/schema.md, docs/data-dictionary.md, docs/coverage.md and data/_counts.json; CI then runs git diff --exit-code on exactly those four paths, so a stale generated doc fails the build. See generated-docs-checked-by-ci-diff and reproducible-analysis.

    The same repo also shows the limit of the technique. Its README claims "no value here identifies a real party — a claim that is test-verified in CI", but the workflow says:

    "On a clean runner the private source + rules are absent, so the leak/stem scans skip and this enforces structural integrity + the PII regex sweep."

    labour-fraud-analysis-a-forensic-data-investigation/.github/workflows/ci.yml, 2026-07-11

    The gate is real but narrower than the prose claims. Recorded on disclosure-gate.

    #Shape 3 — a reproducible command transcript

    browser_game_stickfps/docs/security-audit-phase7.md reproduces each grep, its literal output, and what that output proves, plus a named Limitations section — explicitly "reproducible — rerun the same commands against a later commit to re-verify the invariant". It backs server-authoritative-netcode.

    #Shape 4 — the artefact audits its own generator

    Physics/exam_prep/tools/build_sets.mjs emits both js/quizsets.js and tools/AUDIT.md, and the audit reports numbers that contradict the generator's own header comment (75 bank questions vs a comment saying 62). The audit is honest about the code that produced it. It also records a domain-level finding — that two answers in a provided exam key were wrong — see jaccard-similarity-set-selection.

    #Shape 5 — a runtime black box

    Farley's diagnostics store is an audit artefact generated by use rather than by a build: a ring-buffered IndexedDB log of eight event kinds, exportable as farely-diagnostics-YYYY-MM-DD.json. See on-device-black-box-diagnostics.

    #Where it is absent

    Discrete-Mathematics-Laboratories, Python-Programming-Laboratories, Oracle-Database-Laboratories and Cybersecurity-Engineering-Laboratories have no generated audit. The nearest thing — Python-Programming-Laboratories — actively gitignores its generated output as "all reproducible from source", which is the opposite choice: trust the generator, don't commit its output.

    One instance is a partial: IT Applications in Business and Commerce/project/docs/branch-reports/ is 846 lines of mechanical per-branch audit of a different repository, but its generator was never committed — so the report cannot be re-run.
