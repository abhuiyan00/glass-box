    Angular

    21.2, standalone components, in exactly one place: the lab 4 SPA of information-systems-modelling. It is the only Angular in the source set — every other frontend in the corpus is either react or hand-written vanilla JS.

    #The stack as pinned

    dependencies: @angular/{common,compiler,core,forms,platform-browser,platform-server,router} ^21.2, @angular/ssr ^21.2.7, express ^5.1.0, rxjs ~7.8, tslib. devDependencies: @angular/build, @angular/cli, @angular/compiler-cli, @types/express, @types/node, jsdom, json-server, prettier ^3.8.1, typescript ~5.9.2, vitest ^4.0.8. packageManager: npm@11.11.0.

    Three of those are worth stopping on.

    vitest, not Karma/Jasmine. The Angular default test runner is absent; jsdom plus vitest 4 replaces it. This matches the corpus habit of preferring the lighter runner, but it is the only Angular project available to compare against.

    @angular/ssr + express in an SPA. The app is documented as a browser client talking to Spring Boot on port 8080, and server-side rendering is lab 6's stated topic, not lab 4's. The serve:ssr:* script exists and the server entry point is generated.

    json-server as a devDependency. A leftover from the pre-rewrite scaffold below; nothing in the live app uses it.

    #Two Angular apps, one directory inside the other

    lab4/angular-rest-client-student-crud/ is the real ModellingClub SPA — components and feature routing, a REST client against the Spring API, views guarded on the presence of a JWT (see stateless-jwt-authentication).

    Nested inside it sits angular-rest-client-student-crud/angular-rest-client-student-crud/ — a 39-file copy of the original assignment's student CRUD scaffold, complete with its own db.json for json-server. It is dead: nothing imports it, nothing builds it. It survives as one of four instances of keep-the-superseded-version-in-tree in this repo.

    ⚠ The nested duplicate is also where all the .spec.ts files live. The live SPA has one app.spec.ts and no feature tests — so the test files a reader finds by globbing belong to the dead app.

    #Why Angular at all

    Not a free choice: lab 1's own requirements document proposes a Linux / Python / PostgreSQL / Nginx stack, and the labs answer the same requirements on Java + Angular instead. That is recorded as java-angular-over-the-specs-python-stack — the requirements are treated as the contract and the technology as a choice, stated in those words in the root README.
