    Common Log Format Parsing

    Apache's Common Log Format (CLF) and its Combined extension look space-separated and are not:

    host ident authuser [timestamp] "request" status bytes "referer" "user-agent"

    Three of the nine fields are quoted — request, referer, user-agent — and they are quoted because they contain spaces. The bracketed timestamp contains a space too. So line.split() does not merely fail on those fields; it shifts every field after the first quoted one, silently.

    "Parsing is one regular expression, not line.split(). The request, referer and user-agent fields are quoted precisely because they contain spaces, so positional indexing shifts every field after the first quoted one — silently, producing plausible wrong answers rather than an error."

    Python-Programming-Laboratories/README.md, 2026-07-25

    That is the whole argument: the failure produces plausible wrong answers, not an exception. A status-code histogram built on shifted fields still looks like a status-code histogram. The decision is recorded on regex-over-split-for-log-parsing.

    #The quoted-field subtlety

    The obvious pattern for a quoted field, "[^"]*", is wrong as soon as a value contains a backslash-escaped quote. The correct form is:

    (?:[^"\\]|\\.)*

    — any character that is neither a quote nor a backslash, or a backslash followed by anything. This is not a hypothetical hardening:

    "Not hypothetical -- the sample log in data/ contains an injection attempt whose referer embeds \" sequences, and a naive [^\"]* would terminate the field at the first inner quote and reject the whole line."

    Python-Programming-Laboratories/src/weblog/entry.py, 2026-07-25

    The attack traffic in a real log is precisely the traffic most likely to break a naive parser — so a parser that drops malformed lines drops the lines you most wanted to see.

    #Around the regex

    • One re.VERBOSE pattern covering both CLF and Combined, so the parser is readable and commentable rather than a wall of escapes.
    • A frozen, slotted LogEntry dataclass whose __str__ round-trips back to CLF — parse and re-emit is an identity, which is a testable property rather than an assertion. See pythons-data-model.
    • Lazy iter_entries generator: a log is streamed, never loaded.
    • A ParseReport counting skipped lines and retaining the first five, so failures are surfaced with examples instead of swallowed. errors="replace" on decode means a bad byte costs one skipped line, not the run.
