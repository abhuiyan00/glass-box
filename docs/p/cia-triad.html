    CIA Triad

    Confidentiality, Integrity, Availability — the three properties any security control is ultimately defending. Lab 09 of cybersecurity-engineering-laboratories defines the working vocabulary at the point where it is needed, which is when a protocol has to be chosen rather than described.

    #The definitions the lab uses

    Term Definition
    Confidentialityprotection against unauthorised access, while providing authorised users unobstructed access. Data is not disclosed to anyone without a valid need to know
    Integritythe data has not been altered in an unauthorised way. A third party capturing and modifying it should be detectable
    Availabilitythe system is reachable and usable when needed — the property injection and flooding attacks target when they cannot read anything
    Authenticationconfirming the declared identity of a participant, to a level of certainty
    Authorizationaccess control — confirming that an authenticated entity may use the requested resource

    The lab's own list foregrounds authentication and authorization as separate entries, and that is the distinction worth carrying: they are not the same control, they fail differently, and the broken- access-control class in web-application-injection is precisely what happens when a system authenticates correctly and then never authorises.

    Non-repudiation is the fourth property usually attached to the triad, and it is the one only asymmetric cryptography supplies — see digital-signatures.

    #Which primitive provides which property

    This is the mapping the course is building toward, and getting it wrong is the standard beginner error:

    Property Provided by
    Confidentialityencryption — a cipher and a mode, see block-cipher-modes
    Integritya hash inside a MAC or a signature. Encryption does not provide it
    Authentication (of an entity)signatures plus a trust binding, see public-key-infrastructure
    Authentication (of a message)MAC / HMAC
    Availabilityrate limiting, redundancy, filtering — largely not a cryptographic problem

    The error the mapping prevents: an encrypted channel with no integrity protection can be tampered with. Under a stream-like mode, flipping a ciphertext bit flips the corresponding plaintext bit, and the recipient decrypts modified data with no indication anything happened. Confidentiality and integrity are orthogonal, and every modern protocol provides both explicitly.

    #What the lab measured

    OpenVPN is analysed as the practical case: SSL/TLS for the handshake, HMAC with a digest for packet integrity, X.509 certificates or pre-shared keys for authentication — one product deploying three different primitives for three different properties. Traffic was captured on the tunnel interface against the underlying interface to confirm that the cipher does what is claimed, which is the verification step that makes the property a measurement rather than a belief. See wireshark.

    The lab also transferred the same file repeatedly under different cipher and authentication algorithm choices and recorded the timings. Security properties have a price, and the price is measurable — the same experimental instinct as cryptanalysis-by-measurement, turned from attack to engineering. TLS 1.2 and 1.3 handshakes were inspected for the same reason.

    #Why it belongs in a wiki about how things get built

    The triad is a checklist for reading any design. For each of the three, ask what provides it, what would falsify it, and whether that has been checked. Applied to this source set it immediately separates the systems that state a security property from the ones that demonstrate it — the distinction provenance-and-limits-stated-inline tracks throughout.
