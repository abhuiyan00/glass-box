    Presentation Polish Tail Commits

    After the substance lands, a distinct tail of commits does nothing but presentation: screenshots, then a licence, then licence badges. The commits are separate on purpose and the wording is close to byte-identical across repositories.

    #The canonical sequence

    Optimization Methods, 2026-07-10, four consecutive final commits:

    1. c8c71ca chore: mark generated output as linguist-generated so language stats reflect the real source mix
    2. 39cb617 docs: add a tech-stack section to the top-level README
    3. d0adb9c Add MIT license
    4. 2bac56e Add license badges and an open-source note to the README

    Information-Systems-Modelling runs the same order: six docs(labN): add README with … screenshot commits → 151bc44 Add MIT license → f7395fe Add license badges and an open-source note to the README. Discrete-Mathematics-Laboratories matches: seven per-lab README+screenshot commits → 0a6d54b Rewrite the top-level README as a guided tour → 24e7b33 Add MIT license → 7273d68 Add license badges.

    The pairing Add MIT license + Add license badges and an open-source note to the README appears with near-identical wording in five repos, twice within 24 minutes of each other on 2026-07-10 (Computer Project Management 15:34:06, Physics 15:34:23, privacy-policy 15:10:41).

    #What the tail is not

    It is not a release. The interview settled that the 2026-07-10 and 2026-07-25 bursts were consolidation, not publication — see import-finished-work-into-git. So the tail is a presentation pass over a folder being tidied, not a shipping ceremony. That reading matters: nothing downstream depended on these commits.

    #Evidence

    "chore: mark generated output as linguist-generated so language stats reflect the real source mix"

    Optimization Methods, git commit c8c71ca, 2026-07-10

    "GitHub's language bar counts bytes, so this repo is easy to misread as \"JavaScript\" — most of those bytes are generated map-coordinate data, not code."

    Optimization Methods/README.md, 2026-07-10

    The second quote is the reason for the first: the tail includes managing how the repo appears, not only what it says.

    #Variations and exceptions

    • Inverted. IT Applications in Business and Commerce puts licence work first — commit #1 is Add license, gitignore and gitattributes — while still growing a polish tail (emoji scrub → screenshot galleries → doc-pointer scrub).
    • Collapsed. Oracle-Database-Laboratories and Cybersecurity-Engineering-Laboratories bundle README + LICENSE + .gitignore into one final commit and carry no badges at all.
    • Front-loaded. browser_game_stickfps ships MIT in commit #1, but four of its nine commits are still README-only — the shape survives without the licence pair.
    • Reworked. labour-fraud-analysis's only commit outside its one-second burst, four minutes later, is fdc6d2c Simplify the LICENSE to canonical MIT and note the dual license in NOTICE — see dual-license-mit-plus-cc-by.

    #The one deliberate omission

    Cybersecurity-Engineering-Laboratories chose its illustrations against the obvious candidate:

    "The obvious illustration for lab 7 is not used. The natural screenshot for that lab is the terminal where the RSA keypair is generated — and it prints the full 2048-bit private key. The signature-verification page is used instead."

    Cybersecurity-Engineering-Laboratories/README.md, 2026-07-25

    Presentation work here included a security judgement — see omit-rsa-private-key-screenshot.
