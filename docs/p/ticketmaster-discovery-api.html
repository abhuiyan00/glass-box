    Ticketmaster Discovery API

    Public events feed, used by farely to know when Wrocław venues will empty. It is the live tier of event-driven-demand-positioning — inbound only, key-gated, and fail-soft.

    #The request

    liveEvents.ts issues a single GET /events.json with city=Wroclaw, countryCode=PL, locale=*, size=100, sort=date,asc, over a window from one hour ago to 21 days out. The driver supplies the API key in Settings; it lives in localStorage alongside the Anthropic one — same storage, same unstated plaintext caveat noted on anthropic-messages-api.

    With no key the module is a silent no-op. No error, no prompt, no degraded banner: the seeded venue calendar simply remains the only source. That is what keeps an external dependency compatible with on-device-first-inference — the network is an upgrade tier, not a precondition.

    #The mapping work

    The interesting part is not the fetch, it is the normalisation into the app's own VenueEvent model:

    • Ticketmaster segment → kind, so a concert and a football match are priced as different demand shapes.
    • Venue matched against seven seeded Wrocław venues, or synthesised from the response's own geo-coordinates when unrecognised.
    • Synthesised venues are snapped to the nearest known zone, so zoneEph stays valid and a live event can never introduce a zone the rest of the demand model has never heard of.
    • Crowd size inferred from venue name and segment.

    Provenance is preserved: upcomingEvents merges tiers live > listing > typical, and each event keeps its source — provenance-and-limits-stated-inline.

    #Why this API and not a scrape

    It is the only one of Farely's four network dependencies that is genuinely a data source rather than infrastructure. The others — the anthropic-messages-api classifier, fueleconomy.gov car specs, and OpenFreeMap tiles via maplibre-gl — are respectively outbound, reference lookup, and rendering.

    • TODO: no rationale is recorded for choosing Ticketmaster over any other events source, and no coverage check exists for how much of Wrocław's venue calendar it actually contains. Never exercised against a live shift.

    #Unverified end to end

    Like everything else in farely, this ran only in the browser simulator. Whether the mapping holds against a full 100-event Wrocław response in practice is untested — there is no test runner in the repo at all.
