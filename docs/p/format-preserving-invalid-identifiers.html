    Format-Preserving Invalid Identifiers

    A replacement identifier has two jobs that pull against each other. It must look like the thing it replaces, or every parser, regex, column width and human reader downstream breaks. It must not be a valid instance of that thing, or you have minted an identifier that could collide with a real person's.

    The resolution used in labour-fraud-analysis: keep the shape, break the checksum.

    Identifier class Shape kept Validity broken by
    Travel documentletter prefix + fixed-length digit bodyno issuing-authority range, no check digit
    National identity numbercorrect digit countno checksum, and no date of birth encoded in the leading digits
    Tax numbercorrect digit countno checksum
    Permit referenceserial / year / authority-suffix structurefictional authority; serials offset by a constant

    The national identity number is the instructive case. Real numbers of that family encode a date of birth in their leading digits and end in a check digit. The synthetic version has the right length and nothing else — so it sorts, joins, displays and matches a length regex, while carrying no birth date and failing any checksum routine. It is a shape, not an identity.

    #Why the permit offset matters

    Permit serials in a bulk filing are consecutive in the source, and that contiguity is a load-bearing part of the convergent-evidence argument. A random remapping would destroy it. Adding a constant offset to the whole batch preserves the differences between serials — the property the analysis reads — while changing every value. Structure survives, identity does not: structure-preserving-anonymisation.

    #Assert the invalidity, do not assume it

    The property is only worth claiming if something checks it. Three tests in the suite do:

    • national identifiers must not match a valid-checksum pattern (shape only — see the limitation below),
    • no phone number may match the source-region shape,
    • the currency in the dataset must be a fictional one.

    These run on every push through github-actions, unlike the parts of the disclosure-gate that need the private source. Note the limitation plainly: the identity-number test checks a shape, not that the value fails a real checksum algorithm — a value could in principle pass a real validator and still pass this test. Recorded as a limit of the check, not a known failure.

    #Transferable rule

    When you must publish surrogate identifiers, decide up front which of the identifier's properties are syntactic (length, alphabet, separators, sort order, adjacency) and which are semantic (checksum, embedded date, issuing range, registry lookup). Preserve the first set; deliberately break the second; then write a test for each break.
