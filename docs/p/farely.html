    Farely

    A personal Android rideshare/delivery driver assistant for Wrocław. It reads the driver's own Bolt / Uber / FreeNow offer cards off-screen through an android-accessibility-service, scores each one on deadhead-adjusted-net-profit in PLN, and draws an ACCEPT / MARGINAL / DECLINE bubble over the ride app. Around that core sit demand-zone positioning, a venue let-out events calendar (event-driven-demand-positioning), a multi-app "chore" autopilot, and on-device-black-box-diagnostics.

    #The name

    The source folder is Farley; the product is Farely — fare + -ly. Everything inside the repo spells it Farely: package.json "name": "farely", appId and Kotlin package com.farely.app, the README H1, the git remote. "Farley" is a local directory typo only. Wiki sources: paths must use the folder name Farley/...; prose uses Farely.

    #Status — prototype, never field-validated

    "Only the web simulator, never the APK on a live shift."

    interview, 2026-07-28

    Farely has never scored a real offer on a phone in traffic. The web tester (apps/tester) was used in a browser; the Android path stayed unproven. The roadmap board is accurate about this — Phase 5 (field testing with real offers) is marked ⚪ not started, and five phases sit at 🟡 "code-complete — remaining: validate on device". See phase-status-board.

    12 commits, 2026-07-12 → 2026-07-25, all on main, no tags, no releases, no CI. A debug APK builds locally but is .gitignored — nothing is published. The first commit alone is 172 files / 22,151 insertions of already-finished work, and the CHANGELOG documents ten days (07-02 → 07-13) that git never saw: import-finished-work-into-git in its textbook form. The 2026-07-24/25 tail (ToS warning, guides, screenshots, Technology/Skills/License) is presentation-polish-tail-commits.

    #Stack

    • Root — npm workspaces and a pnpm-workspace.yaml; MIT, private: true, v0.1.0. See pnpm and pnpm-over-npm-for-capacitor-gradle-path.
    • apps/tester (@farely/tester) — Vite 6.3.5, React 18.3.1, TypeScript, Tailwind 4, maplibre-gl 5.24.0, recharts, MUI + a full Radix set, @capacitor/core 7.6.7. All deps exact-pinned. Also holds the pure domain engine in src/app/lib/ — see pure-domain-engine-shared-across-hosts.
    • apps/android (@farely/android) — capacitor 7.6.7 host, webDir: ../tester/dist; AGP 8.7.2, Kotlin 2.0.21, minSdk 23, compileSdk 36. Kotlin classes: FarelyAccessibilityService, OfferNodeParser, OcrReader (stub), OverlayController, MultiAppCoordinator, FarelyBridgePlugin.
    • No test runner, no linter, no typecheck, no CI.

    #Pipeline

    Accessibility event (debounced 300 ms, restricted to the four driver packages) → MultiAppCoordinator sees the screen first and can freeze → OfferNodeParser reads fare/km/min off the node tree → dedup 30 s → bridge into the WebView → offerFromRaw() + scoreOffer() in TypeScript → showOverlay back over the bridge → OverlayController draws the bubble with TYPE_ACCESSIBILITY_OVERLAY (accessibility-overlay-over-system-alert-window). The whole capture side is accessibility-service-overlay; the reading strategy is node-tree-read-before-ocr.

    #Findings — documentation vs code

    Farely is the sharpest instance of documentation-drift in the source set.

    1. ML Kit OCR is not shipped. The README and four docs describe Android ML Kit OCR as the on-device recognition engine. com.google.mlkit:text-recognition is in no build.gradle, OcrReader.readNow() returns null behind a // TODO(Phase 4), and OcrReader.instance is never set. The working on-device reader is the accessibility node-tree parser. Confirmed at interview.
    2. The test claim is aspirational. README.md:174 says "Tested with Vitest and Playwright." There is no test runner, no linter, no typecheck and zero test files; CONTRIBUTING.md says so outright ("do not invent npm test") and SRS §2.5 agrees. Playwright was used only to shoot the README screenshots. Interview: "Aspirational — tests were planned."
    3. The stale chapter index. docs/ocr-overlay/README.md §5 still reads "Phase 0 — Documentation. No native code merged yet", ~13 phases behind 02-roadmap.md.
    4. The permissions doc disagrees with the manifest — it lists MediaProjection as required and denies INTERNET; the manifest declares INTERNET and never uses MediaProjection.
    5. guidelines/Guidelines.md is an unmodified Figma Make template placeholder, shipped in a "professional repo" commit.

    #Privacy posture — precisely

    "Runs fully on-device" (README §Privacy, post-2026-07-24 rewrite) is overstated. Correct: no server, no accounts, no telemetry, no analytics SDK; persistence is localStorage + IndexedDB. Overstated because OpenFreeMap map tiles and fueleconomy.gov are unconditional outbound requests, and the anthropic-messages-api vision path exists in shipped code (key-gated, off without a key). SRS §4.10 lists all six external interfaces honestly and docs/guides/ANDROID-INSTALL.md states it correctly — the README does not. Note the direction of travel: the 2026-07-24 README rewrite demoted the cloud path from VISION's "a deliberate trade-off I switched on" to "ships off by default", which made the claim less accurate, not more. See on-device-first-inference and opt-in-cloud-fallback.

    The identity-check freeze is corroborated in three independent places — ID_CHECK_HINTS in the coordinator, frozen short-circuiting process() before any parse or screenshot, and NOVELTY_HINTS deliberately excluding every verification term. But the guarantee is heuristic, not structural: a verification screen containing a novelty word the hint list misses could still be captured. Both facts belong on the record. Related: never-automate-the-accept-tap, privacy-documented-beside-the-feature.

    Keys are entered in Settings and persisted to localStorage in plaintext. That is not stated as a limitation anywhere in the repo.

    #Declared-but-unused Android permissions

    FOREGROUND_SERVICE_MEDIA_PROJECTION and FOREGROUND_SERVICE (the OCR path they exist for is a stub), SYSTEM_ALERT_WINDOW (the overlay deliberately uses TYPE_ACCESSIBILITY_OVERLAY instead), and ACCESS_FINE_LOCATION (no native location code — deadhead uses a simulated positionRef).
