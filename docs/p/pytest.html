    pytest

    The test runner for python-programming-laboratories — and the only real test framework anywhere in the two lab repositories.

    #Configuration

    Declared in pyproject.toml rather than a separate pytest.ini:

    • testpaths pins the suite to tests/, so a bare pytest never wanders into labs/ and collects a script.
    • pythonpath makes the src/ layout importable without an editable install having to be in place first — see setuptools-and-pyproject.
    • pytest-cov in the dev extra for coverage.

    #The suite

    Six files: conftest.py, test_config, test_entry, test_reader, test_stats, test_lab07_request_parser, test_lab09_insults. 75 def test_ functions plus 5 parametrize decorators.

    What is pinned:

    • Round-trip parsing — parse then re-emit is an identity. A property, not a fixed expected string; see common-log-format-parsing.
    • Config validation, including failing at load rather than at first use.
    • Lab-07 exception ordering — the order validations fire, not just the outcome, so a refactor that reorders checks fails loudly.
    • parametrize sweeps over HTTP methods and protocol versions.

    What is not: labs 01–06, 08, 10, 11 and 13 have no tests at all. The tested surface is the weblog core plus two labs.

    #Two caveats on the headline number

    TODO: the README's "89 tests" figure comes from a screenshot. 75 test functions plus parametrize expansions is consistent with it, but the count is not derivable without running the suite, and no machine or date is recorded. confidence: medium.

    The documented quick start does not work. tests/test_lab09_insults.py imports factory and uses factory.Faker(...), but the dev extra declares only pytest and pytest-cov — so pip install -e ".[labs,dev]" followed by pytest fails at collection in a clean virtualenv. confidence: high. See factory-boy-and-faker and documentation-drift.

    Counting tests is the wrong measure anyway — tests-that-pass-for-the-wrong-reason is the lab's own argument about that.

    #Contrast

    discrete-mathematics-laboratories has no pytest. Its single automated check is a hand-rolled TestRunner in lab3_Sets/mandatory_tasks/test_suite.py — boolean assertions and a ✓/✗ summary.
