    Privacy Documented Beside The Feature

    The privacy argument is not filed in one policy document — it is restated at every site where the sensitive thing happens: in the vision doc, in the legal chapter, in the install guide, in the SRS non-functional requirements, and in the header comment of the source file that does the capture.

    In farely the same two invariants — never tap Accept, never come between the driver and an identity check — are written down in at least six places, in two languages of expression (prose and code comment) and two programming languages.

    #Evidence

    The trade-off is stated where the trade-off is made:

    "This is a deliberate, documented departure from \"nothing leaves the phone\": a screen capture leaves the device only for this classifier, and only for screens that pass a cheap on-device novelty gate."

    Farley/docs/VISION.md, 2026-07-13

    And restated as a comment on the keyword list that enforces it:

    "Deliberately excludes verification/selfie terms: identity checks are detected on-device by the coordinator and NEVER routed to cloud vision."

    Farley/apps/android/.../FarelyAccessibilityService.kt, 2026-07-13

    The second quote is the pattern in one line. A developer editing NOVELTY_HINTS to add a keyword reads the rule at the moment they could break it. A privacy policy in a separate repository would not have been in that field of view — which is worth noting given that privacy-policy-template exists and, by chronology, covers neither of the author's two products.

    #Why the redundancy is the point

    It is the provenance-and-limits-stated-inline habit applied to a legal and ethical constraint rather than to a data field. Six copies is normally a maintenance smell; here each copy sits next to a different way of violating the rule, so the duplication tracks the attack surface rather than the document tree. The ToS and ban-risk warning is likewise repeated four times — README warning block, VISION §7, the legal chapter (including a draft in-app disclaimer), and SRS NFR-L-1.

    #The two costs, both visible in this repo

    Copies drift. The 2026-07-24 README rewrite for public release restated the privacy claim as "runs fully on-device", which is less accurate than the VISION text it echoed: map tiles and fueleconomy.gov are unconditional outbound calls, and the anthropic-messages-api path ships in the bundle. Six sites of truth means six chances to write the sixth one carelessly — see documentation-drift and on-device-first-inference.

    Documentation is not enforcement. The identity-check freeze is corroborated in three independent mechanisms, but all three are keyword heuristics; a verification screen containing an unlisted novelty word could still be captured. The docs assert a guarantee the code makes only probable. Stating the rule six times does not make it structural — see opt-in-cloud-fallback and never-automate-the-accept-tap, where the boundary is structural and the difference is instructive.
