    PL/SQL

    Oracle's procedural extension to SQL: block-structured, statically typed against the schema, and executed inside the database rather than in a client. Used throughout sql/03_plsql/ and sql/04_object_relational/ in oracle-database-laboratories, and nowhere else in this source set.

    #The unit of everything is a block

    DECLARE  … declarations, including local procedures and functions
BEGIN    … statements
EXCEPTION … handlers
END; /

    Anonymous blocks run as-is from sql-plus; named blocks become procedures, functions, packages and triggers. Blocks nest, and nesting is the idiomatic way to scope an exception: the chief-walking exercise wraps its inner lookup in its own BEGIN … EXCEPTION so that walking off the top of the hierarchy ends the chain rather than propagating NO_DATA_FOUND out of the loop.

    The trailing / is not decoration. Inside a type or package body a bare semicolon ends the enclosed statement, not the body, so a file without the slashes cannot be run as a script at all.

    #The features the repo leans on

    Feature Note
    %TYPE, %ROWTYPEanchor variables to the schema, so a column widening does not need an edit
    Cursorsexplicit and FOR-loop forms — see plsql-cursors

    CollectionsTABLE OF … INDEX BY VARCHAR2 associative arrays; nested tables for name lists
    Packagesspec plus body; package variables persist for the session, which is both the feature and the hazard
    Triggersrow, statement, compound, autonomous — see database-triggers
    EXECUTE IMMEDIATEdynamic DDL, used in the teardown scripts
    Object typesMEMBER FUNCTION / MEMBER PROCEDURE, SELF IN OUT — see object-relational-model

    #Name resolution is the language's sharpest edge

    Where a PL/SQL identifier and a column share a name, the PL/SQL identifier wins. That turns WHERE name = name_band into a tautology: the duplicate check passes on everything, silently, with no error anywhere. The repo's two defences are both worth copying — qualify every predicate with its table name, and deliberately name INTO targets apart from the columns they read (allowed_min versus min_mice).

    This is the PL/SQL-specific instance of a general failure mode: a check that runs, reports success and checks nothing. See tests-that-pass-for-the-wrong-reason.

    #Practical notes from the source

    • Reading an associative array at an unassigned key raises NO_DATA_FOUND rather than returning NULL. Every read needs an EXISTS guard; NVL does not help.
    • SHOW ERRORS PACKAGE BODY <name> after a create is how you see why a body compiled invalid — the CREATE itself reports only "created with compilation errors".
    • Package state persists across statements in a session, which is exactly what the three-trigger design exploits and exactly why it is fragile. A compound trigger's declaration section reinitialises per statement instead — see compound-trigger-over-package-state.
    • A MEMBER PROCEDURE receives SELF as IN OUT by default, so an attribute assignment mutates the caller's instance.

    #Where it sits against the alternatives

    PL/SQL puts logic next to the data: no round trip, no ORM, transactional by default. The cost is portability (none of this survives an engine change), testability (there is no test framework here — correctness is asserted in comments and by running the scripts), and reviewability (logic in a trigger executes without appearing at any call site). The repo's own comments repeatedly weigh those trades in place — provenance-and-limits-stated-inline.
