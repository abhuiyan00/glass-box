    Reproducible Analysis

    An analysis is reproducible when every number a reader can see was produced by a command they can re-run, and nothing was typed by hand into prose. labour-fraud-analysis is the most complete instance in the source set, and it gets there through five separate mechanisms rather than one.

    #The five mechanisms

    1. One seed for the whole world. Every generated value in the synthetic dataset descends from a single committed string, hashed per namespace and key — deterministic-seeded-substitution.

    "Global seed — flip this and re-run to regenerate a completely different (but internally consistent) fictional world. Committed value gives the published data."

    labour-fraud-analysis-a-forensic-data-investigation/src/fiction.py, 2026-07-11

    2. A seed for anything else that samples. The entity graph's force-directed layout is pinned in both the dashboard and the notebook, so the same picture comes out twice — see networkx.

    3. No hard-coded numbers, stated as a rule in both directions. The generators say it:

    "Run after anonymize.py so the numbers always match data/. No hard-coded counts."

    labour-fraud-analysis-a-forensic-data-investigation/src/build_docs.py, 2026-07-11

    and so does the presentation layer — "All figures compute live from the CSVs — nothing is hard-coded" (src/app.py).

    4. Generated artefacts committed and then diff-gated. The schema, data dictionary, coverage report and a row-count manifest are regenerated and compared byte-for-byte in CI: generated-docs-checked-by-ci-diff and generated-audit-artifact.

    5. The notebook is executed, not just stored. CI runs it end-to-end headless through nbconvert with a timeout. A notebook that is only ever read is a screenshot; a notebook that must execute on a clean runner is a test. See github-actions.

    #Reproducibility of the analysis, not of the environment

    This is the honest boundary, and it is worth stating because the two are routinely confused.

    Reproducible Enforced by
    the dataset from a seedfiction.py, anonymize.py
    every derived doc and countmake docs + CI git diff --exit-code
    every figure in the notebookCI notebook execution
    structural integrity of the databuild_db.py with foreign keys on, plus the test suite
    Not reproducible Why
    the Python environmentall twelve dependencies are floor-pinned with >=, no upper bound, no lockfile — under a comment claiming reproducibility
    the declared version floorthe project declares support from 3.10; CI runs 3.12 only, so the floor is never exercised. See setuptools-and-pyproject
    the pipeline end-to-endmake all needs the private source corpus, which exists on one machine

    A pinned seed makes the output deterministic given an environment. It says nothing about the environment. Both halves are needed and only one is present here.

    #The unusual part: testing that a finding survived

    Two of the tests assert that the analytical signals themselves still exist in the published data after anonymisation — the shared-contact concentration and the bulk-permit batching. Most pipelines test that the data is well-formed; this one tests that the data is still interesting. See shared-identifier-clustering and structure-preserving-anonymisation.

    The floors are deliberately loose — the shared-inbox test passes at five, where the dataset actually shows twenty-three. A regression test with a loose floor catches catastrophic loss of signal without freezing an exact number into the suite. That is the right trade for a generated dataset and the wrong one for a claim about magnitude.

    #The contrast case

    data-warehousing-and-business-intelligence writes verification queries into its load scripts — verify-the-load-dont-declare-it — but commits no output, no log, no expected-count file, and has no Makefile and no CI. Its one genuinely reproducible artefact is the standalone Python reference script, seeded for exactly this reason: reference-implementation-as-specification. The discipline is present as prose there and as machinery here.
