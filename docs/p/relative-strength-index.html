    Relative Strength Index

    A bounded momentum indicator over a price series. Take the period-over-period change, split it into gains and losses, average each over a trailing window (14 periods by convention), and map the ratio into 0–100:

    RSI = 100 - 100 / (1 + AvgGain / AvgLoss)

    High values mean recent moves were mostly upward, low values mostly downward. Conventional read thresholds are 70 and 30 — but those are an interpretation, not part of the indicator, which is the whole point of measure-vs-dimension.

    #Properties worth knowing before implementing

    • Bounded by construction. The output cannot leave [0, 100]; that makes it easy to assert.
    • Warm-up. With a 14-period window there is no defined value for the first 13 rows of a series. The implementation here writes NULL rather than a number derived from a short window, gated by a COUNT(*) over the same frame — see window-function-frames.
    • Degenerate ends. If average loss is zero the formula divides by zero; if average gain is zero the ratio is zero. Both are handled as explicit branches (→ 100 and → 0 respectively) rather than left to the arithmetic.
    • Two variants exist. The simple moving average of gains and losses, and Wilder's original exponential smoothing. data-warehousing-and-business-intelligence implements the simple-average variant and names Wilder's smoothing as the variant it did not implement — an instance of provenance-and-limits-stated-inline. The two do not agree numerically, so an implementation that does not say which it is cannot be checked.

    Dataa staged real price extract (git-ignored)a seeded random walk, stdlib only

    The Python side exists to be runnable by anyone — see reference-implementation-as-specification for what it does and does not verify. Its use of a seeded random walk rather than a price file is deliberate: the three properties being checked (warm-up length, boundedness, share of values inside the neutral band) hold for any series, so real data would add nothing but a licensing problem. That is dual-implementation-as-cross-check in intent, if not fully in execution.

    #Where it is stored

    On the fact table, as a measure, with the overbought/oversold flags derived in a view instead of stored. See rsi-as-measure-not-dimension for the decision and its rejected alternative — which is still in the tree.
