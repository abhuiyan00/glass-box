    Metasploit Framework

    An exploitation framework: a catalogued library of exploit modules, payloads, encoders and auxiliary tools behind a common console (msfconsole). Appears in lab 12 of cybersecurity-engineering-laboratories, against a deliberately vulnerable Metasploitable VM.

    This page describes the tool's structure and what the lab attempted. It contains no module names in use, no payload, no exploitation procedure and no privilege-escalation steps. See the redaction note on cybersecurity-engineering-laboratories.

    #The structure worth knowing

    The framework's design is the transferable part, because it is a clean separation of concerns:

    Component Role
    Exploit modulethe technique that gains code execution against a specific flaw
    Payloadwhat runs afterwards — the two are chosen independently
    Encoderreshapes a payload to survive transport constraints or naive filtering
    Auxiliaryscanning, fingerprinting and enumeration that does not exploit
    Postmodules that run once access exists

    Decoupling exploit from payload is why one framework covers so much ground: n exploits and m payloads give n × m combinations without either side knowing about the other. It also explains the defensive posture — detecting the payload family is often easier and more durable than detecting each individual exploit.

    #Where it sits in the chain

    Lab 12 runs the standard sequence: enumerate with nmap, identify service versions, look up known vulnerabilities for those exact versions, then search the framework's catalogue for a matching module. That is the value proposition — the framework is a searchable index from "this version is running" to "this is known to be exploitable", which is what turns a version string from trivia into a finding. See network-reconnaissance.

    #What actually happened in the lab

    The chain did not complete. The report records the port scan failing to return a version for a service that was demonstrably running, an unexpected port state, and the final step producing a connection that yielded nothing usable — the report's own words are that the target directory came back empty. The privilege-escalation exercise that followed is not described here at all.

    TODO: whether these were tooling problems, environment problems, or a conceptual gap is not diagnosed anywhere in the repository, and whether the exercise was retried is unrecorded. confidence: low on lab 12's completion; confidence: medium on this page overall, since the framework's role is documented in the README and its structure is not repo-specific.

    That an exploitation lab is the least complete in a fourteen-lab set is itself a finding — exploitation against a prepared target is fragile, version-sensitive and unforgiving of small environment differences, in a way that the measurement labs are not.

    #Scope

    Coursework, 2022, against Metasploitable and other deliberately vulnerable images provided for the purpose. The repository states that nothing was run against a system without authorisation and that none of it is written as an operational guide; this wiki keeps to the same boundary and narrows it.
