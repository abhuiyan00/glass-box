    Regex Over split() for Log Parsing

    Decision. Parse Apache CLF/Combined lines with a single re.VERBOSE regular expression, not with line.split() and positional indexing.

    Date. 2026-07-25, src/weblog/entry.py in python-programming-laboratories.

    #Why

    "Parsing is one regular expression, not line.split(). The request, referer and user-agent fields are quoted precisely because they contain spaces, so positional indexing shifts every field after the first quoted one — silently, producing plausible wrong answers rather than an error."

    Python-Programming-Laboratories/README.md, 2026-07-25

    Silently is the operative word. split() on a log line does not raise; it returns a list of the wrong length with the wrong things in it. A status-code histogram built on shifted fields is still a histogram, and nothing downstream can tell. The failure mode is wrong answers, not errors — the argument on common-log-format-parsing.

    #And the regex has to be the right regex

    The naive quoted-field pattern "[^"]*" is also wrong, and the repo names the input that proves it:

    "Not hypothetical -- the sample log in data/ contains an injection attempt whose referer embeds \" sequences, and a naive [^\"]* would terminate the field at the first inner quote and reject the whole line."

    Python-Programming-Laboratories/src/weblog/entry.py, 2026-07-25

    The shipped form is (?:[^"\\]|\\.)* — the standard escaped-string idiom. Note which lines the naive version drops: the attack traffic. A parser that silently discards malformed lines discards exactly the records a security analysis wanted. See document-the-failure-mode-next-to-the-fix.

    #Pinned, not asserted

    The choice is held in place by tests: round-trip parsing (parse → __str__ → parse is an identity) is a pytest property rather than a fixed expected string, and ParseReport counts skipped lines and keeps the first five so a regression is visible instead of quiet.

    #Counterpoint in the same repo

    Lab 08 goes the other way — configparser over a hand-rolled regex for INI files. The rule is not "prefer regex"; it is "let the format's real grammar decide". See argparse.
