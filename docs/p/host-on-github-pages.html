    Host on GitHub Pages

    Decision. Publish privacy-policy-template as a static site on GitHub Pages, served from index.html at the repository root — and name that provider inside the legal text, not only in the README.

    Date. The HTML rendering and the Pages instructions were committed together on 2026-07-10. Confirmed live at interview, 2026-07-28: "A template, and Pages is live."

    #Why

    Zero build, zero cost, zero new account — the repo is already on GitHub, so publishing is a settings toggle rather than a pipeline:

    "1. Push this repo to GitHub (done)."

    privacy-policy/README.md, 2026-07-10

    The deliverable was shaped for it: one file, no assets, no JS — self-contained-single-file-html. Static hosting is not a compromise here, it is the exact fit.

    #The unusual part: the host is in the policy

    Most policies name their host, if at all, in a generic "we use service providers" clause. This one puts GitHub in the operative text:

    "This Service is hosted on GitHub Pages (GitHub, Inc.). As the host, GitHub acts as a"

    privacy-policy/PRIVACY_POLICY.md, 2026-07-10

    That single sentence carries four downstream sections. §7 designates GitHub the sole processor and links its privacy statement and Pages data-collection notice — controller-vs-processor. §4's technical-data row exists only because a host keeps server logs. §10's international-transfer clause and its Standard Contractual Clauses safeguard exist because that host's infrastructure spans jurisdictions. §12 outsources security to the provider's HTTPS and platform hardening.

    It also enables the no-tracking posture: a static host runs no analytics by default, so §6's "does not set its own cookies" is a statement about the deployment, not just an intention.

    #The cost, and the evidence gap

    Cost. Naming one provider in the legal text couples the document to it. The README's reuse checklist has to flag §7 as an edit point precisely because of this — see one-reusable-policy-not-per-project. A template that hard-codes its host is slightly less reusable and considerably more honest, and the repo takes that trade knowingly.

    Gap. There is no CNAME, no Pages workflow and no deployment artefact anywhere in the tree. The README's "(done)" annotates the push, not the Pages toggle. The live-URL claim therefore rests on the interview alone — recorded as confidence: high because the user confirmed it, with the explicit note that the repository corroborates nothing.
