    H2 Database

    An embedded Java SQL database that runs inside the application process. Information-Systems-Modelling uses it in file mode — a JDBC URL pointing at a modellingclubdb file in the working directory — for labs 3 and 4, with Hibernate/JPA on top and the H2 web console mounted at /h2-ui. The literal URL and its account are in the repo's own properties files and are not reproduced here.

    It replaced sqlite, which lab 2 used via sqlite-jdbc 3.49.1.0 plus hibernate-community-dialects. Both are embedded, single-file, zero-install databases; the swap happens silently between labs 2 and 3, and no README or commit message explains it.

    • TODO: why SQLite was chosen for lab 2 and what forced the move to H2 — the lab brief, Hibernate dialect friction, or the web console — is unrecorded, and the interview did not cover it. confidence: low. Do not assert a reason.

    #What "file mode" buys and costs

    File mode was chosen over in-memory deliberately enough that the in-memory URL sits commented out directly beneath it in both labs' application.properties. The trade: data survives a restart, which makes a demo reproducible and a screenshot honest — and the database becomes a binary file in the working tree.

    It duly got committed. lab4/modellingclubdb.mv.db (112 KB), lab4/StudentService/modellingclubdb.mv.db (96 KB), lab3/.../modellingclubdb.mv.db (68 KB) and a .trace.db are all tracked, and two commits exist whose entire content is a binary database rewrite — "1 file changed, 0 insertions(+), 0 deletions(-)". There is no Git LFS anywhere in the repo.

    #The console, and the profile that turns it off

    spring.h2.console.enabled=true with spring.h2.console.path=/h2-ui in dev. The dev properties file comments the console as "dev only — disable in prod via application-prod.properties", and application-prod.properties does exactly that with spring.h2.console.enabled=false. Small, but it is the discipline provenance-and-limits-stated-inline describes: the hazard is named next to the setting that creates it.

    ⚠ lab3/README.md prints the console's connection URL and username as part of a screenshot caption, and the root README carries a demo-account table. No credential or connection string from this repository is reproduced in this wiki. lab4/.idea/dataSources.xml — a tracked IDE database-connection descriptor — should be removed from tracking.

    #H2 was always the interim answer

    application-prod.properties carries a fully commented-out PostgreSQL + HikariCP + Flyway block under the header "Uncomment and set env vars when migrating from H2 to PostgreSQL", and lab 7 models the changeover as BPMN process 4, "H2 → PostgreSQL Database Migration", complete with a maintenance-window timer and a reversible cut-over back to H2. See bpmn-process-modelling.

    So the migration is specified in two places and executed in none: no Flyway migration exists, no PostgreSQL dependency is in any pom.xml, and no lab runs against one.
