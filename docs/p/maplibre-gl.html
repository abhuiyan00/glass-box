    MapLibre GL

    Open-source WebGL vector map renderer, the community fork of Mapbox GL JS from before its licence change. Used at 5.24.0 in farely to draw demand zones, the driver's position and venue markers — with OpenFreeMap as the tile source, which needs no key and no account.

    #The tiering decision

    MapLibre is the single heaviest thing in the bundle: vite build splits it into its own ~1 MB chunk against a ~309 kB main bundle. Farely responds with two tiers rather than one map:

    • Full tier — MapLibre is import()ed dynamically, so the chunk downloads only when a device is judged capable.
    • LITE tier — device.ts sniffs available RAM (2–3 GB thresholds, the "potato phone" tier) and substitutes a hand-rolled DOM/SVG projection. No WebGL, no 1 MB download, same zones drawn.

    That fallback is the sharpest instance in the repo of zero-dependency-no-build-step surviving at module level: rather than degrading the feature on weak hardware, the app reimplements the needed 5 % of the library by hand. It is also the right instinct for the actual user — a driver's phone is old, hot, and already running two navigation apps.

    • TODO: the 2–3 GB LITE thresholds have no recorded calibration. Whether they were measured against a real device the author owns is unknown — not asked at interview.

    #The privacy consequence

    Map tiles are an unconditional outbound request. Every session fetches OpenFreeMap tiles with no key, no opt-in and no off switch, which is one of the two reasons the README's "runs fully on-device" claim is overstated — the other being fueleconomy.gov car specs. SRS §4.10 and docs/guides/ANDROID-INSTALL.md list it honestly; the README does not. See on-device-first-inference and documentation-drift.

    Unlike the anthropic-messages-api path, no content leaves the device here — a tile request leaks where the driver is looking, which is a different and arguably more continuous exposure than one throttled screen capture. The repo argues carefully about the capture path and never mentions this one.

    #What it renders

    Demand zones and the venue markers produced by event-driven-demand-positioning, plus the position used by the deadhead term in deadhead-adjusted-net-profit — which is simulated, since no native location code exists.
