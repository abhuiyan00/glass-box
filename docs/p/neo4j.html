    Neo4j

    Native property-graph database. Nodes carry labels and properties, relationships are first-class, typed, directed and can carry properties of their own — which is the feature the one project using it here depends on.

    #Where it is used

    Lab 6 of discrete-mathematics-laboratories, run on Neo4j Desktop with a local database and the Desktop import folder. The model is a bipartite (:Object)-[:HAS_VALUE {value}]->(:Attribute) graph representing a pawlak-information-system — the attribute value lives on the relationship, which is precisely what a relational table cannot express without a join table.

    It genuinely ran. Confirmed in interview:

    • 39 :Object nodes, 25 :Attribute nodes, 975 HAS_VALUE relationships — real counts from a live instance, confidence: high.
    • Uniqueness constraints on node keys, which also give index-backed MERGE — see idempotent-loading.
    • An optional Object → Group(grade) → Group(class) hierarchy (14 grades, 2 classes) layered over the base graph.
    • Q0–Q6 report queries reading the structure back out.

    The Desktop workflow itself is the deliverable's other half: guide.txt walks database creation, the import-folder location, opening the Query pane, and the schema visualisation. The GUI import tool is explicitly rejected in favour of scripts — cypher-scripts-over-neo4j-import-tool.

    #Evidence caveat

    Every committed screenshot is viewer-*.png, produced by the offline JavaScript reimplementation in lab6_Neo4j/viewer/, not by Neo4j Browser. The eight-shot Neo4j Browser checklist in guide.txt has no corresponding files in the repo. The live run is attested by interview, not by artefact.

    #Compared with

    The relational alternative for the same data is a wide 39×25 table; the graph form makes "which objects share this attribute value" a traversal rather than a self-join. Contrast with the star schema treatment of the same kind of question in data-warehousing-and-business-intelligence, and with the RDF/triple-store framing in information-systems-modelling.
