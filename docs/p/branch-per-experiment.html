    Branch per Experiment

    A git branch holds one hypothesis, not one feature. The branch name states the hypothesis, the diff against master is the experiment, and the checkpoints and logs on the branch are the result. Nothing merges unless it wins; losing branches stay reachable as evidence of what was ruled out.

    Confirmed in IT Applications in Business and Commerce, where an eight-person team ran a baseline plus nine named branches against a PPO race driver — ten branch reports, two code trees shipped. See proximal-policy-optimisation and it-applications-in-business-and-commerce.

    #What makes it work: the lineage is written down

    Branches alone are not a method — a list of ten branch names six weeks later is archaeology. What makes this legible is that INDEX.md records how ideas descend from each other:

    "Gear ideas: [gear_strategy_max_jerk] (raw jerk) → [headless] (rpm band) → [a.bhuiyan] (data-driven torque/shift map)."

    IT Applications in Business and Commerce/project/docs/branch-reports/INDEX.md, 2026-07-10

    Three branches, one problem, each one superseding the previous answer — the endpoint of which is data-driven-gearing-over-hand-tuned-rpm-bands. INDEX.md also carries a "Recurring findings across branches" section naming what every experiment kept hitting: the corkscrew S-section, gearing, and episodes too short to complete a lap. That is the payoff the individual branches cannot give you.

    #And the honesty test: the branch that did nothing

    The reports audit rather than advertise. Reward_func_improvement is named for a reward change and does not contain one, and the report says so first:

    "Despite the branch name, the tip commit contains no reward-function code change. The only"

    IT Applications in Business and Commerce/project/docs/branch-reports/Reward_func_improvement.md, 2026-07-10

    A report set that will contradict its own branch names is worth reading. Compare provenance-and-limits-stated-inline.

    #The cost, visible here

    Branches of a shared codebase that never merge mean as many copies of the environment wrapper drifting apart, and snakeoil3_gym.py (605 lines) is duplicated verbatim between the two trees that did ship. It also means the reward function has no single definition — four distinct formulations exist across the branches, catalogued in reward-shaping.

    And it forced a second decision: with ten branches and a submission that takes code, which do you ship? See ship-two-branches-not-all-eight — two trees plus the full report set covering the rest, an instance of generated-audit-artifact.

    #Scope limit — do not over-generalise this

    This is one repository, and not one the user drove alone: the branches carry six named authors and the real git history lives in Szymon1905/AI_racer_pytorch, not in the ingested repo. The elsewhere-analogue in this corpus is multiple-solutions-side-by-side, where alternatives coexist in directories rather than branches.
