    Shared-Identifier Clustering

    When records that are supposed to be independent share a contact point — one inbox, one phone, one address, one bank account — the sharing is a claim about control. Counting how many nominally separate entities collapse onto each identifier turns an administrative detail into a structural finding.

    It is the cheapest signal in labour-fraud-analysis and, by the narrative's own assessment, the strongest.

    "The prettiest evidence in the box isn't dramatic. It's a GROUP BY."

    labour-fraud-analysis-a-forensic-data-investigation/docs/investigation.md, 2026-07-11

    #The mechanic

    One value_counts() over a contact column, filtered to non-empty values, sorted descending. That is the entire computation — see pandas. In the case dataset, sixty-six workers, each with a separate name, passport and personal file, resolve onto two contact inboxes: twenty-three people on the first, twelve on the second. (No identifier or person-like value from the dataset is reproduced in this wiki, synthetic or not.)

    The interpretive move is what makes it evidence:

    "One inbox is not thirty-five people's private correspondence. One inbox is one operator holding thirty-five people's mail."

    labour-fraud-analysis-a-forensic-data-investigation/docs/investigation.md, 2026-07-11

    The count is not the finding. The finding is that the count contradicts the story the records tell about themselves — independent hires who happen to share an employer.

    #The graph restatement

    The same relation expressed as edges gives a second reading. Build a bipartite people↔companies graph from four document types, then count people adjacent to two or more companies; those bridges are what entity succession looks like from the person's side rather than the company's. See networkx. Degree is used only for node sizing — no centrality measure is computed, so the graph is a picture of the same group-by, not an independent statistic.

    #Why it survives anonymisation, and why that is checked

    Replacing every value while preserving every relationship (structure-preserving-anonymisation) is exactly what keeps this signal readable: two source inboxes become two fictional inboxes with the same fan-out. Because that is a property the pipeline could silently destroy, it is asserted:

    """The 'one operator, many workers' signal must survive: an inbox shared widely."""

    labour-fraud-analysis-a-forensic-data-investigation/src/tests/test_dataset.py, 2026-07-11

    The assertion floor is deliberately far below the observed value — see reproducible-analysis for why a loose floor is the right choice for a regenerable dataset.

    #What this is not

    confidence: low on the labelling. The README lists entity resolution as a demonstrated skill. What the code performs is grouping and value-counting on an exact string. There is no blocking, no similarity scoring, no probabilistic matching, no transitive-closure clustering — nothing that resolves near-duplicates, which is what entity resolution normally means. Exact-identifier collapse is a valid and often decisive technique; it is a different technique.

    Related: the same repo's person table carries the contact fields the analysis treats as shared across people, which sits awkwardly with its third-normal-form claim — the normalisation "violation" and the signal are the same fact.

    #Where it fits in the argument

    One concentration count proves nothing on its own. It is the second of four independent weak signals argued together as convergent-evidence, each anchored to a document row through chain-of-custody.
