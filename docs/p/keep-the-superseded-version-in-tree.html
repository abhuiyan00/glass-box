    Keep the Superseded Version in Tree

    When something is replaced, the replaced thing is not deleted. It stays beside its successor. Confirmed in seven repositories, in four distinct motives — which is what makes it a pattern rather than untidiness.

    #Motive 1 — pedagogical, on purpose

    Oracle-Database-Laboratories keeps a three-trigger-plus-package-state implementation next to the compound trigger that replaced it, and labels the loser:

    "This works, but it is fragile in a way worth naming ... The guard flag below is what stops that recursion. Version (b) has no such problem and is the one to prefer."

    Oracle-Database-Laboratories/sql/03_plsql/04_triggers.sql, 2026-07-25

    Same instinct in Data-Warehousing-and-Business-Intelligence: docs/lab-1-notes.txt and lab-2-notes.txt hold the as-submitted coursework SQL, bugs and all, while sql/01_analytics/ rewrites each query with a comment explaining what was wrong. A before/after record, deliberately kept. See multiple-solutions-side-by-side for the same habit applied to alternatives that are all correct.

    #Motive 2 — a generated artefact with its pristine source

    IT Applications in Business and Commerce keeps chapters.backup.js (454 lines, hand-written) beside the generated chapters.js (567 lines, DO-NOT-EDIT banner, deterministic seed 1337). The "backup" is in fact the source of truth. Covered on generated-artifact-with-pristine-source.

    #Motive 3 — the rejected design, still shipped

    Data-Warehousing-and-Business-Intelligence argues at length that a technical indicator must be a measure, not a dimension — and then ships project/twtr/ssas/Dim RSI.dim with RSIKey, IsOverbought, IsOversold attributes, i.e. exactly the rejected model. The SQL side ships the winner; the SSAS side ships the loser. See rsi-as-measure-not-dimension.

    #Motive 4 — inertia, and it costs something

    • Information-Systems-Modelling carries a 39-file nested duplicate Angular project — the pre-rewrite student-CRUD scaffold — inside the real app, plus a 557-line instances.ttl referenced by no code, README or pom, plus two byte-identical copies of ontology.ttl in different labs.
    • IT Applications in Business and Commerce keeps two complete gym_torcs/ trees with snakeoil3_gym.py (605 lines) duplicated between them, upstream leftovers neither agent uses, and a commands.txt that is an exact stale copy naming the wrong checkpoint files.
    • labour-fraud-analysis wrote build_viewer.py::strip_locale() to remove a second locale, and interactive/i18n.js still advertises "i18n (EN / PL)" while app.js still branches on 'pl'.
    • browser_game_stickfps/files/ holds pristine 2026-07-14 seed copies of TASKS.md, an empty PROGRESS.md skeleton and the four agent files — a bootstrap kit left in place.

    #The instructive counter-example

    Information-Systems-Modelling 98fac45 refactor(lab6): drop hand-written snapshot pages, generate from the app deleted six hand-written HTML pages, −1268 lines. It is the only place in the whole source set where a superseded version was removed rather than kept — and it is also the only commit in that repo that reads like a working log rather than an import. See generate-markup-instead-of-hand-writing-it.

    #Why it matters for retrieval

    A reader cannot tell motive 1 from motive 4 by looking at the tree. Both leave two versions side by side. The distinguishing evidence is whether a comment names the loser as inferior — which is the same discipline as provenance-and-limits-stated-inline. Where no such comment exists, this wiki treats the duplicate as inertia and says so.
