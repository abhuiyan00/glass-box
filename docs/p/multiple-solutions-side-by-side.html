    Multiple Solutions Side by Side

    The same problem is solved two or three ways in one deliverable, and the trade-off between them is the point. Distinct from keep-the-superseded-version-in-tree: there, one version is wrong or retired; here, all of them work.

    #The instances

    Oracle: three formulations per question. Top-N is written with ROWNUM, with a WITH clause, and with FETCH FIRST … WITH TIES — including a note on the ROWNUM-applied-before-ORDER BY trap. "Empty bands" is written as a LEFT JOIN anti-join, as MINUS, and as NOT EXISTS. Chain-of-chiefs is written three ways over the self-referencing hierarchy. One rule is implemented twice as a trigger, with the inferior version labelled — see database-triggers.

    "The branches are disjoint by construction, so UNION ALL is used instead of UNION: there are no duplicates for UNION to remove, and skipping the sort and de-duplication pass is free."

    Oracle-Database-Laboratories/sql/02_queries/03_joins_and_sets.sql, 2026-07-25

    Python labs: a deliberate CLI A/B. Lab 09 ships click while the core package ships argparse, on comparable problems, and says why:

    "click against argparse. This lab uses click; the core CLI in weblog.cli uses argparse. Comparing the two on the same kind of problem is the point — click's decorators are terser for flag soup, argparse's subparsers give more control over a command hierarchy."

    Python-Programming-Laboratories/labs/09_dataset_reports/README.md, 2026-07-25

    See click-versus-argparse. The same repo keeps a hand-written "teaching version" of a parser beside the production one, for the same reason — see keep-the-teaching-version.

    Warehouse: a second implementation as the specification. rsi_reference.py computes the RSI in Python over SQLite specifically because SQLite's window syntax matches T-SQL's, making it a portable cross-check on the warehouse implementation. See reference-implementation-as-specification. The wiki records one caveat: the script only prints, so the two-implementation diff was never actually asserted.

    Discrete maths: the same system in two stacks. Lab 6 exists as Cypher against Neo4j and as an offline JS viewer that reimplements every query, rendering the graph beside the Cypher that produces it. Lab 4 exists in Python and in the browser. See dual-implementation-as-cross-check.

    Optimisation: five algorithms on one benchmark. Greedy, Random Search, GA, Tabu Search and Iterated Local Search all race on the same six Taillard instances with a shared evaluator and a shared CSV contract, so the convergence plots are directly comparable. See permutation-flow-shop-scheduling and iterated-local-search.

    #What it is for

    Two things, and they are different:

    1. Teaching a trade-off. The Oracle and Python cases exist to show that a choice was available.
    2. Cross-checking a result. The RSI and Neo4j cases exist so that two independent paths must agree — a cheap substitute for a test suite in repos that have none. This is the same motive as generated-audit-artifact, reached without any tooling.

    #Cost

    Duplication drifts. Discrete-Mathematics-Laboratories had to correct a count from 38 objects to 39 "throughout" after its guide and README disagreed, and its guide.txt checklist still says 38 — see documentation-drift. Two implementations mean two things to keep true.
