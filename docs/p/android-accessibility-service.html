    Android Accessibility Service

    The platform API that lets an app observe another app's view hierarchy and act on it. In farely it is the entire capture layer — see accessibility-service-overlay for the idea, this page for the concrete API surface.

    #Configuration in Farely

    FarelyAccessibilityService is declared with android:permission="android.permission.BIND_ACCESSIBILITY_SERVICE" and exported=false. Its accessibility_service_config.xml:

    • packageNames — restricted to four apps: ee.mtakso.driver, com.ubercab.driver, taxi.android.driver, com.mytaxi.driver
    • flags — flagReportViewIds | flagRetrieveInteractiveWindows
    • notificationTimeout — 100 ms

    flagReportViewIds is not decoration: view IDs are what make taught-selectors-over-guessed-labels possible. Without it a taught selector would have nothing stable to store.

    Events handled: TYPE_WINDOW_CONTENT_CHANGED, TYPE_WINDOW_STATE_CHANGED, TYPE_NOTIFICATION_STATE_CHANGED, debounced at 300 ms.

    #The three capabilities used

    1. Node-tree read — OfferNodeParser pulls fare / km / min out of TextView nodes. node-tree-read-before-ocr.
    2. Overlay window — TYPE_ACCESSIBILITY_OVERLAY, attached through the running service, requiring no extra user grant. accessibility-overlay-over-system-alert-window.
    3. AccessibilityService.takeScreenshot() (API 30+) — the screen capture fed to the key-gated opt-in-cloud-fallback. Never invoked while the coordinator is frozen.

    Gesture dispatch is used only for chore automation in the other apps, never for a ride offer: never-automate-the-accept-tap.

    #Permission findings

    Manifest declares INTERNET, SYSTEM_ALERT_WINDOW, FOREGROUND_SERVICE, FOREGROUND_SERVICE_MEDIA_PROJECTION, ACCESS_FINE_LOCATION, POST_NOTIFICATIONS, plus <queries> for the four driver packages and a calendar INSERT intent.

    Load-bearing today: BIND_ACCESSIBILITY_SERVICE, <queries>, INTERNET, POST_NOTIFICATIONS.

    Declared but unused:

    Permission Why it is dead
    FOREGROUND_SERVICE_MEDIA_PROJECTION, FOREGROUND_SERVICEexist for the OCR capture path, which is a stub — no MediaProjection code anywhere
    SYSTEM_ALERT_WINDOWthe overlay deliberately uses TYPE_ACCESSIBILITY_OVERLAY instead
    ACCESS_FINE_LOCATIONno native location code; deadhead uses a simulated positionRef

    An unused permission is not free — it is what a reviewer, a store listing, or a suspicious user reads first. Also a documentation contradiction: 03-android-permissions-and-legal.md lists MediaProjection as required and asserts there is "No INTERNET-dependent OCR", while the shipped manifest declares INTERNET and never mentions POST_NOTIFICATIONS. See documentation-drift.
