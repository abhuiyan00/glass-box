    Oracle Database

    Oracle's relational database engine. Used in exactly one repository in this source set: oracle-database-laboratories, targeting 12c or later — XE (the free Express Edition) is explicitly stated as sufficient — driven entirely through sql-plus scripts.

    #What the repo actually exercises

    Oracle-specific features, in the sense that a port to another engine would need rework:

    Area Feature
    HierarchyCONNECT BY PRIOR, LEVEL, SYS_CONNECT_BY_PATH, CONNECT_BY_ROOT — see hierarchical-queries
    ReshapingPIVOT
    Top-NROWNUM, and the 12c row-limiting clause FETCH FIRST … ROWS WITH TIES
    NullsNVL (Oracle's COALESCE predecessor, still idiomatic here)
    SetsMINUS — Oracle's spelling of EXCEPT
    DatesMONTHS_BETWEEN, ADD_MONTHS, SYSDATE, EXTRACT, TO_CHAR
    IdentitySEQUENCE, and GENERATED BY DEFAULT ON NULL AS IDENTITY (12c)
    Proceduralpackages, compound triggers, PRAGMA AUTONOMOUS_TRANSACTION — see plsql
    ObjectsCREATE TYPE … AS OBJECT, typed tables, REF/SCOPE FOR/DEREF — see object-relational-model
    MergeMERGE, used to close a check-then-write race in a trigger

    #Version-sensitive details worth remembering

    • FETCH FIRST … WITH TIES is 12c+. Before that, Top-N is an inline view plus ROWNUM, and the repo writes both so the older form stays readable.
    • ROWNUM is assigned before ORDER BY runs. WHERE ROWNUM = 1 ORDER BY col DESC does not return the largest row — it returns whatever the access path emitted first, then sorts that one row. The fix is to force the sort to complete in an inner query block first.
    • RAISE_APPLICATION_ERROR accepts only -20000 to -20999. Any other code raises ORA-21000 instead of the intended message.
    • GENERATED … AS IDENTITY is 12c+; earlier schemas need a sequence plus a trigger, which is why both idioms appear in the same file.
    • Constraint names are unique per schema, not per table — which is why the object-relational lab suffixes every constraint to coexist with the relational schema.

    #NLS is the portability hazard

    Several traps in the repo are the same trap: an implicit conversion routed through the session's NLS_DATE_FORMAT. Comparing a DATE column against a bare string works on a session set to YYYY-MM-DD and raises ORA-01861 on any other; concatenating a DATE onto a string produces different text per session. The repo's answer throughout is ANSI DATE '2009-01-01' literals and explicit TO_CHAR with a stated mask — a script that carries its own formatting assumptions instead of inheriting them.

    #Operational surface not exercised

    No tablespace management, no partitioning, no EXPLAIN PLAN or optimiser hints, no RAC, no Data Pump, no execution statistics. Cost arguments in the repo are made in prose (a query per cell versus one aggregating pass, a sort avoided by UNION ALL) rather than measured. Compare sqlite and neo4j, the other two engines in this source set, both used with far less of their surface but with the same script-first discipline.
