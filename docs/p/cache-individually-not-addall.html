    Cache Individually, Not addAll

    Decision. In the service worker's install handler, precache each URL with its own cache.add(url).catch(() => {}) inside a Promise.all, rather than the idiomatic cache.addAll(CORE).

    Date. Present in sw.js at the first commit of physics-exam-prep, 2026-07-10; file mtimes put the code at 2026-06-30.

    #Why

    The reason is written on the line above the code:

    " // addAll is atomic; cache individually so one miss doesn't abort install"

    Physics/exam_prep/sw.js, 2026-07-10

    addAll is specified to reject if any request fails, and a rejected install means the worker never activates — so the app has no offline cache at all. With a CORE list of 33 entries (app shell, five scripts, stylesheet, manifest, icon, three KaTeX files and 20 fonts), a single renamed or mistyped path takes the entire offline capability down, and it does so silently at the one moment the user is offline.

    #The trade being made

    addAll per-URL add().catch()
    One asset missinginstall fails, no offline cacheinstall succeeds, cache is quietly incomplete
    Failure visibleimmediately, loudlynever, at runtime
    Recoveryfix the path, redeploythe fetch handler falls through to network — which is unavailable offline

    This is not strictly the safer option; it is the option that fails partially instead of totally, and it converts a loud failure into a silent one. It is only defensible with something that catches the missing file before shipping — and that thing exists.

    #What makes it safe

    tools/qa.mjs check 8, "Service worker precache vs index.html", is the compensating control. It fails if any local asset index.html loads is absent from sw.js's CORE array, and separately if any concrete CORE path does not exist on disk. So the class of bug that addAll's atomicity would have caught at runtime is caught statically instead, before the code ships — and by a harness that needs no browser. See generated-audit-artifact for the same instinct applied to the question banks.

    The README records that this check was not theoretical:

    "caught a real offline bug (the service worker wasn't caching the newly added scripts; fixed and"

    Physics/exam_prep/README.md, 2026-07-10

    #Alternatives rejected

    Option Why not
    cache.addAll(CORE)the incumbent idiom; one bad path kills the whole install
    Precache nothing, cache on first fetchfirst offline visit renders nothing; defeats offline-first-static-deliverable
    Split into a required core and an optional tailmore code and a policy decision per asset; not taken

    #The unresolved part

    The cache constant reads const CACHE = "physprep-v4"; while snapshot.md documents physprep-v3 and exam_prep/README.md documents the bump "to physprep-v2". That is at least two unrecorded offline-cache changes after the README was written. Asked at interview and answered "Don't remember the cache history".
