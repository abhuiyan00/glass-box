    Opt-In Cloud Fallback

    A remote model call that is structurally optional: absent a key it does not exist, present a key it fires only for inputs a cheap local gate has already judged novel, and on any failure it degrades to the local answer rather than to an error. The counterpart of on-device-first-inference.

    The distinguishing test is what happens with the network unplugged and no credentials. If the feature disappears and the product still works, the fallback is genuinely opt-in. In farely it is:

    "This is a deliberate, documented departure from \"nothing leaves the phone\": a screen capture leaves the device only for this classifier, and only for screens that pass a cheap on-device novelty gate."

    Farley/docs/VISION.md, 2026-07-13

    #The four gates, in order

    1. No key ⇒ no call. classifyScreen(capture, apiKey) returns heuristicClassify() immediately. The key comes from Settings and lives in localStorage only — never committed, never bundled.
    2. Event-type gate. Only WINDOW_STATE_CHANGED is eligible; content churn inside a screen is not.
    3. Novelty gate. A PL/EN keyword list (NOVELTY_HINTS: update / aktualiz / wersj / regulamin / …) must match. It deliberately omits every verification term:

    > "Deliberately excludes verification/selfie terms: identity checks are detected on-device by the > coordinator and NEVER routed to cloud vision." > — Farley/apps/android/.../FarelyAccessibilityService.kt, 2026-07-13

    1. Throttle and freeze. At most one call per platform per 5 minutes, and if (MultiAppCoordinator.frozen) return runs before any of it.

    #Failure semantics

    Failure is silence plus a diagnostics row, not a dialog. A refused, timed-out or malformed response falls back to heuristicClassify(), and the result carries VisionResult.method: "cloud" | "on-device" so downstream code and the driver can both tell which answer they are looking at — the provenance-and-limits-stated-inline habit applied to inference. Every call is logged as a vision event in on-device-black-box-diagnostics.

    #The residual risk, stated

    The exclusion of identity screens is enforced by a keyword list, not by the type system or the platform. A verification screen whose text happens to contain a novelty word the list misses could still be captured and sent. Farely documents the intent in four places but cannot structurally guarantee it; the honest claim is "heuristic, biased towards false-positive freezing", and that is what belongs on the record.
