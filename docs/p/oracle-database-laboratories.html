    Oracle Database Laboratories

    Database Systems coursework from Wrocław University of Science and Technology, republished as a curated SQL suite. One toy domain — a herd of cats organised into hunting bands — carries almost the entire Oracle feature surface. 15 SQL scripts (96,728 bytes, measured 2026-08-05), 4 issued assignment sheets as PDFs, a Mermaid-rendered ER diagram, a README and docs/schema.md.

    "Five relations are enough to reach most of what Oracle offers — a self-referencing hierarchy, a circular foreign key, cursors, packages, compound triggers, and the object-relational layer on top of all of it."

    oracle-database 12c or later (XE is enough), driven as sql-plus @ scripts, with plsql for everything in 03_ and 04_. The only external build step in the repository is mermaid-cli rendering docs/schema.md into assets/schema-er-diagram.png — otherwise zero-dependency-no-build-step holds exactly.

    #The data model

    Five relations. FUNCTIONS (role → allowed mice-ration band, doubling as a validation table), ENEMIES, CATS, BANDS, INCIDENTS (composite primary key (nickname, enemy_name)). Two structural properties drive every exercise built on top:

    • A self-referencing hierarchy. CATS.chief points back at CATS.nickname, TIGER is the root, the tree is four levels deep. Every CONNECT BY in the repo walks it — see hierarchical-queries.
    • A circular foreign key. CATS.band_no → BANDS.band_no and BANDS.band_chief → CATS.nickname. Resolved by creating CATS without its band key and closing the loop with ALTER TABLE — see circular-fk-via-alter-table.

    The object-relational lab rebuilds the same domain as cat_type / common_type / elite_type / account_type / incident_type, and adds three tables (COMMONS, ELITES, ACCOUNTS) with no relational counterpart.

    #Findings

    • The comments are the deliverable. Nearly every script leads with the trap it is avoiding — ROWNUM evaluated before ORDER BY, BETWEEN on a DATE silently dropping the last day, a PL/SQL parameter shadowing the column it is compared against, RAISE_APPLICATION_ERROR outside -20000..-20999. This is the densest instance of provenance-and-limits-stated-inline among the coursework repos.
    • Superseded work is kept on purpose. 04_triggers.sql retains a three-trigger + package-state implementation and labels it inferior to the compound trigger beside it. That is keep-the-superseded-version-in-tree used pedagogically rather than archivally — see compound-trigger-over-package-state.
    • Essentially no documentation drift. README.md, docs/schema.md and the scripts agree on the run order, the circular key, the hierarchy depth and the reference data. Against documentation-drift this is the cleanest repo in the source set.
    • No polish tail. README, LICENSE and .gitignore all land in the single final commit 91b77f9; there are no badges and no separate screenshot commit. A counter-example to presentation-polish-tail-commits, while the README itself is still a readme-as-guided-tour.
    • .gitignore excludes credential material (*.sso, *.p12, *.jks, tnsnames.ora, wallet/) alongside SQL*Plus output. Nothing sensitive is in the tree.
    • No .gitattributes and no Git LFS: the ER PNG and four assignment PDFs are committed as plain blobs.

    #Open gaps

    • TODO: nothing here evidences that any script was ever run against a live Oracle instance. .gitignore excludes *.lst and *.log, and no output is committed. The scripts are internally consistent and would run, but "it ran" is not established. confidence: low on execution.
    • TODO: the README lists "normalisation" among the skills demonstrated, yet no normal-form analysis is written anywhere in the repo, and the schema was issued with the assignment. See database-normalisation. confidence: low on the normalisation claim.
    • TODO: the cat-herd domain is a standard assignment for this course; assignments/ contains the sheets as issued. How much of each solution is original versus canonical is not recorded. Do not assert authorship of the problems; the commentary and the alternative formulations are clearly the author's.
    • TODO: the whole suite standardises on SQL*Plus & substitution variables and 02_cursors.sql explicitly declines a host bind, but no file says whether that was a deliberate preference or simply what the course environment provided. confidence: low — see sql-plus.
