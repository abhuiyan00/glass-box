    Generate Markup Instead of Hand-Writing It

    Decision. Delete six hand-written HTML pages carrying RDFa and JSON-LD, and generate both syntaxes from a single JSON dataset instead.

    Date. 2026-07-09 — the generator (ef3b9f3) and the deletion (98fac45) land the same day, −1268 / +222.

    #The rejected alternative, named with its failure mode

    The alternative was not hypothetical. It was the working implementation, and it was thrown away:

    "The old approach hand-wrote the same data into six HTML files twice (RDFa in the body + JSON-LD in the head), so every fact lived in 2–4 places and could drift. This app makes the data the single source of truth and generates the markup."

    Information-Systems-Modelling/lab6/app/README.md, 2026-07-09

    The commit message says the same thing in eight words:

    "refactor(lab6): drop hand-written snapshot pages, generate from the app"

    Information-Systems-Modelling, git commit 98fac45, 2026-07-09

    "Every fact lived in 2–4 places" is the diagnosis. A build with an RDFa property in the body and a JSON-LD key in the head is asserting the same triple twice, in two syntaxes, in one file — and a seventh page would have made it worse. See linked-data-publishing.

    #What replaced it

    lab6/app/data/*.json holds the instances; one renderer emits RDFa, JSON-LD, the SSR responses and the static dist/ build. src/rdf/vocabmap.js extends the same rule to the documentation about the output — the VOCAB MAP provenance comment on each page is produced by walking that page's own graph, so it cannot go stale. The general form is single-source-of-truth-generators, and the vocabulary rule it applies is schema-org-first-custom-vocab-fallback.

    #Why this commit is the most unusual in the source set

    98fac45 deletes a superseded version. Across all fifteen source repositories, that happens essentially nowhere else: the standing habit is keep-the-superseded-version-in-tree, and Information-Systems-Modelling is itself the corpus's four-way champion of keeping things — a dead nested Angular scaffold, an orphaned 557-line instances.ttl, byte-identical ontology.ttl copies, and three whole superseded backends under forward-copy-lab-progression.

    The same author, in the same repository, in the same fortnight, both kept everything and deleted something. Per §10 of this wiki's schema that is a finding about the practice, not a contradiction to resolve: the deletion happens precisely where keeping the old copy would have reintroduced the bug — a stale hand-written page still serving stale triples is worse than no page. Where the old version is inert, it stays.

    #Costs and open threads

    • The hand-written pages are gone from HEAD, so the "before" is only reachable through git history. That is the trade the deletion makes deliberately.
    • The generated deliverable, dist/, is gitignored and untracked, while lab6/README.md calls it the thing to inspect. A reader cloning the repo gets the generator and not the output — documentation-drift.
    • verify_jsonld.py was deleted in the same commit, replaced by scripts/validate.py.
    • TODO: whether RDFa and JSON-LD had actually drifted before the rewrite — and whether verify_jsonld.py is what caught it — is unrecorded, and the interview did not cover it. The README states drift as a risk ("could drift"), not as an observed event. confidence: low on any claim that a real divergence occurred. Do not assert one.
